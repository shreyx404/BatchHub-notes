TCP/IP

The four-layer grammar of the Internet — how data is packetised, addressed, routed and reassembled.

The TCP/IP model is the fundamental framework for computer networking. Designed and developed by the Department of Defense (DoD) in the 1960s, it is a concise, four-layer version of the seven-layer OSI model — and it is non-proprietary, compatible with every operating system, hardware platform and network type.

These notes walk the entire unit in exam-grade depth: the layered architecture, the Data Link layer, link-layer addressing, ARP, and the Transport layer with TCP & UDP — complete with diagrams, comparison tables, flashcards and a self-test.

01

FOUNDATIONS

What is the TCP/IP Model?

TCP/IP stands for Transmission Control Protocol / Internet Protocol — the core protocols of the Internet. The model is a fundamental framework that defines how data is transmitted over networks, ensuring reliable communication between devices.

TCP/IP was designed and developed by the Department of Defense (DoD) in the 1960s and is based on standard protocols. It is a concise version of the OSI model: it contains four layers, unlike the seven layers of OSI.

How does the TCP/IP model work?

  1. At the sender's end, the model divides the data into packets.
  2. Packets travel through a 4-layer procedure — data enters the layers in one order (top → bottom).
  3. At the receiver's end, the same packets are processed in reverse order (bottom → top).
  4. Packets are recombined to form the same data — this preserves the accuracy of the data.
Exam one-linerTCP/IP = DoD, 1960s · 4 layers · non-proprietary · the concise version of the OSI model (7 layers).

Why TCP/IP dominates — six properties

FEATURE / 01

Non-proprietary

Not controlled by any single company, so the IP suite can be modified easily and evolves openly.

FEATURE / 02

Universal OS support

Compatible with all operating systems — any system can communicate with any other.

FEATURE / 03

Hardware agnostic

Compatible with all types of computer hardware and networks.

FEATURE / 04

Highly scalable

Grows from a small LAN to the global Internet without redesign.

FEATURE / 05

Routable

As a routable protocol it can determine the most efficient path through the network.

FEATURE / 06

The Internet standard

Widely used in current Internet architecture — it is the fundamental protocol suite for data transfer.

ARCHITECTURE

The Layered Architecture

The TCP/IP model stacks four layers. Each layer has specific functions managing different aspects of network communication; on the sender the data flows down the stack (encapsulation) and on the receiver it flows up (decapsulation).

L4

Application Layer

Topmost layer

The layer closest to the user. It is a group of applications requiring network communications — this layer is responsible for generating the data and requesting connections. It acts on behalf of the sender (and the corresponding layer acts on behalf of the receiver).

Per the course material, it is responsible for end-to-end communication and error-free delivery of data, and it shields upper-layer applications from the complexities of data. Its flagship protocols: HTTPHTTPSSSHNTP — detailed in §06.

L3

Transport Layer

Host-to-host

The transport layer protocols exchange data-receipt acknowledgments and retransmit missing packets to ensure that packets arrive in order and without error. This end-to-end communication is the essence of the layer. Two protocols live here: TCPUDP

  • TCP — applications interact as if physically connected by a circuit; data flows like a character-by-character byte stream: establish connection → transmit in byte order → close connection.
  • UDP — datagram delivery service; no connection verification; preferred for small data because it eliminates connection setup overhead.

→ Full deep-dive with handshake animation in §05.

L2

Internet / Network Layer

Routing heart

This layer parallels the functions of OSI's Network layer. It defines the protocols responsible for the logical transmission of data over the entire network. Main protocols residing here: IPICMPARP

It routes packets of data from one device to another across a network by assigning each device a unique IP address, used to identify the device and determine the route packets should take. → Deep-dive in §03; ARP in §04.

L1

Network Access Layer

Deepest layer

The bottom layer, also treated in this unit as the Data Link Layer domain. It handles the physical realities of the link: error prevention and framing are provided by this layer, and it prepares data for transmission on behalf of sender and receiver.

Nodes & links
A node is any addressable device on the network (host, switch, router); a link is the communication channel connecting two or more nodes.
Services of the link layer
Framing · physical (MAC) addressing · error prevention/control · media access.
Categories of links
Point-to-point — a dedicated link between exactly two nodes. Broadcast / multipoint — a shared link where many nodes compete for the medium (e.g. Ethernet, Wi-Fi).
Sublayers
LLC (Logical Link Control) — interface to the network layer; flow & error control. MAC (Media Access Control) — physical addressing and control of access to the medium.
Unit-index topic · Link-layer addressing — three types of addresses ① Physical / MAC address — hardware address burned into the NIC, used on the local link.  ② IP (logical) address — identifies the host across the whole internet, used by the Internet layer.  ③ Port address — 16-bit address identifying the exact process/application at the Transport layer.
03

INTERNET LAYER

The layer that routes everything

The Internet Layer is a layer in the Internet Protocol (IP) suite — the set of protocols that define the Internet. It is responsible for routing packets of data from one device to another across a network.

How it routes: it assigns each device a unique IP address, used to identify the device and determine the route packets should take. Each packet gets an IP address, routing tables determine the best route, and the packet is forwarded to the next hop until it reaches its destination — where all packets are reassembled.

  1. You click send — the email is broken down into smaller packets and handed to the Internet Layer for routing.
  2. The Internet Layer assigns an IP address to each packet and consults routing tables to determine the best route.
  3. Each packet is forwarded to the next hop on its route until it reaches the destination.
  4. Your friend's computer reassembles the packets into the original email.

Without the Internet Layer, it would not be possible to send data across the Internet.

IP is the low-level internet protocol that facilitates data communications over the internet. It is responsible for delivering packets from the source host to the destination host by looking at the IP addresses in the packet headers.

An IP packet consists of a header (routing information — source & destination of the data) and the data payload itself. IP defines how to address and route each packet to ensure it reaches the right destination: each gateway computer on the network checks the IP address to decide where to forward the message.

(A gateway is a network node used in telecommunications that connects two networks with different transmission protocols together.)

  • Provides the mechanism for delivering data from one network node to another.
  • Connection-less: it doesn't guarantee delivery, nor provide error checking and correction.
  • Longer strings of data must be broken into multiple packets, sent independently, then reorganised into correct order.
IP VERSIONS

IPv4 vs IPv6

IP has 2 versions: IPv4 and IPv6. IPv4 is the one most websites are using currently — but IPv6 is growing, because the number of IPv4 addresses is limited compared to the number of users.

Watch the wordingThe deck notes the header of a single IP data packet as being between 20 and 24 bytes, which limits packet size — hence fragmentation. It also states IP "operates at the network access layer"; in standard TCP/IP teaching IP is the defining protocol of the Internet layer. Answer per your lecture's framing if asked directly.

ICMP — Internet Control Message Protocol. It is encapsulated within IP datagrams and is responsible for providing hosts with information about network problems.

Think of ICMP as the network's diagnostic messenger: when a packet cannot reach its destination, or a router is congested, ICMP messages report the condition back to the source. (Echo requests/replies — the classic ping — use ICMP.)

Exam one-linerICMP = encapsulated inside IP datagrams · reports network problems to hosts.

ARP — Address Resolution Protocol. Its job is to find the hardware address (MAC) of a host from a known IP address.

04

ADDRESS RESOLUTION

ARP in Depth

ARP finds the hardware address — the Media Access Control (MAC) address — of a host from its known IP address. It is the bridge between the logical world of IP and the physical world of MAC.

STEP A / BROADCAST

"Who has this IP?"

ARP broadcasts a request packet to all the machines on the LAN and asks if any machine is using that particular IP address.

⟶
STEP B / REPLY

"That's me — here's my MAC"

When a machine recognises the IP address as its own, it sends a reply so ARP can update the cache for future reference and proceed with communication.

⟶
STEP C / CACHE

Remember it

All operating systems in an IPv4 Ethernet network keep an ARP cache. Next time, the cached IP→MAC translation is used directly — no new ARP request.

The ARP cache — facts that get asked

CACHE / 01

Check first

Every time a host requests a MAC address to send a packet on the LAN, it checks its ARP cache — if the IP→MAC translation exists, a new ARP request is not entertained.

CACHE / 02

Limited & cleansed

ARP has a limited cache size and periodically cleanses entries to free up space.

CACHE / 03

Short memory

Addresses tend to stay in the cache for only a few minutes.

CACHE / 04

Fresh information

Frequent updates enable other devices to see when a physical host changes its requested IP address.

CACHE / 05

Garbage collection

When cleansing, ARP detects unused entries and unsuccessful attempts to reach computers that are currently powered off.

CACHE / 06

Universal

All operating systems in an IPv4 Ethernet network keep an ARP cache.

The four types of ARP

TYPE / RARP

Reverse ARP

The inverse question: a device that knows its own MAC asks for its IP address (classic use: diskless workstations booting).

TYPE / PROXY

Proxy ARP

A router/gateway answers ARP requests on behalf of another host, bridging queries across network segments.

TYPE / GRATUITOUS

Gratuitous ARP

A host announces its own IP→MAC mapping without being asked — useful after an IP change and for duplicate-address detection.

TYPE / INVERSE

Inverse ARP

Discovers a peer's address from a known virtual-circuit identifier — the operation inverse of normal ARP, used on circuits such as Frame Relay / ATM.

05

HOST · TO · HOST

The Transport Layer

The host-to-host (transport) layer provides communication between hosts on a network. Its protocols exchange data-receipt acknowledgments and retransmit missing packets so packets arrive in order and without error — that is end-to-end communication.

Six functions of the transport layer

F / 01

Process-to-process delivery

Delivers data not just host-to-host, but from the exact source process to the exact destination process — via ports.

F / 02

End-to-end connection

Creates a connection between devices so hosts communicate end-to-end without intermediate devices managing the conversation.

F / 03

Multiplexing & Demultiplexing

Many sources share one network connection (mux); at the destination the data is split back to the right receivers (demux).

F / 04

Data integrity & error correction

Checks for errors; if a packet is lost, the layer requests retransmission so all data is received correctly.

F / 05

Congestion control

Keeps the network free of congestion that could block the receipt of data.

F / 06

Flow control

Controls the size and flow rate of data so fast senders don't overwhelm slow receivers.

Consider two hosts, A and B. Host A wants to send a file to host B:

  1. The transport layer in A breaks the file into smaller segments (segmentation), adds error correction and flow control information, and transmits them.
  2. Host B's transport layer receives the segments, checks for errors, and reassembles the file.
  3. After successful transfer, host B acknowledges receipt to host A.

This covers segmentation & reassembly, reliable transfer, multiplexing/demultiplexing and end-to-end communication — all in one example.

Transmission Control Protocol

TCP is a connection-oriented protocol that establishes a connection between sender and receiver before delivering data, ensuring reliable and orderly delivery of packets across networks. It is sometimes referred to as TCP/IP, since it uses IP to transport data packets — while also connecting computers, applications, web pages and web servers.

TCP understands holistically the entire stream of data these assets require, and ensures the entire volume of data needed is sent the first time. Applications interact with one another as though physically connected by a circuit — data resembles character-by-character transmission rather than separate packets: a starting point establishes the connection, the whole transmission flows in byte order, and an ending point closes the connection.

  • Defines how applications create channels of communication across a network.
  • Manages how a message is assembled into smaller packets, transmitted over the internet and reassembled in the right order at the destination.
  • Controls the size and flow rate of data; prevents congestion and bottlenecks from out-of-order delivery.
  • Runs checks to ensure delivery; detects problems arising in IP and requests retransmission of lost packets.
Why not just IP?If an application sending a large amount of data used only IP, the data would be broken into many IP packets, each needing its own send/receive request (IP requests are issued per packet). With TCP, only a single request to send an entire data stream is needed — TCP handles the rest.

Fig. 05 — The TCP three-way handshake

TCP uses handshakes such as SYN, ACK, SYN-ACK to establish a connection before any data moves — the reason it is called connection-oriented. After the handshake, acknowledgments and retransmission keep delivery reliable.


CONNECTION ESTABLISHED
TCP IDENTITY

Heavy-weight · header 20–60 bytes (variable) · byte stream · no broadcasting · slower but reliable.

WHO USES TCP

HTTP, HTTPS, FTP, SMTP, Telnet — and applications like WWW, e-mail, SSH, and streaming services (Netflix, YouTube, Spotify).

User Datagram Protocol

UDP is a connectionless protocol that allows communication between two or more devices without establishing any connection. The sender simply sends data packets to the receiver that holds the destination address.

UDP provides a datagram delivery service: connections between receiving and sending hosts are not verified. It does not guarantee delivery to the correct destination, generates no acknowledgment about the sender's data, and does not acknowledge the receiver — hence it is an unreliable protocol. Applications transporting small amounts of data prefer UDP because it eliminates the processes of establishing and validating connections.

UDP IDENTITY

Lightweight · header 8 bytes fixed · message stream · faster, simpler, more efficient · basic error-checking via checksums only · no sequencing (application layer manages order if needed) · supports broadcasting.

WHO USES UDP

DNS, DHCP, TFTP, SNMP, RIP, VoIP — plus real-time multimedia streaming, online gaming, DNS queries, network monitoring, and routing updates (RIP exchanges routing info among routers).

☎

Connection-Oriented

Designed on the telephone system — dial, establish the line, talk in order, hang up. TCP is the example.

Connectionless

Based on the postal system — every letter is independent, routed on its own, may arrive out of order. UDP, IP, ICMP are the examples.

Choose TCP when…

You need reliability over speed: web pages, e-mail, file transfers, remote logins, anything where lost or out-of-order data breaks the result.

Choose UDP when…

You need speed over reliability: live streaming, gaming, VoIP, DNS lookups, broadcasts — where a lost packet is annoying but not fatal.

FINAL PREP

Exam Corner

Rapid recall — 18 one-liners

  1. TCP/IP = Transmission Control Protocol / Internet Protocol — the core protocol suite of the Internet.
  2. Designed & developed by the Department of Defense (DoD) in the 1960s, based on standard protocols.
  3. TCP/IP has 4 layers; OSI has 7 — TCP/IP is the "concise version" of OSI.
  4. Layers top → bottom: Application → Transport → Internet → Network Access.
  5. Sender: data flows down the layers (encapsulation); receiver: up (decapsulation) — packets recombined to preserve accuracy.
  6. Internet layer protocols: IP, ICMP, ARP. It parallels the OSI Network layer.
  7. IP delivers packets by reading IP addresses in packet headers; versions: IPv4 (dominant, limited) & IPv6 (growing).
  8. ICMP is encapsulated within IP datagrams; it reports network problems to hosts.
  9. ARP: finds the MAC address from a known IP address. Types: Reverse, Proxy, Gratuitous, Inverse.
  10. All IPv4 Ethernet OSes keep an ARP cache; entries last only a few minutes; cache is checked before any new ARP broadcast.
  11. ARP request is a broadcast to all machines on the LAN; the owner replies; cache is updated.
  12. Transport layer = host-to-host / end-to-end; protocols: TCP & UDP.
  13. Transport functions: process-to-process delivery · end-to-end connection · multiplexing/demultiplexing · data integrity & error correction · congestion control · flow control.
  14. A port is a 16-bit positive integer → 0–65535; protocols bind connections to protocol ports.
  15. TCP: connection-oriented, reliable, sequenced, byte stream, header 20–60 B, heavy-weight, SYN / SYN-ACK / ACK handshake, no broadcasting.
  16. UDP: connectionless, unreliable, no ACKs or sequencing, 8 B fixed header, lightweight, faster, supports broadcasting.
  17. TCP apps: WWW, e-mail, FTP, SSH, streaming (Netflix/YouTube/Spotify). UDP apps: DNS, DHCP, TFTP, SNMP, RIP, VoIP, gaming, real-time streaming.
  18. Application layer: HTTP/HTTPS (HTTPS = HTTP + SSL), SSH (encrypted shell over TCP/IP), NTP (clock sync — prevents the 2:30 PM vs 2:28 PM crash).

Mnemonics

"All Traffic Is Networked"

Application → Transport → Internet → Network Access (top to bottom). Reverse it for the receiver's decapsulation path.

"Call vs Card"

TCP = phone call (dial first, ordered talk, hang up). UDP = postcard (fire and forget, no guarantee, fast). Also: TCP handshake order — Syn → Syn-Ack → Ack ("Send, Send-back, Answer").

Self-test — expand to check your answer

Which layer is responsible for delivering packets by looking at IP addresses in packet headers?

The Internet Layer, via the Internet Protocol (IP).

A host announces its own IP→MAC mapping without being asked. Which ARP type is this?

Gratuitous ARP.

Your ARP cache already holds the IP→MAC translation you need. What happens?

No new ARP request is entertained — the cached translation is used directly.

Which transport protocol does DNS use, and why?

UDP — DNS queries are small and need speed; UDP avoids the overhead of establishing and validating a connection.

Complete the analogy: connection-oriented is to telephone as connectionless is to ___?

The postal system — each packet (letter) travels independently.

Name the four TCP/IP layers from top to bottom.

Application → Transport → Internet (Network) → Network Access.

What makes TCP "reliable" — name at least three mechanisms.

Acknowledgments, retransmission of lost packets, sequencing/in-order reassembly, plus flow control and congestion control.

Why is IPv6 growing while IPv4 is still most-used?

IPv4 is what most websites currently use, but its address space is limited compared to the number of users — so IPv6 is growing.
