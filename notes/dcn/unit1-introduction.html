Data Communication

Data communications is the exchange of data between two devices via a transmission medium (e.g., a wire cable). The communicating devices must be part of a system comprising both hardware and software.

Key Definition

Telecommunication (tele = Greek for "far") covers telephony, telegraphy, and television. Data is information in any agreed-upon form between parties.

Four Fundamental Characteristics

The effectiveness of a data communications system depends on:

CharacteristicDescriptionReal-world Impact
Delivery Data must reach the correct destination — only the intended device/user Misrouted packets → wrong recipient
Accuracy Data must arrive unaltered; corrupted data is unusable Bit flips in files → corrupt downloads
Timeliness Data delivered in time; late data = useless data. Real-time transmission: data delivered as produced, in order Video buffering, VoIP dropouts
Jitter Variation in packet arrival time. E.g., video packets expected every 30ms but arriving at 30ms and 40ms alternately → uneven quality Choppy video calls, audio glitches

Types of Data

Analog Data
  • Continuous in nature — can take any value within a range
  • Represented by sine waves
  • Varies smoothly over time (no sudden jumps)
  • Used in traditional systems: telephone lines, radio

Examples: Human voice, thermometer readings, FM radio, analog TV

Digital Data
  • Discrete — has fixed, separate values (0s and 1s)
  • Represented by square waves
  • Easier to store, process, transmit with low noise
  • Used in modern computing and communication

Examples: Text files, MP3, internet data, computer storage

Bandwidth

Bandwidth is the maximum rate at which data can be transmitted over a communication channel in a given amount of time. It is the capacity of a network path, not speed.

Bandwidth vs Speed

Bandwidth = how much information you can receive per second (volume). Speed = how fast that information arrives. A wide highway (high bandwidth) lets more cars through; but each car (data packet) still travels at the same speed.

Bandwidth (bps) = Baud Rate × log₂(L)

Where L = number of signal levels

Types of Bandwidth

TypeDescription
Analog BandwidthRange of frequencies a channel can carry (Hz). Difference between upper and lower frequency components.
Digital BandwidthMaximum data rate in bps a digital channel can support

Units

bps — bits/sec Kbps — 10³ bps Mbps — 10⁶ bps Gbps — 10⁹ bps Tbps — 10¹² bps

Factors Affecting Bandwidth

  • Transmission Medium — Fiber optics > coaxial > twisted pair
  • Signal Type — Analog signals have limited frequency range
  • Noise & Interference — Reduce effective data rate
  • Hardware Capabilities — Routers, switches, NICs
  • Protocols Used — Some protocols introduce significant overhead

How to Increase Bandwidth

  • Get a higher Mbps ISP plan
  • Upgrade to a modern router (supports higher frequencies)
  • Use a wired Ethernet connection (reduces wireless congestion)

Data Transmission & Transfer Rate

Data Transmission

Refers to methods of transferring data over a communication medium from one device to another. Focuses on digital transmission — sending/receiving digital bit streams.

Two Types of Transmission

Parallel Transmission
  • Multiple bits transmitted simultaneously per clock pulse
  • Used for short distance (computer → printer)
  • Faster but requires more wires
Serial Transmission
  • One bit sent at a time over a single channel
  • Used for long distance (computer → computer over network)
  • 8 bits per clock pulse including start/stop bits (parity bits)

Data Transfer Rate (DTR)

The amount of digital data moved from one place to another in a given time. Also called throughput or bit rate.

DTR = D / T   |   bps = Number of bits ÷ Transmission Time (sec)

Speed Reference

Connection TypeDTR
Dial-up modem33.6 Kbps
USB 1.012 Mbps
USB 2.0480 Mbps
Gigabit Ethernet1,000 Mbps (1 Gbps)
Cisco Silicon One G10025.6 Tbps

Factors Affecting Data Transfer Rates

  • Network Congestion — Too much traffic → packet loss, queuing delays, session timeouts
  • Network Latency — Total time for a packet to travel source → destination. TCP (connection-oriented) increases latency; UDP (connectionless) doesn't.
  • Inadequate Hardware — Low RAM/CPU/I-O on client or server slows TCP processes
  • Filtering & Encryption — Firewalls scanning for viruses → packet loss, retransmission overhead
  • Traffic Prioritization (QoS) — VoIP/video gets high priority; low-priority traffic suffers during congestion
  • Load Balancing — Misconfigured load balancers → packet loss, retransmissions
  • Transmission Medium — Fiber optic > twisted-pair; DTR varies by cable type

Baud Rate vs Bits Per Second

Bits Per Second (bps)

Number of bits (0 or 1) transmitted per second. Measures useful data throughput.

1 Kbps = 1,000 bps
1 Mbps = 1,000,000 bps
1 Gbps = 10⁹ bps

This is what internet speed tests measure.

Baud Rate

Number of signal units (symbols) transmitted per second. One symbol may carry multiple bits.

bps = Baud Rate × bits/symbol

In DSL/Wi-Fi, bps > baud rate because each symbol encodes multiple bits via modulation.

Key Distinction

Baud Rate counts signal changes per second; bps counts bits per second. When a modulation technique encodes, say, 4 bits per symbol: a 1200 baud signal = 4800 bps.

Redundancy

Redundancy is the duplication of critical components or functions to increase reliability. If one part fails, the redundant part takes over, ensuring minimal disruption. It is the foundation of all error detection techniques.

TypeDefinitionExamples
Data Redundancy Same data stored in multiple locations/formats Database replication, RAID, cloud backups
Path Redundancy
(Network)		 Multiple communication paths between devices STP switches, dual ISP connections, mesh topology
Hardware Redundancy Duplicate physical components Dual power supplies, mirrored drives, redundant routers
Software Redundancy Multiple software systems/backup modules Multiple AV engines, parallel system services
Advantages
  • Increases reliability and availability
  • Improves fault tolerance
  • Enables error detection and correction
  • Ensures continuous service in critical systems
Disadvantages
  • Increased cost (hardware, storage, bandwidth)
  • Introduces system design complexity
  • Requires additional management and maintenance
Use Cases

Data Centers (multiple ISPs + power sources), Cloud Computing (cross-region replication), Banking and Military (disaster recovery, high availability).

Error Detection Methods

Error detection introduces redundancy bits into transmitted data. The receiver uses these extra bits to verify data integrity. Detection ≠ correction — detected errors require retransmission.

VRC / Simple Parity LRC / 2D Parity Checksum CRC

1. Vertical Redundancy Check (VRC) / Simple Parity Check

Adds one extra parity bit per data unit. In even parity: total number of 1s (including parity bit) is even. In odd parity: total 1s is odd.

Advantages
  • Detects all single-bit errors
  • Detects odd number of errors
  • Simple to implement in hardware/software
  • Minimal overhead — only 1 extra bit per byte
  • Fast error detection
Disadvantages
  • Cannot detect even number of bit errors
  • No error correction capability
  • Inefficient for large data blocks
  • No protection against burst errors
VRC Failure Example

Data: 101010 → Codeword: 1010101 (even parity). If two bits flip → 1111101. Receiver counts 1s: 5 (odd)... wait, 5 is odd — BUT if two bits flip in a way that maintains even count of 1s, the receiver sees "no error" — which is wrong.

Advantages over VRC
  • Detects and corrects all single-bit errors
  • Detects 2- and 3-bit errors occurring anywhere in matrix
  • Can pinpoint exact error location (row × column intersection)
  • Easy to implement with XOR logic
Disadvantages
  • Fails if even number of bits flip in same column
  • Cannot correct 2- or 3-bit errors — only detect
  • Adds one extra redundant message row → overhead
  • Not suitable for high-noise channels (burst errors)

3. Checksum

Data divided into equal-sized segments. 1's complement arithmetic used to sum all segments. Sum is complemented → checksum. Sent with data. Receiver performs same calculation; if result is all zeros → data is correct.

Sender Steps

  1. Divide data into k segments of m bits each
  2. Add all segments using 1's complement arithmetic
  3. Complement the sum → this is the checksum
  4. Transmit data + checksum

Receiver Steps

  1. Add all received segments (including checksum) using 1's complement
  2. Complement the result
  3. If result = 0000...0 → no error; otherwise → error detected, discard

4. Cyclic Redundancy Check (CRC)

The most powerful error-detection method. Based on binary polynomial division (modulo-2 arithmetic / XOR). Data is treated as a large binary number and divided by a generator polynomial. The remainder = CRC, appended to data.

Core Principle

Unlike checksum (addition-based), CRC is division-based. A sequence of redundant bits (CRC bits) are appended so the resulting data is exactly divisible by the generator polynomial. If the receiver's division has a non-zero remainder → error.

CRC Algorithm Steps

Given: Data = 11010011 | Generator = 1011 (degree=3)

Step 1: Append (k-1) = 3 zeros to data
11010011 → 11010011000

Step 2: Perform modulo-2 division (XOR)
11010011000 ÷ 1011 using XOR repeatedly

Step 3: Remainder = CRC (must be k-1 = 3 bits)
Remainder: 011

Step 4: Append CRC to original data
Transmitted: 11010011 + 011 = 11010011011

Receiver: divides 11010011011 by 1011 → remainder = 000 → ✓ no error

Requirements for a Good Generator Polynomial

  • Must be a binary polynomial (e.g., 1011 represents x³+x+1)
  • Highest and lowest bits must be 1 (e.g., 1001 ✓, 0101 ✗)
  • Chosen based on application — standard polynomials selected for maximum error detection
  • Not all random polynomials work — poor choices miss error patterns
CRC Advantages
  • Detects single-bit, double-bit, odd-number, and burst errors
  • Efficient — uses simple XOR arithmetic
  • Scalable (choose polynomial by application)
  • Widely used: Ethernet, USB, storage devices, Wi-Fi
  • Easily implemented in hardware (shift registers + XOR gates)
CRC Disadvantages
  • Cannot correct errors — only detects
  • Detection power depends on generator polynomial choice
  • Not cryptographically secure — can't prevent tampering
  • Overhead for very short messages
  • Certain patterns may slip through undetected

IEEE 802 Standards

IEEE 802 is a family of networking standards covering Physical Layer (Layer 1) and Data Link Layer (Layer 2) of the OSI model for LANs and MANs.

StandardNameStatusKey Feature
802.1Bridging & ManagementActiveVLANs, STP, 802.1X security, QoS
802.2Logical Link Control (LLC)ActiveUpper sublayer of Data Link — 3 service types
802.3EthernetDominantCSMA/CD, wired LAN, 10Mbps–40Gbps+
802.4Token BusObsoleteToken passing on bus topology (factory automation)
802.5Token RingObsoleteToken passing on logical ring (IBM, banking)
802.11Wi-Fi (WLAN)Very ActiveWireless LAN — a/b/g/n/ac/ax variants

IEEE 802.1 — Network Management & Bridging

Operates at Data Link Layer (Layer 2). Does not define a specific network type; instead defines how networks are managed, interconnected, and secured. Used in wired LANs, wireless LANs, data centers, AV networks.

  • STP (Spanning Tree Protocol) — Prevents network loops in switched Ethernet
  • VLANs — Virtual LANs for network segmentation
  • 802.1X — Port-based network access control (security)
  • QoS — Quality of Service: prioritizes critical traffic (VoIP, video) over less important traffic
802.1 Data Flow Example (PC → Printer)

1. LLC (802.2) wraps data in a frame, adds MAC address of destination printer. 2. MAC (802.1) adds source MAC address; MAC sublayer regulates how data is sent onto the network cable. 3. Ethernet (802.3) transmits the frame over the physical cable.

IEEE 802.2 — Logical Link Control (LLC)

Defines the LLC sublayer — the upper part of the Data Link Layer. While 802.3/802.5/etc. define the MAC sublayer and physical layer, 802.2 manages reliable communication above the MAC.

Service TypeDescriptionUse Case
Type 1 (Unacknowledged)Connectionless — no acknowledgment, no error recoveryBroadcasting, where speed matters more than reliability
Type 2 (Acknowledged)Connection-oriented — acknowledged, error recoveryReliable data transfer (similar to TCP)
Type 3 (Acknowledged Connectionless)Connectionless with acknowledgment per frameIndustrial control systems

IEEE 802.3 — Ethernet

The most dominant wired LAN standard. Defines both the MAC sublayer (Layer 2) and Physical Layer (Layer 1).

  • CSMA/CD — Carrier Sense Multiple Access with Collision Detection: devices listen before transmitting; if collision detected, back off and retry
  • Frame structure: Preamble | Destination MAC | Source MAC | Type | Data | FCS (CRC)
  • Speeds: 10 Mbps → 100 Mbps → 1 Gbps → 10 Gbps → 40 Gbps
  • Media: twisted-pair, coaxial, fiber optic
Physical Layer (PHY)
  • Electrical/optical characteristics
  • Cable type (coax, UTP, fiber)
  • Voltage levels for signals
  • Data encoding as electrical/light pulses
MAC Sublayer
  • Manages shared cable access
  • Defines data packet format
  • MAC addressing for device identification
  • Implements CSMA/CD collision detection

IEEE 802.4 — Token Bus (Obsolete)

Defines the Token Bus protocol: physical bus topology but logical ring communication. A token (special data frame) circulates; only token holder may transmit. Was used in factory automation (MAP — Manufacturing Automation Protocol by GM). Now replaced by Ethernet.

Working

  1. Token circulates in a defined logical order around the bus
  2. Only the device with the token can transmit → collision-free
  3. Guarantees fairness — every device gets a turn
  4. Ideal for real-time industrial control systems

IEEE 802.5 — Token Ring (Obsolete)

Developed originally by IBM (1980s). Uses token-passing instead of CSMA/CD. Devices logically arranged in a ring, physically connected in star using a Multi-Station Access Unit (MSAU).

Token Ring Lifecycle

1 Idle → Token circulates around ring
2 Station wants to transmit → Seizes token, sends data frame
3 Data frame circulates → Receiver copies it, marks as received
4 Frame returns to sender → Sender removes it from ring
5 Token regenerated → Passed to next station in ring
IEEE 802.5 Token Ring lifecycle

Defines protocols for Wireless Local Area Networks (WLANs). Uses radio waves to connect devices. Maintained by IEEE LAN/MAN Standards Committee.

Key Technologies in 802.11

  • OFDM (Orthogonal Frequency Division Multiplexing) — Efficient data transmission across subcarriers
  • MIMO (Multiple Input Multiple Output) — Multiple antennas increase throughput and range
  • MU-MIMO (Multi-User MIMO) — Simultaneously serves multiple devices
  • Beamforming — Focuses the wireless signal toward the device instead of broadcasting in all directions

  • Easy deployment and scalability

  • Lower speed and range vs wired networks
  • Security concerns if improperly encrypted

MAC Sublayer

The MAC (Medium Access Control) Sublayer is the lower sublayer of the Data Link Layer (Layer 2) in the OSI model. It controls how devices in a network gain access to the shared communication medium and transmit data without collisions.

Why MAC Matters

Without MAC, multiple devices on the same network would transmit simultaneously → collisions → corrupt data. MAC ensures orderly, efficient access to the shared medium.

MAC Sublayer position in the OSI model

Main Functions of the MAC Sublayer

FunctionDescription
FramingEncapsulates data into frames with header, payload, and trailer (FCS/CRC)
MAC AddressingAssigns and uses 48-bit hardware addresses to uniquely identify devices on local network
Medium Access ControlDetermines when a device can transmit; prevents/manages collisions (CSMA/CD for Ethernet, token passing for Token Ring)
Error DetectionAdds FCS (Frame Check Sequence) — CRC computed and appended to detect transmission errors
Flow ControlRegulates data flow between sender and receiver to prevent buffer overflow
SynchronizationEnsures sender and receiver are synchronized using preamble bits

MAC Address

A 48-bit hardware address assigned to a Network Interface Card (NIC). Written in hexadecimal: 00:1A:2B:3C:4D:5E

  • First 24 bits — OUI (Organizationally Unique Identifier) — assigned by IEEE to manufacturer
  • Last 24 bits — Device-specific identifier assigned by manufacturer

MAC in Different IEEE Standards

Network Topologies

A topology defines the physical or logical arrangement of devices (nodes) in a network and how they communicate.

Mesh

Every device connected to every other device (full mesh shown)

✓ Highly fault-tolerant
✗ Costly, complex cabling
Star

All devices connect to a central hub or switch

✓ Easy to manage, add devices
✗ Central hub = single point of failure
Bus

All devices on a single shared cable (bus). Data broadcasts both directions.

✓ Easy install, less cable
✗ Collision-prone, hard to troubleshoot
Ring

Each device connects to exactly two others, forming a loop. Data hops through nodes.

✓ Predictable transmission
✗ One break = whole ring down
Network topologies — Mesh, Star, Bus, Ring
TopologyStructureAdvantagesDisadvantagesIEEE Standard
Mesh Every node ↔ every other node Highly reliable, fault-tolerant, no data loss if one link fails Very costly, complex to install and manage —
Star All nodes → central hub/switch Easy to add/remove, simple troubleshooting Central hub failure = entire network down 802.3 (Ethernet)
Bus All nodes on single shared cable Easy to install, less cable required Collisions common, hard to troubleshoot, limited scalability Early 802.3
Ring Each node connects to 2 neighbors in loop Reduced collisions, predictable data flow Complex troubleshooting, slower (data hops through each node) 802.5 (Token Ring)
