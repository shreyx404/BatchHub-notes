01 · Foundations

What the OSI Model Is

In 1984, the International Organization for Standardization (ISO) published a seven-layer blueprint for inter-computer communication: the Open Systems Interconnection (OSI) reference model. It is not software, not hardware, and not a protocol — it is an architectural model that describes how information from a software application in one computer moves through a physical medium to the software application in another computer.

Definition — write it exactly like this

OSI is a reference model that describes how information from a software application in one computer moves through a physical medium to the software application in another computer.

  • Seven layers — each layer performs one particular network function; none tries to do everything.
  • Division of labour — the whole communication task is divided into seven smaller, manageable tasks, one assigned to each layer.
  • Self-contained layers — each layer can perform its task independently, so a layer can be changed or upgraded without redesigning the model.
  • Developed by ISO in 1984 — now considered the architectural model for inter-computer communications.
  • Conceptual, not an implementation — OSI defines functions, not running code. It is used for teaching, troubleshooting and protocol design.

    02 · Structure

    Layered Architecture & Organisation of the Layers

    Why layer at all? Because networking is a monstrous problem. The model's genius is divide and conquer: break the whole task into seven smaller, manageable sub-tasks, and make each layer self-contained so its sub-task can be performed independently. A layer only needs to know what service it requests from below and what it offers above — never how the neighbours achieve it.

    Benefits of a layered architecture

    • Manageability — seven small problems instead of one giant one; each is designed, taught and debugged separately.
    • Modularity / independence — changes in one layer (e.g. upgrading a protocol) do not affect other layers, provided the interfaces remain unchanged.
    • Interoperability & vendor independence — devices from different vendors interoperate because every layer has a standard function.
    • Easier troubleshooting — a fault can be isolated to one layer instead of the entire system.
    • Standardisation — a common framework for designing and comparing protocols.

    Organisation — upper layers vs lower layers

    The OSI model is divided into two halves. The upper layers mainly deal with application-related issues and are implemented only in software. The lower layers deal with data-transport issues; the data-link and physical layers are implemented in hardware and software. (An "upper layer" simply means the layer just above another layer.)

    Upper layers · 7–5 Lower layers · 4–1
    Deal with application-related issues — data representation, dialogue, network services. Deal with data-transport issues — end-to-end delivery, routing, framing, signalling.
    Implemented only in software; Application layer is closest to the end user. Data-link + Physical implemented in hardware and software; Physical is the lowest layer, closest to the physical medium.
    Concerned with what is sent. Concerned with how it reaches the other machine — the Physical layer places the information on the medium.
    Protocol vs Interface — a favourite short answer Protocol = the horizontal rules between peer layers on different machines (Layer-4-on-A ↔ Layer-4-on-B). Interface = the vertical rules between adjacent layers on the same machine, defining the services and primitives the lower layer offers to the one above. A Service Access Point (SAP) is the defined "slot" through which the layer above taps the services of the layer below — like numbered mailboxes between floors of a building.
    03 · Communication pattern

    Peer-to-Peer Processes & Interfaces Between Layers

    Here is the subtle idea the whole model rests on. Each layer on one device interacts logically with the same layer on another device — its peer. The Transport layer on Computer A communicates with the Transport layer on Computer B; the Network layer on A communicates with the Network layer on B, and so on up and down the stack. These matched pairs are called peer-to-peer processes.

    But no layer ever jumps across the network directly (except the Physical layer). Each layer only directly communicates with the layers immediately above and below it on the same machine:

    • Downward communication — it receives data from the higher layer, processes it, adds its own header, and passes it down.
    • Upward communication — it sends data to the higher layer after stripping and processing the header its peer added.

    Because corresponding layers run the same protocol, each layer "understands" exactly the header its peer wrote — that is what makes the logical conversation possible. The interfaces between layers are critical for two things: encapsulation (adding headers/trailers on the way down) and Service Access Points (SAPs) through which adjacent layers interact.

    FIG. 02Logical peer talk vs actual physical flow — hover any layer row

    Exam pointer

    "Distinguish logical peer-to-peer communication from actual data flow" is a classic 3-mark short answer. Peer layers never exchange data directly — they exchange headers via the layer below, all the way down to the Physical layer, which is the only layer that actually touches the medium.

    04 · Data in motion

    Encapsulation & Decapsulation

    As data moves down the layers on the sending side, each layer treats everything received from above as plain payload, adds its own header (and sometimes a trailer) in front of / behind it, and hands the bundle to the layer below — this is encapsulation. On the receiving side the mirror image runs upward: each layer removes and reads exactly the header its own peer wrote, then passes the payload up — this is decapsulation.

    05 · The model's DNA

    Ten Characteristics of the OSI Model

    These ten properties are the standard "characteristics of OSI" answer — memorise the bold lead words; each pair of rows below is one marking point.

    01
    Layered architecture

    Seven layers, each with a specific function, communicating only with its peer layer on another device (peer-to-peer) and with the layers directly above and below it on the same device (interface communication).

    02
    Standardised protocols

    Provides a standard framework so devices from different vendors can interoperate — promoting vendor independence and compatibility.

    03
    Encapsulation & decapsulation

    Headers (and sometimes trailers) are added as data descends the sender's stack, and removed layer-by-layer as it climbs the receiver's stack.

    04
    Modularity

    Each layer is independent — changes in one layer (e.g. a protocol upgrade) do not affect others, provided the interfaces remain unchanged.

    05
    Peer-to-peer communication

    Each layer on the sender's device communicates logically with the same layer on the receiver's device — Transport on A ↔ Transport on B.

    06
    Service-oriented

    Every layer provides services to the layer above and consumes services from the layer below — e.g. the Network layer provides routing services to the Transport layer.

    07
    Protocol independence

    The model defines functions, not specific protocols — at Transport you may choose TCP or UDP; at routing, RIP or OSPF.

    08
    Standard reference model

    A conceptual model, not an implementation — used mainly for teaching, troubleshooting and protocol design.

    09
    Facilitates troubleshooting

    Layered nature lets you isolate issues to a specific layer — an IP-addressing problem points straight at the Network layer.

    10
    Interoperability

    Different systems, hardware and software can communicate regardless of their underlying architecture.

    06 · The rules of conversation

    What Is a Protocol?

    Definition

    A protocol is a set of rules that governs how data is transmitted and received between devices in a network — a standardised language that computers use to communicate, ensuring messages are understood correctly and processed accordingly.

    Every protocol can be described by three classic elements — a neat two-mark answer:

    • Syntax — structure and format of the data: field order, header layout, encoding.
    • Semantics — the meaning of each bit of structure: control information, error handling, action to take.
    • Timing — when to send and how fast: sequencing, speed matching, timeouts.

    The OSI model itself defines no protocols — only the function each layer must perform (characteristic 7: protocol independence). Real protocol families then fill those slots. The table you must internalise for this unit is the port map: every application-layer dialogue runs on a numbered TCP or UDP port, and examiners love one-mark port questions.

    Exam pointer

    Port numbers are the most-asked one-liner of this unit. Learn the consolidated "port wall" in §14 — DNS 53, HTTPS 443, FTP 20/21, Telnet 23, SMTP 25/587, POP3 110, IMAP 143/993, NetBIOS 137/138/139, RPC 135. Also remember: ports exist only at Layer 4 — IP itself has none.

    07 · Layer 7 of 7 — the window

    Application Layer

    L7

    The window. This layer provides network services to the end-user — it serves as a window for users and application processes to access network service. It is the layer closest to the end user; the user and this layer interact directly with the software applications.

    An immediate clarification that earns marks: "Application layer" does not mean applications like Word or Photoshop. It means the network application protocols that allow such software to communicate over a network. This layer interfaces directly with software applications to provide network services, determines resource availability, and ensures communication is possible. Here we find the protocols that define how application data is formatted and exchanged.

    Functions

    File transfer, access & management (FTAM) — lets a user access, retrieve and manage files on a remote computer.

    Mail services — provides the basis for email forwarding and storage.

    Directory services — provides distributed database sources used to supply global information about various objects.

    Working

    Data preparationNecessary headers and control information are added; the right protocol (HTTP, FTP, SMTP…) is selected for the data and service.
    Data transferPrepared data passes to Presentation for formatting, then down through Session, Transport, Network, Data Link and Physical.
    Data receptionThe receiver's Application layer gets data from the lower layers and extracts it from the packet.
    InterpretationData is interpreted per the protocol used and presented to the user in a suitable format.

    Protocols & ports

    Protocol Port What it does
    HTTP TCP 80 Transfers webpages and resources between servers and browsers — human-readable, stateless, text-based.

    Real-world scenario When you type a website name in your browser: DNS resolves it to an IP address, then HTTP/HTTPS fetches the page. Two Application-layer protocols, one click.
    08 · Layer 6 of 7 — the translator

    Presentation Layer

    L6

    The translator. This layer is responsible for translating, encrypting and compressing data. It integrates all data formats into acceptable, compatible ones, so the Application layer always receives data in a usable form — enabling secure, unambiguous transfer across the network. It converts data from a complex format into one the application layer understands — which is exactly why it is called the translator.

    Functions

    Data translation — character-code conversion between different systems' sets (ASCII, EBCDIC, Unicode), plus conversion of complex data structures into a standard transmission format.

    Syntax & semantics — defines the syntax (structure) of data and its meaning (semantics), ensuring data is interpreted correctly at the receiving end.

    Compression & decompression — reduces the number of bits to be transmitted. Common algorithms: Huffman coding, Lempel-Ziv (LZ), dictionary-based compression. Crucial for multimedia — text, audio, video.

    Encryption / decryption — converting the sender's information into another form before it travels the network, to maintain privacy. Common algorithms: AES, DES, RSA. Protects confidentiality and integrity.

    Data formatting — converts data into a standard format for transmission, ensuring compatibility between different systems.

    TLS no fixed port Transport Layer Security — encrypts and ensures integrity of communication; rides along with application protocols (e.g. HTTPS uses TLS over TCP 443).
    SSL no fixed port Secure Sockets Layer — the predecessor of TLS, now deprecated in its favour (HTTPS, FTPS, SMTPS).

    Worked example — image transfer

    • Converts the image format (e.g. JPEG, PNG) into a standard transfer format.
    • Compresses the image to reduce file size.
    • Encrypts it to protect it during transmission.
    • Formats the image data for transmission — and at the receiving end the Presentation layer reverses every step to restore the original image.
    Real-world scenario When a secure banking page loads, TLS encrypts the data before transmission — presentation-layer security in action.
    09 · Layer 5 of 7 — the dialog controller

    Session Layer

    L5

    The dialog controller. The fifth layer is responsible for establishing, managing and terminating communication sessions between applications on different hosts, and for synchronising the data exchange. It acts as a bridge between the higher-level application layer and the lower-level transport layer.

    Functions

    Session establishment & termination — initiates and ends sessions between applications; allocates the necessary resources.

    Session management — controls the dialogue between applications, deciding which party can send data at any moment; manages synchronisation points for recovery in case of failure.

    Data synchronisation — ensures data is transferred correctly and in order, using checkpoints to recover data after transmission errors or interruptions.

    Multiplexing — allows several applications to share a single network connection and manages multiple sessions simultaneously.

    Session establishment — initiates a session request with the remote application and negotiates parameters: data-transfer mode (half- or full-duplex) and synchronisation points.

    Session management — controls the flow of data between applications using session identifiers to track different sessions, and manages checkpoints for recovery.

    10 · Layer 4 of 7 — the end-to-end deliverer

    Transport Layer

    L4

    The end-to-end deliverer. The fourth layer ensures complete, error-free and sequenced delivery of data. It provides end-to-end communication, reliability and port-based addressing, and may work connection-oriented (TCP) or connectionless (UDP).

    Functions

    End-to-end delivery — a reliable connection between two applications on different hosts; guarantees data arrives in the correct order and without errors.

    Segmentation & reassembly — breaks data into smaller segments for efficient transmission; reassembles them at the destination to restore the original data.

    Flow control — manages the rate of transmission so the receiving host is never overwhelmed.

    Error control — detects and corrects errors using checksums and similar mechanisms.

    Connection management — establishes, maintains and terminates connections between applications — setup and teardown both.

    Multiplexing & demultiplexing — lets multiple applications share a single network connection, identifying which application each piece of data belongs to (by port).

    Working

    Receives data from the Session layer — typically as a continuous data stream.

    Segments it — each segment's header carries source and destination ports, sequence number, acknowledgment number, checksum and other control data.

    Applies error & flow control — detection/correction mechanisms such as checksums and ARQ; flow regulation such as the sliding window.

    Manages the connection — for connection-oriented protocols like TCP, a connection is established before transfer (SYN → SYN-ACK → ACK) and connection state is maintained throughout.

    Delivers to the Network layer — which adds its own header and encapsulates the segments into packets.

    FIG. 08Multiplexing down, demultiplexing up — sorted by port number

    The two great transports — TCP vs UDP

    TCP (Transmission Control Protocol) is connection-oriented and reliable. It establishes and maintains a connection between hosts, divides data into segments, and — because segments travel the internet by multiple routes and may arrive out of order — reorders them correctly at the receiving end. It provides flow control, error recovery and congestion control, which is why HTTP, FTP and SMTP ride on it.

    UDP (User Datagram Protocol) is connectionless and unreliable: the receiver sends no acknowledgment when a packet arrives and the sender does not wait for one — that is precisely what makes it unreliable, and what makes it fast, with low overhead. It suits applications tolerating loss or delay: DNS, streaming media, VoIP.

    SCTP (Stream Control Transmission Protocol) adds multi-streaming and multi-homing on top of TCP-style reliability; ports are application-defined. Its classic use is telecom signalling.

    11 · Layer 3 of 7 — the navigator

    Network Layer

    L3

    The navigator. Layer 3 manages device addressing and tracks the location of devices on the network. It determines the best path to move data from source to destination — based on network conditions, the priority of service, and other factors — and is responsible for routing and forwarding packets. Routers are Layer-3 devices, providing routing services within an internetwork. The protocols that route network traffic are network-layer protocols: IP and IPv6.

    Functions

    Addressing — assigns logical addresses (IP) to devices; a unique identifier for each device on the network.

    Routing — determines the best path from source to destination; routing protocols (RIP, OSPF, BGP) build and maintain routing tables.

    Packet switching — breaks data into smaller packets for transmission, adding header information including source and destination addresses; each packet is routed independently.

    Congestion control — manages network traffic to prevent congestion and ensure efficient transfer, regulating data flow.

    Error handling — detects errors in transmitted packets and applies correction mechanisms such as checksums to protect data integrity.

    Working

    Receives data from the Transport layer — segments carrying data plus end-to-end communication information.

    Encapsulates — adds a header to create a packet: source logical address (sender's IP), destination logical address (receiver's IP), and control information — packet length, time-to-live (TTL), protocol.

    Routes — routing protocols determine the best path; routers examine the destination address and forward the packet to the next hop.

    Packet-switches — large data is split into smaller packets, each independently routed through the network.

    Delivers to the Data Link layer — which adds its own header and trailer to create a frame for the physical network.

    FIG. 10Routing — every router reads H3 and picks a next hop

    Key protocols

    Protocol Port / No. What it does
    IP (IPv4 / IPv6) no ports! Provides addressing and packet delivery between hosts — basic connectivity between networks.
    ICMP IP proto no. 1 Internet Control Message Protocol — diagnostic and error messages (the engine behind ping & traceroute).
    ARP — Address Resolution Protocol — maps IP addresses to physical (MAC) addresses.
    RARP — Reverse ARP — maps physical (MAC) addresses to IP addresses.
    IGMP IP proto no. 2 Internet Group Management Protocol — manages membership of multicast groups.
    OSPF IP proto no. 89 Open Shortest Path First — a routing protocol that finds the shortest path in an IP network.
    RIP · BGP routing protocols Build and maintain routing tables — distance-vector (RIP) and the internet's inter-domain protocol (BGP).
    Exam pointer — the trick question

    "Which port does IP use?" — none. Ports exist only in the Transport layer. IP is identified instead by protocol numbers: ICMP = 1, IGMP = 2, OSPF = 89. And keep ARP/RARP directions straight: ARP finds a MAC from an IP; RARP finds an IP from a MAC.

    Real-world scenario When you open Google Maps, IP addressing ensures your request actually reaches Google's servers across dozens of routers — each making its own next-hop decision from your packet's H3 header.
    12 · Layer 2 of 7 — warden of a single link

    Data Link Layer

    L2

    The warden of a single link. This layer is responsible for the error-free transfer of data frames, defines the format of data on the network, provides reliable and efficient communication between two or more devices, and uniquely identifies each device on the local network — by its physical (MAC) address.

    The two sublayers

    The data link layer is itself split — a fact the syllabus stresses and examiners reward:

    • Logical Link Control (LLC) — responsible for transferring packets to the Network layer of the receiver; identifies the network-layer protocol from the header; also provides flow control. (IEEE 802.2.)
    • Media Access Control (MAC) — the link between LLC and the network's physical layer; used for transferring packets over the network, physical addressing and arbitration of the shared medium. (IEEE 802.3 / 802.11.)

    PHYSICAL LAYER · L1 — bits leave

    Functions

    Framing — translates the physical layer's raw bit stream into packets known as frames, adding a header and a trailer; the header carries the hardware destination and source addresses.

    Physical addressing — adds a header containing the destination (MAC) address, and the frame is transmitted to exactly the destination named in that header.

    Flow control — the layer's core discipline: a constant data rate is maintained on both sides so no data is corrupted — a fast transmitting station (a powerful server) must not overrun a slower receiving one.

    Error control — a calculated CRC (Cyclic Redundancy Check) value is placed in the trailer before the frame goes to the physical layer; if an error is detected, the receiver sends an acknowledgment requesting retransmission of the corrupted frame.

    Access control — when two or more devices share one communication channel, data-link protocols decide which device has control of the link at a given time.

    Packet vs Frame — the classic comparison

    The packet is the basic unit of communication between source and destination in a network: data sent over the network is divided into packets that the destination recombines. Dividing data into packets lets a network manage different bandwidths, different routes, and many connected devices receiving packets independently — and makes it easy to retransmit only the lost pieces. Each packet's header carries source and destination IP addresses, a protocol field, version, and a trailer field with error-correction information and identification flags. The frame is its Layer-2 counterpart — a small part of a message that identifies the data and how it should be decoded. The essential difference is simply which layer each belongs to; a frame carries more link-specific information than a packet.

    HDLC none High-Level Data Link Control — a synchronous data-link protocol that encapsulates data on serial links.
    Real-world scenario When two computers connect through a switch, Ethernet frames use MAC addresses to deliver data — the switch is a purely Layer-2 device making purely local decisions.
    Exam pointer

    "Differentiate packet and frame" is a standard 4-mark question — reproduce the table above in table form, and lead with the one-line rule: packet = L3 + IP; frame = L2 + MAC (+ CRC).

    13 · Layer 1 of 7 — courier of raw bits

    Physical Layer

    L1

    The courier of raw bits. The lowest layer's main functionality is to transmit individual bits from one node to another. It establishes, maintains and deactivates the physical connection, and specifies the mechanical, electrical and procedural network interface specifications. It also converts the data frames received from the data-link layer into bits of 1s and 0s for transmission, and maintains data quality by applying the necessary protocols and maintaining the data bit rate.

    Functions

    Line configuration — defines the way two or more devices are physically connected.

    Data transmission — defines the transmission mode between the two devices: simplex, half-duplex or full-duplex.

    Topology — defines how network devices are arranged (bus, ring, star, mesh…).

    Signals — determines the type of signal used to carry the information.

    Interface specifications — mechanical, electrical and procedural characteristics of the network interface.

    FIG. 13The three transmission modes — a guaranteed two-mark question

    Characteristics of the physical layer

    Signals — data frames from upper layers are converted into network signals for the channel. Two kinds: digital signals (discrete pulses representing the upper layers' digital data) and analog signals (continuous waves carrying the converted bits).

    Transmission medium — without proper conversion at this layer, network function is damaged. Wired: fibre-optic cable, coaxial cable, etc. Wireless: Bluetooth, Wi-Fi and other radio models.

    Data flow — maintains the information flow rate and the transmission time frame. Three factors affect it: error-rate (incorrect data received due to channel noise), encoding (how data is encoded for the channel) and bandwidth (the transmission rate the channel can carry).

    Noise in transmission — transmitted data may be damaged or corrupted for several reasons. Dispersion: data spreads and overlaps in transit, damaging the original signal. Attenuation: gradual weakening of the signal along the channel. Data delay: data arrives outside its specified time frame.

    15 · Final approach

    Exam Corner

    One-mark quick facts

    OSI = Open Systems Interconnection, by ISO, 1984
    7 layers; each self-contained; OSI is conceptual, not an implementation
    PDU ladder: Data (7–5) → Segment → Packet → Frame → Bits
    Ports exist ONLY at L4 — IP has no ports
    ICMP = proto 1 · IGMP = 2 · OSPF = 89
    TCP header ≥ 20 B · UDP header 8 B
    ARP: IP → MAC · RARP: MAC → IP
    FTP: two connections — 20 data, 21 control
    SSL deprecated → TLS; HTTPS = HTTP + TLS over 443
    DNS: UDP 53 (TCP 53 for zone transfers)
    SMTP sends (25/587); POP3 downloads & deletes (110); IMAP syncs (143/993)
    NetBIOS: UDP 137 / 138, TCP 139 · RPC: TCP 135
    Data link sublayers: LLC + MAC; CRC rides in the L2 trailer
    Routers L3 · switches/bridges L2 · hubs/repeaters L1
    Attenuation = weakening · dispersion = spreading/overlap · delay = late arrival
    SCTP = multi-streaming + multi-homing, telecom signalling
    Upper layers (7–5) software only · L2 + L1 hardware + software
    Session = dialog controller · Presentation = translator · Application = window

    Self-test — cover the answer, then reveal

    Q·01

    The OSI model was developed by whom, and when?
    AnswerBy the International Organization for Standardization (ISO) in 1984 — a seven-layer architectural model for inter-computer communications.
    Q·02

    Name the PDU at each of Layers 4, 3, 2 and 1.
    AnswerSegment (L4), Packet/datagram (L3), Frame (L2), Bits (L1). Layers 7–5 all carry "Data".
    Q·03

    Which layer adds a trailer, and what does it contain?
    AnswerThe Data Link layer (L2) — the T2 trailer carries the CRC (Cyclic Redundancy Check) for error detection; corrupted frames are retransmitted on request.
    Q·04

    Match the addressing: L2, L3, L4.
    AnswerL2 → MAC (physical) address; L3 → IP (logical) address; L4 → port numbers. Ports exist nowhere else.
    Q·05

    Which protocols belong to the Presentation layer?
    AnswerTLS, SSL (deprecated in favour of TLS) and MIME — covering encryption and multimedia encoding within email protocols.
    Q·06

    Checkpoints and dialog control are functions of which layer?
    AnswerThe Session layer (L5) — it establishes, manages, synchronises and terminates sessions, resuming from the last checkpoint after failures.
    Q·07

    State the packet-vs-frame difference in one line.
    AnswerA packet is the L3 unit carrying source/destination IP addresses; a frame is the L2 unit carrying MAC addresses plus a CRC trailer — a packet is encapsulated inside a frame.
    Q·08

    Give one use-case each for TCP and UDP, with reasons.
    AnswerTCP — email/HTTP/FTP, needing ordered, error-free delivery (retransmission + reordering). UDP — DNS lookups, streaming, VoIP: speed matters more than perfect delivery.
    Q·09

    What is ICMP's protocol number and purpose?
    AnswerIP protocol number 1 — diagnostic and error messages; the mechanism behind ping and traceroute.
    Q·10

    Define attenuation vs dispersion vs data delay.
    AnswerAttenuation — gradual weakening of a signal over the channel; dispersion — signal spreading/overlapping that damages the original data; data delay — arrival outside the specified time frame.
    Q·11

    List the NetBIOS ports and their services.
    AnswerUDP 137 (name service), UDP 138 (datagram service), TCP 139 (session service).
    Q·12

    Which layers are implemented in hardware?
    AnswerThe Physical layer, and the Data Link layer, are implemented in hardware and software; Layers 7–5 are software only. Layer 4/3 sit in software on the hosts.
