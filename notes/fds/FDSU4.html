§ 01 · Orientation

Unit at a glance

Stacks and queues are not new data structures — they are the general List ADT with access deliberately restricted. That restriction is the entire point: it produces the LIFO and FIFO disciplines, guarantees O(1) operations, and powers everything from expression evaluation to CPU scheduling.

Exam note

If an exam question asks “how do a stack and a queue relate to the List ADT?” — answer: both are restricted Lists; insertion and deletion are limited to fixed ends. The difference is entirely in which ends: a stack uses one end for both operations; a queue uses opposite ends.

The Stack ADT

Definition

A stack is a special kind of list in which all insertions and deletions happen at one end, called the TOP. It is also known as a pushdown list or a LIFO (Last-In, First-Out) list.

The five operations (Aho, Hopcroft & Ullman)

OperationEffect
MAKENULL(S)Makes S an empty stack
PUSH(x, S)Inserts element x at the top of S
TOP(S)Returns the element at the top of S
POP(S)Deletes the top element of S
EMPTY(S)Returns true iff S has no elements

Note what is absent: no position is ever named or searched. Every operation touches only the top — that is why everything is O(1).

Characteristics

  • Data can only be placed on the top of the stack.
  • Data can only be removed from the top of the stack.
  • Data can only be removed from the bottom if it is the only item on the stack.
  • Data cannot be removed from the middle without first removing all items above it.

Formal ADT specification

Read s1 as “the state of the stack before the operation”. A precondition must hold for the call to be legal; a postcondition is what the call guarantees. POP and TOP demand a non-empty stack; PUSH demands a non-full one — these are exactly the underflow and overflow checks you write in code.

Primitive operations, in words

  • Create a stack (array or linked list)
  • Push(e) — place e on top, if not full
  • Pop() — take out the top item, if not empty
  • Read top — inspect without removing
  • Stack_Empty() / Stack_Full() — boolean checks

Stacks in everyday life

  • A stack of plates — only the top plate can be lifted off or added to
  • A stack of books on the floor — the most recently placed book comes off first
  • Undo in a text editor — the last edit made is the first undone
  • The “back” button in a browser — the most recently visited page reappears first
  • Stack of coins, stack of chairs, Tower of Hanoi

The complete class

This is exactly MAKENULL, PUSH, POP, TOP and EMPTY from the ADT, renamed to C++ style. Every member function runs in O(1) — no loops, no shifting.

Exam note — two classic definitions

Stack overflow: pushing onto a full array — the array has nowhere left to grow. Stack underflow: popping an empty stack. Both are checked before the index moves. Also remember: the popped slot is not cleared — the stale value simply sits there until the next push overwrites it.

Notations & precedence

An expression is a string of operands and operators. Operands are numeric values; operators are unary (+, −) or binary (+, −, *, /, ^). Where the operator sits relative to its operands defines the notation — and everything else follows from that.

Why bother with postfix?

  • Postfix can be evaluated with a single left-to-right scan and a stack — no precedence table, no parentheses, no backtracking
  • This is exactly how many real compilers and calculators evaluate arithmetic internally
  • Example: (A + B) * C needs parentheses in infix to override precedence; in postfix the same expression is A B + C * — the order of the operators already encodes what happens first

Precedence in action

  • A + B * C — * binds tighter than +, so this means A + (B * C)
  • A * B + C * D — both multiplications happen before either addition
  • A ^ B ^ C — ^ is right-associative: A ^ (B ^ C)
  • A − B − C — left-associative: (A − B) − C, not A − (B − C)
Exam note — why right-associativity matters for ^

Exponentiation is not associative: 2 ^ 3 ^ 2 evaluated right-associatively (correct) is 2 ^ (3 ^ 2) = 2 ^ 9 = 512; evaluated left-associatively (wrong) it is (2 ^ 3) ^ 2 = 8 ^ 2 = 64. This is the single most-tested associativity fact in this unit — and it changes the conversion algorithm’s pop rule (see § 09).

§ 09 · Expressions

Infix → postfix conversion

Basic rules

  1. Operands — letters or numbers go to the output right away
  2. Opening parenthesis ( — push it onto the operator stack
  3. Closing parenthesis ) — pop operators to the output until the matching ( is found; then discard both parentheses (no parenthesis ever reaches the output)
  4. Operators (+ − * / ^) — pop higher-or-equal precedence operators to the output before pushing the new operator (respecting associativity)
  5. End of input — pop every remaining operator to the output

The algorithm

  • Scan the infix expression left to right, using one stack to hold operators and parentheses
  • Operand → append directly to the output
  • ( → push onto the stack
  • ) → pop operators to the output until the matching ( is found; discard both
  • Operator o → pop and output every stack-top operator with precedence ≥ o (respecting associativity), then push o
  • At the end of the scan, pop every remaining operator to the output
Exam note — the associativity refinement

“Pop while precedence ≥ incoming” is correct for the left-associative operators (+ − * /). For the right-associative ^, pop only while stack precedence is strictly greater — so a second consecutive ^ gets pushed on top of the first, producing A B C ^ ^ = A^(B^C). If you pop on equality you wrongly get (A^B)^C.

Trace 1 — A + B * C (no parentheses)

Precedence alone decides the order. * has higher precedence than +, so + is never popped while * sits above it; every operator is eventually popped once scanning ends.

The two-precedence trick (Sahni-style tables)

Some textbooks give each operator two precedences: an in-stack precedence (ISP) and an off-stack / incoming precedence (ICP). The rule becomes: push the incoming operator while its off-stack precedence is greater than the in-stack precedence of the top; otherwise pop first.

  • Incoming * (ICP 3) over top + (ISP 2) → 3 > 2 → push — * waits above +
  • Incoming + (ICP 1) over top * (ISP 4) → 1 ≤ 4 → pop first — left-associativity
  • Incoming ^ (ICP 6) over top ^ (ISP 5) → 6 > 5 → push — this is exactly what makes ^ right-associative
  • ( has ICP 100 (always pushed) but ISP 0 (nothing above it ever pops) — it acts as a wall

§ 10 · Expressions

Infix → prefix conversion

Method A — right-to-left scan with two stacks

  1. Scan the expression character by character from right to left
  2. If ) → push onto the operator stack
  3. If an operand → push onto the prefix stack (prestack)
  4. If an operator → if the opstack is empty, push it; else pop operators from the opstack onto the prestack while the top’s precedence ≥ the incoming operator’s, then push the incoming operator
  5. If ( → pop the opstack onto the prestack until the matching ) is found; ignore (cancel) both parentheses
  6. At the end, pop all remaining opstack entries onto the prestack
  7. The answer is obtained by popping the prestack completely — it comes out in left-to-right order

The slide-deck variant of this algorithm builds the result string p[] from the right end (k = n−1, decrementing as symbols are placed) — the same idea expressed as index arithmetic.

Method B — without an operator stack (four steps)

1 · reverse the infix string  →  2 · swap every ( with ) and ) with (
3 · convert that string to postfix (the ordinary algorithm)  →  4 · reverse the output infix → prefix, mirrored

Worked micro-example, A*B+C: reverse → C+B*A; no parentheses to swap; postfix of C+B*A → CBA*+; reverse → +*ABC ✓. The logic: reversing mirrors the expression, so “operator after operands” (postfix) becomes “operator before operands” (prefix).

§ 11 · Expressions

Evaluating postfix & prefix

Postfix evaluation — the algorithm
  1. Read the postfix expression character by character, left to right
  2. Operand → take its value and push it onto the stack
  3. Operator → pop two operands as op2 (first pop — the RIGHT operand) and op1 (second pop — the LEFT operand); compute result = op1 OP op2
  4. Push the result back onto the stack
  5. Repeat until the expression is exhausted
  6. Pop the single remaining value from the top — that is the answer
Exam note — operand order (the #1 lost mark)

The second pop is the LEFT operand: compute op1 OP op2, never op2 OP op1. For + and * it happens not to matter (commutative), but for − and / the order is decisive: 6 5 − is 1, not −1. Example from 8 / 2: op1 = 8, op2 = 2 → 4.

Trace — 3 4 + 5 *  (from infix (3 + 4) × 5)

One stack, one pass. The stack never needed to know about precedence, because postfix had already encoded it. The same three-line loop evaluates any postfix expression, however deeply nested the original infix was — this is the technique used inside many calculators and stack-based virtual machines. Similarly 1 2 3 + *: push 1, push 2, push 3; + → 2+3=5; * → 1×5 = 5.

Every active procedure call gets an activation record pushed onto the run-time stack — Aho, Hopcroft & Ullman note this holds regardless of whether the language allows recursion. This is the implicit stack of § 06 at work.

Each record holds everything needed to resume the caller. When the callee returns, its record is popped and the caller’s state — untouched beneath it on the stack — becomes current again.

Simulating recursion without recursion

Any recursive procedure can be rewritten iteratively by managing an explicit, user-defined stack — Aho, Hopcroft & Ullman call this “complete recursion elimination” (§ 2.6). Each stack cell stores exactly what an activation record would: the current parameter values, the current local variables, and a marker for where to resume.

  • Why do it? Procedure calls are expensive in some languages; an explicit stack can be faster in tight, frequently-executed code
  • Trade-off: the resulting code is longer and harder to read — recommended only when speed truly matters
  • Tail-recursion elimination (the lighter variant): when the recursive call is the very last action, it can be replaced by a jump / loop — no stack growth at all

Recursion vs iteration

AspectRecursionIteration
Memory useO(depth) stack framesO(1) extra (typically)
Code clarityOften shorter, mirrors the definitionCan require extra bookkeeping
RiskStack overflow on deep recursionNo call-stack growth

Stack overflow — causes and prevention

  • Every activation record takes real memory; the run-time stack has a fixed size limit
  • Recursion with no reachable base case — or a base case that is never satisfied — keeps pushing frames forever
  • Eventually the stack’s memory region is exhausted: a stack overflow, which normally crashes the program
  • Prevention: (1) always ensure the base case is reachable from every recursive call; (2) check that each call moves strictly closer to the base case; (3) for very deep or unbounded recursion, prefer the iterative / explicit-stack version

  • A call-centre queue — callers are answered in the order they called
  • Batch-mode operating systems — jobs to be processed are placed in a queue awaiting execution

Modulo arithmetic makes it wrap

Instead of always incrementing, advance an index with % size. When an index reaches size − 1, the very next step brings it back to 0. This is exactly the “circle” AHU describe: the array’s last position is followed by its first.

rear = (rear + 1) % size   ·   front = (front + 1) % size
size = 6:  rear = 5  →  (5 + 1) % 6 = 0 index 5 is followed by index 0 — a full slot’s reuse, automatically

Worked example from the deck (size 5): rear = (4+1) % 5 = 0 — after the fourth location we store data at location zero again; front = (3+1) % 5 = 4 — after location 3 we delete from location 4. The advantage of the circular queue: the space of the queue is used fully, curing the false overflow of the linear version.

Priority queues

Definition

A priority queue is a data structure in which the intrinsic ordering of the elements determines the result of its basic operations — not arrival order. It is a set with the operations INSERT and DELETEMIN. DELETEMIN is “a function that returns some element of smallest priority and, as a side effect, deletes it” — it combines DELETE and MIN into a single ADT operation. (“Some”, because several elements may tie for smallest.)

Min-priority vs max-priority

VariantWho leaves firstExample
Min-priority (ascending)DELETEMIN removes the smallest priority valueAn emergency room — the most critical patient (lowest “time to harm”) goes first
Max-priority (descending)The largest priority value leaves firstA task scheduler that always runs the highest-priority job next

From the second reference deck, in array terms: an ascending priority queue is a collection where items can be inserted arbitrarily but only the smallest priority value can be removed; a descending priority queue inserts arbitrarily but removes only the largest. Sometimes we need to insert or delete from other positions than front or rear — that is exactly what the priority queue buys us.

Worked example — the emergency room

“Patients having potentially fatal problems will be taken before any others, no matter how long the respective waits are.”

How would we implement this?

A priority queue is a set with INSERT and DELETEMIN — so any set implementation works. The trade-offs:

ImplementationINSERTDELETEMIN
Unsorted listO(1)O(n) — must scan for the minimum
Sorted listO(n) — must find the insertion pointO(1) — minimum is always first
Heap (“partially ordered tree”)O(log n)O(log n)

Issues for the array implementation — and the fix

  • Must examine all the elements to find the largest / smallest for deletion
  • Removal from the middle of an array is complicated: it needs to shift all subsequent elements
  • Needs some indicator (e.g. −1) to mark the empty status of vacated positions
  • A new insertion into an unsorted array leads to total disorder — every deletion requires a full scan
  • Solution: keep the elements arranged in ascending or descending order after each insertion — then the extreme element is always at a known end

Linked-list implementation

  • Single list — sorted nodes in one list: insert walks to the correct position, the minimum / maximum sits at a known end
  • Multiple lists — one list per priority value: e.g. insert nodes with priority 2 and priority 3 into their own lists; DELETEMIN only ever looks at the lowest non-empty list’s front

Stacks

Trace push(5), push(8), pop(), push(2) on an empty stack. What is on top at the end?

Stack after each step: [5] → [5, 8] → pop removes 8 → [5] → push(2) → [5, 2]. The top is 2 (top index = 1).

Starting from an empty stack, what is on top after push(1); push(2); pop(); push(3)?

pop() removes 2 (the then-top). Final stack: [1, 3]. Top = 3.

Why is push() considered O(1) even though the array could hold thousands of elements?

push() touches only the position at top: one comparison (isFull()), one increment (top+1), one write. No other element is ever inspected, searched, or shifted — the cost is independent of n.

What does LIFO stand for? Name one everyday example.

Last-In, First-Out — the most recently inserted element is the first removed. Everyday examples: a stack of plates (only the top plate moves), books on the floor, undo in an editor, the browser back button.

State two drawbacks of the array stack implementation and the linked-list remedy.

Array: (1) size is restricted — capacity fixed before use, so pushes can overflow; (2) memory is wasted if the stack stays mostly empty. Linked list: nodes are created dynamically as needed — isFull() becomes not applicable; push = insert-at-head, pop = delete-at-head, still O(1).

Distinguish implicit and explicit stacks.

Implicit: built by the run-time environment to store function-call status; push/pop happen automatically and the programmer cannot manipulate it (function calls, recursion). Explicit: designed by the programmer; push/pop are called manually by the user (e.g. reversing a string, expression conversion, the user stack in recursion elimination).

Why does right-associativity matter specifically for the ^ operator?

Exponentiation is not associative. For 2 ^ 3 ^ 2: right-associative (correct) = 2^(3^2) = 2^9 = 512; left-associative (incorrect) = (2^3)^2 = 8^2 = 64. In the conversion algorithm this means a second consecutive ^ must be pushed, not popped — pop only on strictly greater precedence for ^.

Give reasons a compiler might prefer postfix over infix internally.
  • No parentheses — the order is completely clear without grouping symbols
  • No precedence table — the operator positions already encode the evaluation order
  • Simple rules — an operator always immediately follows its operands
  • Easy stack usage — one left-to-right scan with push/pop evaluates the expression; no backtracking. This is exactly how many real compilers and calculators evaluate arithmetic internally.

Expression evaluation

Evaluate 2 4 8 + − 8 + .

4+8=12; 2−12=−10; −10+8. Answer: −2 — note the subtraction order: the second pop is the left operand.

Why must the two popped operands be applied in the correct order for − and / but not for + and *?

Addition and multiplication are commutative (a+b = b+a, a×b = b×a), so a swapped pop order changes nothing. Subtraction and division are not commutative — 6−5 = 1 but 5−6 = −1 — so the first pop must be treated as the right operand and the second pop as the left, computing op1 ∘ op2.

State the prefix evaluation algorithm and evaluate * + 3 4 5 .

Scan right to left; operand → push; operator → a = pop, b = pop, push(a OP b) — the first pop is the left operand. For * + 3 4 5: push 5, 4, 3; +: a=3, b=4 → 7; *: a=7, b=5 → 35.

Recursion & the run-time stack

What does an activation record contain, and when is it pushed?

Pushed on the run-time stack at every active procedure call (whether or not the language allows recursion), it holds the parameter values, the local variables of that call, and the return address to jump back to — everything needed to resume the caller.

Explain stack overflow and how to prevent it.

Each activation record takes real memory and the run-time stack has a fixed limit. Recursion with no reachable base case keeps pushing frames until the stack’s memory region is exhausted — a crash. Prevention: ensure the base case is reachable from every call; ensure each call moves strictly closer to it; for very deep recursion, use the iterative / explicit-stack version (complete recursion elimination).

Compare recursion and iteration.

Recursion: O(depth) stack frames, often shorter code mirroring the definition, risk of stack overflow, call/return overhead per level. Iteration: O(1) extra memory, may need extra bookkeeping, no call-stack growth, usually faster in tight loops. (Table in § 13.)

Queues & circular queues

Explain why a plain array-based queue eventually reports “full” even when it holds few elements.

False overflow. Each dequeue advances front and leaves its slot behind — the vacated slots are never reused by the linear scheme. After many enqueue/dequeue pairs the whole queue drifts rightward; once rear reaches MAX−1, isFull() fires even though slots 0..front−1 are empty and unreachable. The fix is the circular queue: advance both indices modulo size so rear wraps back onto the freed slots.

In a size-6 circular queue, rear = 5. What is rear after one more enqueue?

rear = (5 + 1) % 6 = 0

The index wraps from the last slot back to the first — the whole point of modulo arithmetic.

Why can’t front == rear alone tell you whether a circular queue is empty or full?

The pointers record position, not occupancy. With the “rear = next free slot” convention, an empty queue starts with front == rear, and a completely full one wraps rear back onto front — identical pointer values, opposite states. Disambiguation needs occupancy information: a count variable, an empty flag, or a sacrificed slot.

For a circular queue of size 5 with front = 3 and rear = 4 — is the queue full or empty? What extra information would you need to be sure?

Neither. Under the usual “rear = last element” convention it holds the elements at indices 3 and 4 — exactly 2 elements: not empty (count > 0) and not full (count < 5). But front and rear alone never distinguish the empty from the full coincidence, and the exact count depends on the convention (rear-as-last vs rear-as-next-free). To be certain in every state you need a count variable (or a boolean empty flag, or the sacrifice-a-slot scheme) — always state the convention you assume.

Trace new CircularQueue(4), enqueue(A), enqueue(B), enqueue(C), dequeue(), enqueue(D), enqueue(E).

(front, rear, count) after each: (0,−1,0) → (0,0,1) A → (0,1,2) A,B → (0,2,3) A,B,C → (1,2,2) B,C → (1,3,3) B,C,D → (1,0,4) B,C,D,E — rear wrapped from 3 to 0, reusing A’s old slot. Full table in § 17.

Why is the head of a linked queue the front?

Because it is harder to remove items from the tail of a singly linked list — deletion at the tail requires walking to the predecessor, O(n). With a head pointer, deletion at the head is O(1); with a tail pointer, insertion at the tail is O(1) — so head = front (dequeue) and tail = rear (enqueue), both O(1).

Priority queues & deques

Give one example each of a real system that behaves like a stack, a queue, and a priority queue.

Stack: the browser back button / undo in an editor. Queue: a print spooler / checkout line at a shop. Priority queue: an emergency-room triage (most critical patient first) / an OS scheduler running the highest-priority job next.

Differentiate ascending and descending priority queues.

Both insert arbitrarily. Ascending: only the smallest priority-value element can be removed (min-priority, DELETEMIN). Descending: only the largest priority-value element can be removed (max-priority). Emergency room → ascending; task scheduler → descending.

Compare the three priority-queue implementations.

Unsorted list: INSERT O(1), DELETEMIN O(n) (full scan). Sorted list: INSERT O(n) (find position), DELETEMIN O(1) (extreme is at the end). Heap: both O(log n) — the balanced choice, and what std::priority_queue uses.

Distinguish input-restricted and output-restricted deques.

Input-restricted: insertion allowed at one end only, deletion at both ends. Output-restricted: insertion at both ends, deletion at one end only. The full deque allows both operations at both ends.
