Foundation

Sorting — Core Concepts You Must Know First

Definition · Sorting

Sorting refers to arranging data elements in some given order — ascending or descending. Sorting algorithms arrange elements in a data structure in a specific order to optimise search efficiency and data readability.

0.2Essential Vocabulary (definitions examiners love)

  • Sort order — the target arrangement: ascending (non-decreasing) or descending (non-increasing).
  • Pass — one complete sweep over the data. The phases in which elements move toward their proper positions are called passes. Ex: 10,30,20,50,40 → Pass 1: 10,20,30,50,40 → Pass 2: 10,20,30,40,50
  • In-place sort — the amount of extra space required is constant with input size, i.e. O(1) auxiliary space. Bubble, Selection, Insertion and Heap sort are in-place.
  • Adaptive sort — running time depends on the existing order of the input (nearly-sorted input runs faster). Insertion sort is adaptive; selection sort is not.

Stability — the most-tested concept

Definition · Stability

A sort is STABLE if it preserves the relative order of records with equal keys. Equal elements that appeared in a certain order in the input appear in that same order in the output. An unstable sort may or may not keep equal elements in their original order.

Why it matters: sorting students by test score — two students with equal scores should stay in their original (e.g. roll-number) order. Stability is usually unimportant for plain integers, but critical when sorting records by one field among several.

Fig 0.2 — Stability: equal keys never “cross” each other

Efficiency & measuring sorting algorithms

  • Efficiency is expressed as time complexity using Big-Oh notation — how the running time grows with input size n (number of records).
  • Sorting techniques commonly have O(n²) or O(n log n) complexity.
  • Bubble, insertion, selection → O(n²)  ·  Merge & quick sort → O(n log n) (average).
  • Space complexity matters too: how much extra memory the algorithm needs.

Classification of sorting algorithms

1 · Simple / Comparison-Based

Bubble, Selection, Insertion, Merge, Quick, Heap sort — order is determined by comparing pairs of elements.

2 · Non-Comparison-Based

Counting, Radix, Bucket sort — use mathematical properties of keys (digits, ranges, distribution) instead of comparisons → can achieve linear time under conditions.

Real-life applications of sorting (frequent 2-mark question)

  • E-commerce: Amazon/Flipkart filters — “Price: Low to High”, ratings, newest arrivals; warehouse inventory sorted by SKU / expiry date.
  • Search & media: Google ranks billions of pages by relevance in milliseconds; Netflix sorts recommendation rows by preference scores; Instagram/X feeds sort by relevance.
  • Everyday utilities: contact lists (alphabetical), file explorers (name/size/date), photo galleries (chronological), spreadsheets (Excel’s sort button).
  • Systems: databases use merge sort to maintain primary indexes; routers sort packets by priority; computational biology sorts genomic datasets for pattern matching.
Part B · Block 1

1 · Array Fundamentals

Definition · Array

An array is a fixed-size, ordered collection of elements of the same type, stored in contiguous memory locations — this contiguity is what makes constant-time access possible. Because every element has the same size, the address of any element can be computed directly from its index, without walking through the array.

1.11D Arrays: Memory Representation & Addressing

Fig 1.1 — Contiguous storage of int A[6] = {12,45,7,89,23,56}
Address(A[i]) = Base + i × size
Base = address of A[0] · size = bytes per element · i = index

This single formula is why array access is O(1) — one multiplication and one addition, regardless of array size or index position.

Worked example
// int array, base = 1000, size = 4 bytes
int A[6] = {12,45,7,89,23,56};

// Address of A[3]:
//   1000 + 3*4 = 1012
cout << A[3];  // prints 89

Key Insight

Insertion/deletion cost comes from shifting, not from the operation itself. Inserting 99 at index 2 requires first shifting every subsequent element one slot right. Deletion leaves a gap that must be closed by shifting left. End-of-array insertion avoids shifting entirely.

1.22D Arrays: Concept, Row-Major & Column-Major

A 2D array models a table or grid — declared as a matrix of rows and columns, e.g. int M[3][4]. Physically, memory is still one contiguous 1D block — the “rows and columns” view is a mapping the compiler applies on top of flat memory.

1.3Sparse Matrices

A sparse matrix has far more zero entries than non-zero ones — common in scientific computing, graphs, and large lookup tables. Dense storage wastes memory: an r×c matrix always costs O(r×c) space even if only a handful of entries are non-zero.

Fig 1.3 — 4×4 sparse matrix (5 non-zeros) stored as triplets; a header records (rows, cols, count)

Linked-list representation

“When to prefer triplet over dense?” — When non-zero count k ≪ r×c (e.g. a 1000×1000 matrix with 50 non-zeros costs 50 triplets vs 1,000,000 dense cells). Trade-off: random access degrades from O(1) to O(k), since finding M[i][j] requires scanning the triplet list.

1.5Dynamic Arrays & Amortised Growth

A static array’s size is fixed at declaration — too small and it overflows, too large and memory is wasted. A dynamic array grows on demand: when full, it allocates a bigger block and copies elements over, giving the illusion of unlimited size.

Fig 1.4 — Resizing by doubling
// C++ std::vector IS a production dynamic array
#include <vector>
std::vector<int> v;
v.reserve(1000);  // pre-allocate, avoid repeated resizes
for (int i = 0; i < 1000; i++) v.push_back(i);

Key point: push_back, size(), and [] behave exactly as described. Calling reserve(n) up front avoids repeated resizing when the final size is known ahead of time.

2 · Searching Techniques

Searching algorithms are designed to find the location of a specific target element within a collection. The choice of technique depends heavily on how the data is organised and the performance requirements of your application.

Classification of searching methods

Linear / Sequential Search

Checks every element from start to finish until a match is found. Works on ordered and unordered collections. Time: O(n).

Interval / Divide-and-Conquer Search

Exploits ordering to eliminate portions of the search space — binary, ternary, interpolation, exponential, jump, and Fibonacci search.

2.1Linear (Sequential) Search

Idea

Check each element in order, from the first to the last, until the target is found or the array is exhausted. Makes no assumption about ordering — works on any array, sorted or not.

When to use: unsorted data, small arrays, or a one-off search where sorting first wouldn’t pay off. Space O(1). Simplicity is the trade-off for O(n) time — binary search is faster once data is sorted.

2.2Binary Search

Idea & Precondition

Requires a sorted array. Compare the target to the middle element; discard the half that cannot contain it, and repeat on the remaining half. Each comparison eliminates roughly half of the remaining search space.

Fig 2.1 — Binary search halving the search space
Iterative version — note the overflow-safe midpoint
int binarySearch(int a[], int n, int key) {
    int lo = 0, hi = n - 1;
    while (lo <= hi) {
        int mid = lo + (hi - lo) / 2;  // avoids overflow vs (lo+hi)/2
        if (a[mid] == key) return mid;
        else if (a[mid] < key) lo = mid + 1;
        else hi = mid - 1;
    }
    return -1;
}
Recursive version
int binarySearch(int a[], int lo, int hi, int key) {
    if (lo > hi) return -1;              // base: empty range
    int mid = lo + (hi - lo) / 2;
    if (a[mid] == key) return mid;
    if (a[mid] < key)
        return binarySearch(a, mid+1, hi, key);
    return binarySearch(a, lo, mid-1, key);
}

Search 23 in [2,5,8,12,16,23,38,45]: lo=0, hi=7, mid=3 → a[3]=12 < 23 → go right · lo=4, hi=7, mid=5 → a[5]=23 = 23 → found! Only 2 comparisons for 8 elements.

“Why does binary search require sorted input?” — The algorithm’s correctness depends on the invariant that everything left of mid is ≤ a[mid] and everything right is ≥ a[mid]. On unsorted data, discarding a half may discard the target — the algorithm can report “not found” for a value that is actually present.

3 · Bubble Sort

Idea

Repeatedly step through the array, comparing adjacent elements and swapping them if they are out of order. Each full pass “bubbles” the largest remaining element to its correct position at the end. Smaller values bubble up to the top; larger values sink to the bottom. After k passes, the largest k elements occupy the last k positions.

Standard C++ implementation
void bubbleSort(int a[], int n) {
    for (int i = 0; i < n-1; i++) {          // passes
        for (int j = 0; j < n-i-1; j++) {  // inner loop SHRINKS — tail sorted
            if (a[j] > a[j+1]) {
                int t = a[j]; a[j] = a[j+1]; a[j+1] = t;
            }
        }
    }
}
Early-exit optimisation — the optimised version you should write in exams
void bubbleSort(int a[], int n) {
    for (int i = 0; i < n-1; i++) {
        bool swapped = false;
        for (int j = 0; j < n-i-1; j++) {
            if (a[j] > a[j+1]) {
                swap(a[j], a[j+1]);
                swapped = true;
            }
        }
        if (!swapped) break;  // full pass, zero swaps → already sorted
    }
}

Advantages

  • O(n²) — very slow for large datasets
  • Almost no real-world applications; mostly academic

4 · Selection Sort

Idea

Divide the array into sorted and unsorted parts. Repeatedly select the smallest element from the unsorted portion and swap it with the first unsorted element. The sorted region grows by exactly one element per pass.

Live Visualisation · Selection Sort
SPEED
Press RUN to watch selection sort execute.

The procedure, step by step (array of length n)

  1. Search elements 0 through n−1 and select the smallest → swap with location 0
  2. Search elements 1 through n−1 → swap with location 1
  3. Search elements 2 through n−1 → swap with location 2 … continue until nothing remains to search

Worked example — [64, 25, 12, 22, 11]

PASS 1
Unsorted [64,25,12,22,11] → min 11 → swap with 64 → [11, 25, 12, 22, 64]
PASS 2
Unsorted [25,12,22,64] → min 12 → swap with 25 → [11, 12, 25, 22, 64]
PASS 3
Unsorted [25,22,64] → min 22 → swap with 25 → [11, 12, 22, 25, 64]
PASS 4
Unsorted [25,64] → min 25 already in place → no swap → [11, 12, 22, 25, 64] ✓

Classic exam example — [89, 45, 68, 90, 29, 34, 17]

Fig 4.1 — The sorted region grows one element per pass; each line is one pass
C++ implementation
void selectionSort(int a[], int n) {
    for (int i = 0; i < n-1; i++) {
        int minIdx = i;
        for (int j = i+1; j < n; j++)   // scan — NO swapping inside
            if (a[j] < a[minIdx])
                minIdx = j;               // only track the minimum's index
        int t = a[i]; a[i] = a[minIdx]; a[minIdx] = t;  // ONE swap
    }
}

Complexity derivation — with the formal analysis from the slides

for i ← 0 to N-2 {
    min ← i;
    for j ← i+1 to N-1 {
        if (A[j] < A[min]) min ← j;      // cost c per comparison
    }
    swap A[i] and A[min];
}

Selection vs Bubble — Swap Count (guaranteed question)

Bubble sort performs up to O(n²) swaps (one potential swap per comparison). Selection sort performs at most n−1 swaps — exactly one per outer pass. Both are O(n²) comparisons, but selection sort is preferable when writes/swaps are expensive (flash memory, large structs/records). Only cycle sort beats selection sort in memory writes.

Properties

  • Not stable ✗ — a long-distance swap can jump an equal element past another (e.g. [3a, 3b, 1] → after one pass [1, 3b, 3a]).
  • In-place ✓ — O(1) auxiliary space.
  • Not adaptive ✗ — comparisons are identical for every input ordering.
  • Heap sort is based on selection sort — it selects the maximum via a heap instead of a linear scan, dropping selection cost to O(log n).
Advantages
  • Easy to understand and implement — ideal for teaching
  • O(1) extra memory
  • Fewest memory writes of standard sorts — good when writes are costly
Disadvantages & Applications
  • O(n²) — slower than quick/merge sort
  • Not stable
  • Use: small lists, minimal-write scenarios, foundation of heap sort

5 · Insertion Sort

Idea — the card-player’s algorithm

Based on the technique used by card players to arrange a hand of cards. The player keeps the cards picked up so far in sorted order; when a new card arrives, he makes room for it and inserts it in its proper place. Formally: build the sorted portion one element at a time — take the next unsorted element (the key) and shift larger elements rightward until its correct slot appears, then insert.

Algorithm outline

Start from the second element (the first is trivially sorted). For each element from index 1 to n−1: pick it as key, compare with sorted predecessors, shift each larger one right, and drop key into the gap.

Worked example — [5, 3, 8, 4, 2]

START
[5] | [3, 8, 4, 2] — first element assumed sorted
PASS 1
Insert 3: 5 > 3 → shift 5 right → insert at front → [3, 5] | [8, 4, 2]
PASS 2
Insert 8: 5 < 8 → no shift needed → [3, 5, 8] | [4, 2]
PASS 3
Insert 4: shift 8, shift 5, stop at 3 → insert after 3 → [3, 4, 5, 8] | [2]
PASS 4
Insert 2: 8, 5, 4, 3 all larger → shift all → insert at beginning → [2, 3, 4, 5, 8] ✓

C++ implementation — standard exam version
void insertionSort(int a[], int n) {
    for (int i = 1; i < n; i++) {       // passes: 1 to n-1
        int key = a[i];              // current element to insert
        int j = i - 1;
        while (j >= 0 && a[j] > key) { // check previous (sorted) elements
            a[j+1] = a[j];            // shift greater elements RIGHT
            j--;
        }
        a[j+1] = key;               // insert key into the gap
    }
}
Alternate course version (shift-and-place inside loop)
void insertsort(int a[20], int n) {
    int i, k, y;
    for (k = 1; k < n; k++) {              // passes
        y = a[k];                          // current element
        for (i = k-1; i >= 0 && y < a[i]; i--) {  // scan back
            a[i+1] = a[i];                  // shift greater right
        }
        a[i+1] = y;                        // place y in its slot
    }
}

Shift vs Swap — Subtle Exam Point

A shift in insertion sort moves only one item, whereas an exchange in bubble/selection sort uses a temporary and moves three items. The number of shifts during an insertion is one less than the number of comparisons — or equal to it when the new value is the smallest so far.

Why insertion sort survives in practice

  • Adaptive: number of inversions is directly proportional to work — a sorted array costs O(n). Contrast with selection sort’s input-independent O(n²).
  • Stable ✓, in-place ✓ (O(1) space), simple to implement.
  • Best choice for small lists and nearly-sorted data.
  • Used as a subroutine in Bucket Sort and in hybrid algorithms — when the subarray becomes small inside Quick/Merge sort, they switch to insertion sort. IntroSort and TimSort both use it.
Part D · Block 3 — Strategy

6 · Divide-and-Conquer: The Strategy

Definition

Divide and Conquer is a method of algorithm design with three distinct steps:

1 · Divide — if the input size is too large to deal with directly, divide the data into two or more disjoint subsets.
2 · Recurse — use divide and conquer to solve the subproblems associated with the subsets.
3 · Conquer — take the solutions to the subproblems and “merge” them into a solution for the original problem.

Fig 6.1 — The three steps of divide and conquer

Divide-and-conquer applied to sorting

StepMerge SortQuick Sort
DivideSplit at midpoint — trivial (just find the middle)Partition around a pivot — the hard work
RecurseSort both halves recursivelySort both partitions recursively
ConquerMerge the sorted halves — the hard workNothing — once both sides are sorted, the whole is sorted
Table 6.1 — The mirrored structure of merge sort vs quick sort (very examinable)

The base case: a problem of size 1 (a single element) is already solved — return directly. Merge sort and quick sort differ in where the hard work happens: merge sort does trivial division and expensive combination; quick sort does expensive division and free combination.

7 · Merge Sort

Idea

Divide the array into two halves, recursively sort each half, then merge the two sorted halves back together. The hard work happens in the merge step — the divide step is trivial (just split at the middle). The algorithm continuously splits until it cannot divide any further, then sorts and merges the pieces back together.

Three-phase description (as in the course)

  1. Divide: find the midpoint mid = (low + high) / 2 and split into two halves.
  2. Conquer: recursively call merge sort on both left and right subarrays.
  3. Combine: merge the two sorted halves into a single sorted array.

Alternate 3-way formulation (from the D&C slides): remove all elements and divide them into sequences L (less than pivot-free split — first ⌈n/2⌉ elements), E, and G… in the list version: L holds elements < x, E holds equal, G holds greater; recursively sort L and G; concatenate L, E, G.

Textbook program (Horowitz-style) — merging two sorted lists
template <class T>
void Merge(T *initList, T *mergedList, const int l, const int m, const int n)
{
    // initList[l:m] and initList[m+1:n] are sorted lists.
    // They are merged to obtain the sorted list mergedList[l:n].
    for (int i1 = l, iResult = l, i2 = m + 1;
         i1 <= m && i2 <= n;              // while neither input list is exhausted
         iResult++)
    {
        if (initList[i1] <= initList[i2]) {
            mergedList[iResult] = initList[i1];
            i1++;
        }
        else {
            mergedList[iResult] = initList[i2];
            i2++;
        }
    }
    // copy remaining records, if any, of first list
    copy(initList + i1, initList + m + 1, mergedList + iResult);
    // copy remaining records, if any, of second list
    copy(initList + i2, initList + n + 1, mergedList + iResult);
}

Program 7.7 — note the ≤ comparison: taking from the left list on ties is exactly what makes merge sort stable.

Merge routine — modern C++ course version
void merge(int a[], int l, int m, int r)
{
    vector<int> L(a+l, a+m+1);   // copies of the sorted halves —
    vector<int> R(a+m+1, a+r+1); // this is the O(n) auxiliary space
    int i = 0, j = 0, k = l;
    while (i < L.size() && j < R.size())
        a[k++] = (L[i] <= R[j]) ? L[i++] : R[j++];
    while (i < L.size()) a[k++] = L[i++];  // flush leftover tails
    while (j < R.size()) a[k++] = R[j++];
}
Recursive driver
void mergeSort(int a[], int l, int r)
{
    if (l >= r) return;          // base case: length ≤ 1 is sorted
    int m = l + (r - l) / 2;
    mergeSort(a, l, m);           // sort left half
    mergeSort(a, m+1, r);        // sort right half
    merge(a, l, m, r);            // combine
}

Part D · Block 3 — Divide & Conquer

8 · Quick Sort

Idea

Quick sort is a highly efficient, divide-and-conquer, in-place sorting algorithm that selects a pivot element and partitions the array so that smaller elements move before the pivot and larger elements after it. All elements less than the pivot go left; all greater-or-equal go right; the pivot lands in its final sorted position. Recursion then handles each side independently.

Core steps

  1. Select pivot: pick an element (first, last, random, or median).
  2. Partition: rearrange elements around the pivot point.
  3. Recurse: repeat independently for the left and right sub-arrays.

Two views of the divide step

Sequence view (3-way)

Divide S into three sequences: L (elements < x), E (elements = x), G (elements > x). Recursively sort L and G. Conquer: concatenate L, then E, then G back into S.

In-place view (2-pointer)

Pointer l scans from the left, r from the right. A swap is performed when l is at an element larger than the pivot and r is at one smaller. A final swap with the pivot completes the divide step.

Textbook program (Horowitz-style) — pivot = a[left], Hoare partition
template <class T>
void QuickSort(T *a, const int left, const int right)
{
    // Sort a[left:right] into nondecreasing order.
    // a[left] is arbitrarily chosen as the pivot. i and j partition
    // the subarray so that a[m] <= pivot for m < i, and a[m] >= pivot
    // for m > j. Assumes a[left] <= a[right+1].
    if (left < right) {
        int i = left,  j = right + 1,  pivot = a[left];
        do {
            do i++; while (a[i] < pivot);   // scan right past small
            do j--; while (a[j] > pivot);   // scan left past large
            if (i < j) swap(a[i], a[j]);
        } while (i < j);
        swap(a[left], a[j]);             // pivot into final position
        QuickSort(a, left, j-1);        // sort left part
        QuickSort(a, j+1, right);       // sort right part
    }
}

Program 7.6 — the do-while loops guarantee both scans stop at the pivot sentinel, so i and j always stay in bounds.

Choose the last element as pivot. Walk through the array keeping index i as the boundary of “elements smaller than pivot”. Whenever a[j] < pivot, swap it into position i+1 and advance i. Finally swap the pivot into position i+1 — its correct sorted position.

partition() — Lomuto scheme
int partition(int a[], int lo, int hi) {
    int pivot = a[hi];        // last element as pivot
    int i = lo - 1;           // boundary of "smaller than pivot" region
    for (int j = lo; j < hi; j++) {
        if (a[j] < pivot) {
            i++;
            swap(a[i], a[j]);
        }
    }
    swap(a[i+1], a[hi]);   // pivot → its correct final position
    return i + 1;             // pivot's final index
}
quickSort() — partition first, THEN recurse
void quickSort(int a[], int lo, int hi) {
    if (lo < hi) {                 // base case: 0/1 elements
        int p = partition(a, lo, hi); // pivot placed at index p
        quickSort(a, lo, p - 1);     // sort left sub-array
        quickSort(a, p + 1, hi);    // sort right sub-array
    }
}

The Canonical Exam Question

“Why is quick sort’s worst case O(n²) despite O(n log n) average?” — The worst case is triggered by consistently unbalanced partitions: when the pivot is always the smallest or largest element, each partition produces subproblems of size 0 and n−1, so the sequence length reduces by only 1 per step. The recursion depth becomes n, and total work = n + (n−1) + … + 1 = n(n+1)/2 ∈ O(n²). Trigger input: an already-sorted (or reverse-sorted) array with a last-element (or first-element) pivot. Mitigation: randomized or median-of-three pivot selection makes this vanishingly unlikely — which is why quicksort remains a top practical choice.

Running-time intuition (from the D&C slides)

  • Worst case: the pivot does not divide the sequence in two; at each step the length reduces only by 1 → O(n²).
  • General case: time spent at level i of the quick-sort tree is O(n); running time = O(n) × O(height).
  • Average case: O(n log n).
  • Space: O(log n) — recursion stack for the balanced case (in-place partitioning, no auxiliary arrays).
  • Stability: ✗ not stable — long-range swaps during partitioning can reorder equal keys.
Strengths
  • Fastest average-case in practice — a staple of library sorts
  • In-place: O(log n) stack only
  • Cache-friendly, small hidden constants
Weaknesses
  • O(n²) worst case on bad pivots
  • Not stable
  • Recursive — deep stacks on degenerate inputs

10.1Case Study 1 — Buffering Streaming Sensor Data

Problem Context

In IoT devices, embedded systems, and automotive safety modules (ABS, airbag controllers), sensors continuously sample temperature, pressure, acceleration. The core challenge is a speed mismatch: the Producer (sensor hardware, e.g. readings every 2 ms) is far faster than the Consumer (processor writing to flash or transmitting over Wi-Fi/cellular in batches, due to power and latency overheads). Directly processing every reading risks data loss when the CPU is busy — so engineers use array-based buffers.

Two buffering architectures

Option A · Linear Array Buffer

A standard contiguous block float sensor_buffer[SIZE]. Readings appended from index 0 to SIZE−1; when full, collection stops or triggers a processing flush, then resets index to 0. Static batching.

Option B · Circular (Ring) Buffer ★

For continuous non-stop monitoring, wraps around using modulo arithmetic. Two indices — head (where new data is written) and tail (where data is read). Key benefit: eliminates element shifting entirely — new readings automatically overwrite the oldest ones.

10.2Case Study 2 — Pattern Matching in Intrusion Detection

Network intrusion detection systems (IDS) scan packet payloads and log lines for known attack signatures — fixed byte/character sequences associated with malicious traffic. This is fundamentally a string (character-array) search problem, repeated over a continuous stream. Both the log data and the signature are naturally stored as character arrays; detection must run in real time at network line-rate, so per-byte cost determines whether the system keeps up.

Naive pattern-matching sketch
bool containsSignature(string text, string sig) {
    int n = text.size(), m = sig.size();
    for (int i = 0; i <= n - m; i++) {   // slide signature across text
        int j = 0;
        while (j < m && text[i+j] == sig[j])  // compare char-by-char
            j++;
        if (j == m) return true;   // full match found!
    }
    return false;
}
EXAMPLE
Text "...DROPTABLE..", signature "DROP" — i=0..2: mismatch immediately, slide forward · i=3: D,R,O,P all match → signature found at index 3 → flag this log line for review.
LIMITATION
Naive matcher is O(n×m) worst case — a bottleneck at line-rate with many signatures per packet. It re-examines overlapping characters on every failed attempt.
PRODUCTION
Snort & Suricata use Boyer–Moore or Knuth–Morris–Pratt (KMP), which skip ahead using information from earlier comparisons instead of re-scanning. The data structure is still the same character array — only the search strategy changes.

10.3Case Study 3 — Anomaly Detection in Large-Scale Logs

Server/application logs are naturally stored as arrays of records (timestamp, metric value) — e.g. request latency sampled every second, millions of entries per day. Anomaly analysis finds values that deviate sharply from the norm — a latency spike or error-count surge. Arrays fit because logs are time-ordered (ideal for sequential storage and windowed access), sorting by metric enables percentile/threshold queries via binary search, and batch analysis maps onto array slicing.

Sliding-window anomaly detection — flag points > k std-devs from the window mean
for (int i = W; i < n; i++) {            // W = window size, k = sensitivity
    float mean = average(a, i-W, i);
    float sd   = stddev(a, i-W, i, mean);
    if (abs(a[i] - mean) > k * sd)
        flagAnomaly(i);
}
// Each step is O(W) over an array slice — O(n×W) total for the full log

SPIKE
Next reading: 810 → |810 − 120.6| = 689.4 ≫ 3 × 2.4 → flagged as anomaly
SCALE

QUESTION 01 · ADDRESS CALCULATION
Derive the address of A[i][j] in a 5×8 row-major array with base 2000, element size 4.
REVEAL ANSWER

Row-major formula: Addr(A[i][j]) = Base + (i × cols + j) × size, with cols = 8, size = 4:

Addr(A[i][j]) = 2000 + (8i + j) × 4 = 2000 + 32i + 4j

Check: A[2][3] = 2000 + (2×8 + 3)×4 = 2000 + 76 = 2076. Access remains O(1) — one arithmetic computation, no traversal.

QUESTION 02 · QUICK SORT WORST CASE
Why is quick sort’s worst case O(n²) despite O(n log n) average case? Give an input that triggers it with a last-element pivot.
REVEAL ANSWER

With a poor pivot, partitions are size 0 and n−1: the sequence shrinks by only one element per step. Total work = n + (n−1) + … + 1 = n(n+1)/2 ∈ O(n²), and recursion depth becomes n.

Trigger input: an already-sorted array (or reverse-sorted) with the last element as pivot — the pivot is then always the maximum (or minimum), producing the maximally unbalanced split. Mitigation: random or median-of-three pivot selection.

QUESTION 03 · INSERTION SORT TRACE
Trace insertion sort on [9, 5, 1, 4, 3] and count the shifts performed.
REVEAL ANSWER

Insert 5: shift 9 → [5, 9, 1, 4, 3] — 1 shift
Insert 1: shift 9, 5 → [1, 5, 9, 4, 3] — 2 shifts
Insert 4: shift 9, 5 → [1, 4, 5, 9, 3] — 2 shifts
Insert 3: shift 9, 5, 4 → [1, 3, 4, 5, 9] — 3 shifts

Total: 8 shifts (= number of inversions in the input — insertion sort’s work is proportional to inversions, which is exactly why it is adaptive).

QUESTION 04 · STABILITY ANALYSIS
Is bubble sort stable? Justify from the swap condition.
REVEAL ANSWER

Yes. The swap condition is strict inequality: if (a[j] > a[j+1]). When two adjacent elements are equal, the condition is false and no swap occurs — so equal elements never cross each other, and their original relative order is preserved in the output. That is precisely the definition of stability.

QUESTION 05 · SPARSE MATRICES
When would you prefer a triplet sparse-matrix representation over a dense 2D array?
REVEAL ANSWER

When the non-zero count k ≪ r×c. Dense storage always costs O(r×c) space even if almost all entries are zero; triplets cost only O(3k) (plus a header of rows/cols/count). Example: a 1000×1000 matrix with 50 non-zeros needs 50 triplets versus 1,000,000 dense cells. Trade-off: random access to M[i][j] degrades from O(1) to O(k), since the triplet list must be scanned. Prefer a linked representation when the matrix changes dynamically.

QUESTION 06 · BINARY SEARCH PRECONDITION
Why does binary search require sorted input, and what happens if you run it on unsorted data?
REVEAL ANSWER

Correctness rests on the invariant: everything left of mid is ≤ a[mid], everything right is ≥ a[mid]. On unsorted data, discarding a half may discard the target — the algorithm can report “not found” (−1) for a value that is actually present, or return a wrong index. The result is unreliable, not merely slow.

QUESTION 07 · SYNTHESIS
Compare bubble and selection sort on swap count, and state when each is preferred.
REVEAL ANSWER

Both do exactly n(n−1)/2 comparisons, but bubble sort can perform up to O(n²) swaps (one per comparison) while selection sort does at most n−1 swaps — exactly one per outer pass. Selection sort is preferred when writes are expensive (flash memory, large records); only cycle sort beats it on memory writes. Bubble sort’s advantages: stable (selection is not) and adaptive with the early-exit flag — best case O(n) on sorted input, where selection is still O(n²).

QUESTION 08 · DESIGN
Which sort would you choose for: (a) a nearly-sorted 30-element array, (b) a 10-million-record file requiring a stable sort, (c) an in-memory general-purpose sort where average speed matters most?
REVEAL ANSWER

(a) Insertion sort — adaptive, near O(n) on almost-sorted data, ideal for small arrays.
(b) Merge sort — stable with guaranteed O(n log n); the standard choice for external sorting of massive files and database index maintenance.
(c) Quick sort — fastest average case in practice, in-place with O(log n) stack; use random or median-of-three pivots to avoid the O(n²) trap.

QUESTION 09 · CASE STUDY
In a sensor ring buffer, what is the difference between the overflow handling strategies for streaming video versus flight telemetry?
REVEAL ANSWER

Streaming (video/audio): overwrite strategy — newest data matters most; when the buffer fills, new readings replace the oldest ones automatically via modulo wrap-around.
Flight telemetry (critical data): blocking strategy — no reading may be lost; when full, the system pauses sensor acquisition or drops the incoming packet, and signals the condition. Underflow (reading an empty buffer) is handled by returning a status flag (false/NULL) to prevent reading junk memory.

QUESTION 10 · DERIVATION
Derive the time complexity of merge sort using the recursion-tree method.
REVEAL ANSWER

Recurrence: T(n) = 2T(n/2) + O(n). The recursion tree halves n at each level: level 0 has one problem of size n, level 1 has two of size n/2 (total n), level 2 has four of size n/4 (total n) … the leaf level has n/2 problems of size 2 (total n). So every level does O(n) total merging work. The tree has log₂n levels (n halves to 1 in log₂n steps). Total: O(n) × O(log n) = O(n log n) — identical for best, average, and worst case because the split is always exactly at the midpoint, regardless of input order.
