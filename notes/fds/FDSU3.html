§ 01

Foundations

Arrays, pointers, and the case for linked lists

1.1Linear data structures & sequential organization

A linear data structure arranges data in a list or straight sequence — the adjacency relation between elements is strictly one-to-one. The two canonical examples are the array and the linked list.

Sequential organization means data is stored in sequential form, in consecutive memory locations (an array). Two basic operations are performed on data stored this way:

  1. Storing data at a desired location.
  2. Retrieving data from a desired location.

For a one-dimensional array int a[10], the compiler locates any element by pure index arithmetic:

addr(a[i])  =  base(a)  +  i × sizeof(element)

That single formula is why array access is O(1) random access — no searching, no walking, just one multiplication and one addition.

1.2Recap: arrays & their drawbacks

  • Elements stored in contiguous memory, indexed 0 … n−1.
  • Random access by index is O(1) — very fast.
  • Size is fixed at creation in most languages.
  • Inserting or deleting in the middle requires shifting elements — O(n) in the worst case.
Array drawbacks — the exam list
  1. Very difficult to insert or delete a middle element (involves shift operations).
  2. Overall representation is time and space inefficient — resizing means copying everything.
  3. We cannot make an exact judgement of size in advance — over-estimate wastes contiguous memory; under-estimate causes overflow.

1.3Why linked lists exist

vs

Problems with arrays

  • Fixed capacity — resizing means copying everything.
  • Insert/delete in the middle shifts O(n) elements.
  • Unused capacity wastes contiguous memory.

What linked lists fix

  • Grow and shrink one node at a time, on demand.
  • Insert/delete is O(1) once you hold a pointer to the spot.
  • Nodes can live anywhere in memory — no shifting, no reservation.
Definition — Linked list

A linear data structure in which the elements are not stored at contiguous memory locations. The elements are linked using pointers: each node contains a data field and a reference (link) to the next node. Memory allocation to nodes is random, and the structure is dynamic — nodes are allocated or deallocated as per requirement.

1.4The node — the building block

A node bundles a value with a pointer to the next node. A chain of nodes, linked head-to-tail, forms the list; the last node's pointer is NULL. The list itself is tracked by a single pointer, head — everything else is reachable by following next.

1.5Self-referential structures

Definition — Self-referential structure

A struct (or class) that contains one or more members that are pointers or references to another object of the same structure type. These are the fundamental building blocks of dynamic data structures — linked lists, trees, and graphs.

Why can't a struct contain itself directly? Because that would cause an infinite recursive sizing loop at compile time — the struct would contain a copy of itself, which contains a copy of itself, forever. But it can contain a pointer to its own type, because a pointer's size is fixed regardless of the structure's payload.

Why are they used?

  • Dynamic memory allocation — data structures grow or shrink at runtime, unlike fixed arrays.
  • Non-contiguous storage — pointers hold the addresses of subsequent elements, wherever they live.
  • Complex data relationships — stacks, queues, binary search trees, graphs.

1.6Pointers refresher (C++)

  • A pointer variable holds the address of another object.
  • Node* next; — next can point to a Node, or to nothing.
  • new Node(...) allocates on the heap and returns its address.
  • nullptr is the safe "points to nothing" value.
  • p->data and p->next dereference through a pointer p.
  • delete p; frees the heap memory p points to.

1.7Memory layout — contiguous vs. scattered

1.8Where linked lists show up

  • Browser back/forward history — doubly linked
  • Music-player playlists, including "repeat all" — circular
  • Undo/redo stacks in editors
  • Adjacency lists for graphs
  • Free lists inside memory allocators
  • Building block for stacks, queues, and hash-table buckets

Applications — the full taxonomy

  • System architecture & operating systems — memory management (linked list of free/allocated blocks); process scheduling (queues of ready/blocked processes); file-system allocation (FAT links disk blocks into files).
  • Application software — undo/redo (DLL of operations); browser history (DLL of URLs); looping playlists (CLL).
  • Abstract data types — stacks & queues without size limits; graphs (adjacency lists); hash tables (separate chaining).
  • Advanced computation — polynomial manipulation (coefficient + exponent per node); sparse matrices (store only non-zero elements).
Exam tip

A linked list is the right structure when a large number of insertions and deletions is needed on a (possibly sorted) list that grows and shrinks — e.g. student enrolment records each semester. Searching it, however, is slower than searching an array.

§ 02

Memory & Fragmentation

How the heap really works underneath a linked list

2.1Where do variables live? Stack vs. heap

  • STACK — local variables & function calls; fixed size; allocated/freed automatically; very fast; strict LIFO order. e.g. the pointer Node* p; itself.
  • HEAP — objects created with new, alive until delete; programmer controls the lifetime; size decided at run time. e.g. the node new Node{10, nullptr} itself.

Heap memory — core characteristics

Heap memory is a region of RAM for dynamic allocation: unlike the stack's strict LIFO order, blocks may be allocated and deallocated randomly, at runtime, in any order.

  • Dynamic size — the amount of space isn't fixed at compile time; request variable amounts while running.
  • Global access — heap objects are reachable from anywhere, as long as you hold a pointer or reference.
  • Slower access — allocation requires searching free blocks and tracking pointers, so it is slower than stack operations.
  • Deallocation — manual in C/C++ (malloc/new vs free/delete); forgetting causes leaks. Managed languages (Java, Python, JS) use garbage collection to clear unused objects automatically.

Definition — Memory leak

A bug where a program takes memory from the system for temporary use but fails to release it back when no longer needed. The unreleased memory builds up over time, slows the device, and can crash the application.

2.2Dynamic allocation: new & delete

Iron rule

Every new must be matched by exactly one delete. In C++, the programmer — not the language — owns this bookkeeping.

2.3What is memory fragmentation?

As blocks are allocated and freed over time, the heap can end up with wasted space even though total free memory looks sufficient. There are two distinct diseases:

Internal fragmentation — waste inside a block

Allocators often hand out memory in fixed-size chunks (rounded to 8 or 16 bytes) for speed and simple bookkeeping. If a request doesn't exactly fill a chunk, the leftover space inside that block is wasted — it can't be given to anyone else.

External fragmentation — scattered free gaps

Free memory is split into many small gaps between still-allocated blocks. A request for one large block can fail even though the sum of all free space is enough, because no single gap is big enough.

Exam tip — how to tell them apart

Internal = wasted space inside an allocated block. External = free memory between allocated blocks, split into small non-adjacent gaps.

2.4Tracking free space: the free list

The allocator keeps its own linked list threading together every free block, so it can quickly find space for the next request. Each free block stores its own size and a next pointer to the following free block — the list lives inside the very memory it manages.

2.5Dangling pointers & memory leaks

Definition — Dangling pointer

A pointer that still holds the address of memory that has already been freed. Dereferencing it is undefined behaviour.

Definition — Memory leak

Allocated memory that is no longer reachable by any pointer, and therefore can never be freed.

Quick check — after this code runs, what state is q->next in? 
Node* p = new Node{1, nullptr};
Node* q = new Node{2, nullptr};
p->next = q;
q->next = p;
delete p;
Answer

q->next is a dangling pointer — it still holds p's old address, but that block has been freed. q itself is fine; only the field pointing at the freed node is unsafe to use.

2.6Pointer safety practices

  • Set a pointer to nullptr immediately after delete.
  • Never delete the same pointer twice (double free).
  • Never dereference a pointer you haven't checked for nullptr.
  • Keep exactly one "owner" responsible for deleting each node.
  • Prefer tools like valgrind / AddressSanitizer to catch leaks early.
§ 03

Singly Linked Lists

Structure, insert, delete, traverse, and search

3.1Structure

Each node points only forward. To reach node i you must walk through every node before it — there is no going back. A linked list is a series of connected nodes; each contains at least a piece of data (any type) and a pointer to the next node. Head points to the first node; the last node points to NULL. Basic operations: insert, find, delete, print, etc.

3.2Creating a list by hand

The equivalent C program links four named nodes manually: set each node's data, chain the next fields (n1->next = n2; … n4->next = NULL;), set Head = n1;, then walk with temp while temp != NULL, printing each value.

3.3accept() and create() — the C factory pattern

This is the classic exam answer for "write a program to create a linked list": a function that manufactures one node, and a driver loop that keeps attaching nodes at the end.

3.4Traversal — the walking pointer

To traverse, we need a walking pointer — a pointer that moves from node to node as each element is processed:

  1. Start a working pointer curr at head.
  2. While curr is not nullptr: visit/print curr->data, then move forward: curr = curr->next.
  3. The loop ends the instant curr becomes nullptr.

Cost: O(n) — every node is visited once. Note the fine print: a list of n nodes needs n + 1 loop checks — the final check sees curr == nullptr and stops.

3.5Insert at head — O(1)

O(1) — no traversal needed. head is passed by reference (Node*&) so the caller's pointer is updated too.

3.6Insert at tail — O(n)

O(n) with only a head pointer — we must walk to the last node first. Maintain a tail pointer as well, and appending drops to O(1) — this is exactly how a queue is implemented (§ 10.4, P8).

3.7Insert at a position / after a node

Order matters

Link the new node forward first, then splice it in. If you write prev->next = newNode; first, the old value of prev->next is overwritten before it's saved — the rest of the list is lost forever.

Insertion — the four cases (classic exam question)

3.8Deletion

Delete at head — three steps, O(1):

  1. Node* temp = head;  (remember the old head)
  2. head = head->next;  (move head forward)
  3. delete temp;  (free it)

Delete a middle node (given prev): temp = prev->next; then prev->next = temp->next; then delete temp;. Note that deleting the last node and a middle node use the same process — only two cases exist.

Pitfall — condition order in C

The original slide wrote while(a->empid != num && a != NULL). This dereferences a before checking it for NULL — if the key is absent, the loop reads through the end of the list and crashes. Always test a != NULL first, and handle the first-node case before the walk (or b stays NULL).

3.9Search — the pre / cur technique

Since nodes have no names, we search with two pointers: pre (previous) and cur (current). Initially pre = NULL and cur points to the first node. The two pointers move together toward the end of the list; pre trails one node behind so that, on a hit, we already hold the predecessor needed for insertion or deletion.

The last row is the "extreme case" from the lectures: with a target larger than every element, the pair marches off the end — pre settles on the last node, cur becomes NULL.

O(n) worst case — and unlike a sorted array, a linked list (even sorted) has no way to binary-search, because you cannot jump to the middle; there is no random access.

Retrieving a node

Retrieving means randomly accessing a node to inspect or copy its data. The list must first be searched; if the item is found it is retrieved, otherwise the process aborts. Retrieval uses only the cur pointer, which points at the node found by the search.

3.11Advantages & disadvantages

vs

Advantages

  • Dynamic size — no fixed limit like arrays.
  • Efficient insertion & deletion at the beginning (and at the end with a tail pointer); efficient in the middle too, given a pointer to the preceding node.
  • No wastage of memory — nodes exist only while needed.
  • Can implement complex structures: stacks, queues, graphs.

Disadvantages

  • Extra memory for the pointer stored in every node.
  • No direct / random access — reaching element i needs traversal.
  • Cache-unfriendly — nodes are not in contiguous memory.

3.12Other basic operations

Inversion, traced: p holds the already-reversed prefix, q is the node being flipped, r remembers the not-yet-reversed suffix. Each iteration points q backward at p, then all three slide one step. When q falls off the end, p stands on the old tail — the new head. (The slide version omitted return p; and crashed on an empty list — both fixed above.)

Other list operations to know: concatenate two lists (walk to the end of the first, link it to the head of the second), merge two sorted lists (§ 10.4, P7), sort a list, and split a list into two.

    § 04

    Doubly Linked Lists

    Two pointers per node buy backward traversal

    4.1Structure

    Every node keeps a prev pointer as well as next — the list can be walked in either direction, from first to last or from last back to first. The list may also carry two pointer variables: first (points to the first node) and last (points to the last node).

    The C version: struct node { int data; struct node *next; struct node *prev; };

    4.2Doubly vs. singly — the trade

    vs

    Doubly linked gains

    • Traverse forward AND backward.
    • Delete a node in O(1) given only its pointer.
    • A pointer to a node doubles as a "position" you can move either way.

    The cost

    • One extra pointer per node — more memory.
    • Every insert/delete touches more pointer fields.
    • More bookkeeping — easier to introduce bugs.

    Applications of DLL: the browser cache/URL list behind the BACK and FWD buttons; undo functionality in Photoshop or Word (a list of states); stacks, hash tables and binary trees; representing a deck of cards in a game; sparse matrices.

    4.3Insert at head

    4.4Insert at tail

    Walk curr from head to the last node, then link the new node in behind it: curr->next = newNode; newNode->prev = curr; — and newNode->next = nullptr.

    In C (from the lecture): insert_end walks a = a->next while a->next != NULL, then a->next = newnode; newnode->prev = a;. Insertion in between two nodes a and b uses the four-link recipe: a->next = new; new->prev = a; new->next = b; b->prev = new;

    4.5Insert before a given node

    Pitfall — inserting before the head

    If curr is the head, curr->prev is null and this function never updates head — the new node is stranded off the front of the list. Either pass head by reference and set head = n; in that case, or use insertHead instead. This is exactly the kind of edge case exam questions probe.

    4.6Delete a node — the DLL's party trick

    The three deletion cases (C steps from the lecture)

    • First node: temp = first → first = first->next → first->prev = NULL → temp->next = NULL → free(temp).
    • Any middle node (temp): (temp->next)->prev = temp->prev; → (temp->prev)->next = temp->next; → free(temp).
    • Last node (temp, after walking to it): (temp->prev)->next = NULL; → temp->prev = NULL; → free(temp).

    4.7Traverse & search

    Exam tip

    Having a prev pointer does not speed up search in an unsorted list — it's still O(n). Bidirectional links help navigation and deletion, not lookup.

    4.8Singly vs. doubly — complexity & memory

    § 05

    Circular Linked Lists

    No NULL at the end — the last node points back to the first

    5.1Structure

    A linked list in which the last node points back to the head/first node instead of NULL. The circular list has neither a beginning nor an end — there is no end, only a loop. In the circular doubly variant, next of the last node wraps to head and prev of the head wraps to the last node — every node can be reached in either direction, forever.

    5.2Why use a circular list?

    • Natural fit for anything that repeats in a cycle.
    • No special-case NULL check needed when "wrapping around".
    • Any node can act as an entry point — not just a fixed head.
    • Common uses: round-robin scheduling, looping playlists, the Josephus problem.

    Advantage: no fixed header — the entry pointer can be shifted to any node in the list (we must have at least one entry pointer). Disadvantage: care must be taken while processing, or we may get into an infinite loop.

    5.3Creation & insertion

    The modern O(1) alternative avoids the walk by inserting right after the head instead:

    The equivalent C display from the lecture walks with while (temp->next != first), printing each node, then prints the last node's data after the loop — two ways to solve the same "don't loop forever" problem.

    5.4Deletion — the C cases

    • Single node: simply set first = NULL — nothing else exists.
    • Key absent: print a "not found" message (use a flag: search sets flag = 1 on a hit).
    • First node (data 10): with two pointers: first = first->next; → last node's next updated to the new first → temp->next = NULL; free(temp).
    • Middle node (e.g. 20): pointer a on the previous node, temp on the victim: a->next = temp->next; temp->next = NULL; free(temp).
    • Last node: a on the second-last: a->next = first; (re-close the loop!) → temp->next = NULL; free(temp).

    5.5The #1 circular-list bug

    Pitfall — the infinite loop 
    // BUG: this never stops on a circular list!
Node* curr = head;
while (curr != nullptr) {
    // curr is NEVER nullptr here —
    curr = curr->next;      // it just keeps wrapping around
}

    Forgetting that a circular list has no NULL is the classic bug. Always stop on "back to head" (curr != head) — or a counted number of steps — instead.

    5.6Application — round-robin CPU scheduling

    5.7Application — the Josephus problem

    Definition — Josephus problem

    n people stand in a circle, numbered 1 to n. Starting from person 1 and counting clockwise, in each step exactly k−1 people are skipped and the k-th person is eliminated. Counting resumes from the next person, and the process continues until only one person remains. Determine the position of the survivor.

    InputElimination orderSurvivor
    n = 5, k = 22 → 4 → 1 → 53
    n = 7, k = 33 → 6 → 2 → 7 → 5 → 14

    A circular list makes the "wrap around" trivial to code: count k−1 steps of curr = curr->next, unlink the k-th node, repeat until one node remains.

    Examiner's shortcut — the Josephus recurrence

    For a one-line answer in MCQs, compute with 0-indexed positions: J(1) = 0; J(n) = (J(n−1) + k) mod n, then add 1. Check: n=5, k=2 → J = 2 → survivor 3; n=7, k=3 → J = 3 → survivor 4. Both match the tables above.

      § 06

      Application · Polynomials

      Each term becomes one node — coefficient, exponent, and next

      6.1Representing a polynomial

      Why a linked list? Because a polynomial is sparse — 5x³ + 2x + 7 has only three terms, but an array indexed by exponent would need slots for exponents 0…3 (and x¹⁰⁰⁰ + 1 would need a thousand). The linked representation stores only the non-zero terms, in decreasing order of exponent: no prior estimation of the number of nodes, easy insertion and deletion of terms — at the price of no random access.

      6.2Building a polynomial — sorted insert

      Extension — insertTerm that combines like terms (needed for multiplication)

      6.3Adding two polynomials

      Walk A and B together, one term each, like merging two sorted lists:

      1. Same exponent → add the coefficients into one result term; advance both.
      2. A's exponent larger → copy A's term; advance only A.
      3. B's exponent larger → copy B's term; advance only B.

      When one list runs out, append the remainder of the other. Each pointer only ever moves forward, so the whole addition is O(m + n).

      Why the tail pointer here?

      append keeps a tail pointer so each result term costs O(1) — the very optimisation discussed in § 3.6. Without it, building an m+n term result by repeated tail-inserts would be O((m+n)²).

      6.4Multiplying two polynomials

      • Multiply every term of A by every term of B.
      • Term arithmetic: (c₁, e₁) × (c₂, e₂) → (c₁·c₂, e₁+e₂).
      • This produces up to |A| × |B| partial-product terms.
      • Combine terms with equal exponents (add their coefficients) — use the combining insertTerm.

      Complexity: O(m·n) partial products are generated; each insertion into the result costs up to O(result length), giving O(m·n·(m+n)) with this simple scheme — fine for exam answers, and the standard "combine as you insert" improvement is the extension above.

      § 07

      Application · Memory Management

      The allocator itself is built out of a linked list

      7.1The allocator's free list

      The heap is one big pool of memory; the allocator threads every currently-free block into its own linked list (§ 2.4). Each free block stores its own size and a next pointer to the following free block.

      7.2First-fit allocation

      1. Walk the free list from free_head.
      2. Stop at the first block whose size ≥ the request.
      3. If it's much bigger than needed, split it in two.
      4. Unlink the (used) block from the free list; return it to the caller.

      Sibling strategies (know the names): best fit picks the smallest adequate block; worst fit picks the largest; next fit resumes the search where the last one stopped.

      7.3A tiny first-fit allocator

      The pointer-to-pointer idiom: p is the address of the link that points at the current block (first &freeHead, then &block->next). To unlink, we just write *p = b->next; — no separate prev pointer, no head special-case. (b + 1) is pointer arithmetic: one Block past the header, i.e. the bytes the user may use.

      7.4Coalescing — fighting fragmentation on free

      When a block is freed, the allocator checks its immediate neighbours in memory; if they're also free, it merges them into one larger block instead of leaving adjacent free fragments — directly countering external fragmentation.

      § 09

      Linked Lists in the Wild

      Real systems you use every day, and the list hiding inside each

      9.1Singly linked lists — under-the-hood systems

      Each item points only to the next; highly optimised for adding or removing items quickly at the ends.

      • OS memory management — the OS keeps a linked list of "free blocks" to track available RAM. Opening/closing programs (malloc / free) splits or merges list nodes without rearranging physical memory.
      • Blockchain networks — conceptually, Bitcoin or Ethereum behave like a singly linked list: each block of transactions contains data and a digital "pointer" (a hash) to the previous block, creating an immutable chain.
      • Hash-map collision handling — deep inside language runtimes (Python dictionaries, Java HashMaps), two keys that hash to the same bucket are handled by chaining a linked list of entries at that bucket (separate chaining).

      9.2Doubly linked lists — bidirectional navigation

      Each node points to both the next and the previous item — ideal wherever you must move back and forth.

      • Browser history — clicking Back or Forward in Chrome/Firefox traverses a doubly linked list of visited URLs.
      • Undo / redo — Word, VS Code, and Photoshop log actions as nodes; Undo walks the pointer backward, Redo forward.
      • Image viewers — gallery apps let you swipe to the next image or back to the previous one seamlessly.

      9.3Circular linked lists — continuous loops

      The final item points back to the very first, creating an endless cycle.

      • Music & video playlists — Spotify or VLC: when the final song finishes, the player loops back to the first track ("repeat all").
      • OS task scheduling — round-robin: the OS cycles through a circular list of active programs, giving each a few milliseconds of CPU before moving to the next.
      • Traffic-light controllers — automated systems cycle repeatedly through Green → Yellow → Red states.

      10.1Key takeaways

      • Linked lists trade the array's O(1) random access for O(1) insert/delete.
      • A node is just a value plus one or two pointers — everything else follows.
      • Fragmentation is why allocators (and free lists) exist in the first place.
      • Doubly linked lists add a prev pointer for backward traversal & O(1) delete.
      • Circular lists replace "until NULL" with "until back at head".
      • Polynomials and memory allocators are both, underneath, linked lists.

      10.3Review questions (click to reveal)

      Q1. What is the time complexity of inserting a new node at the head of a singly linked list?
      A) O(1)B) O(n)C) O(log n)D) O(n²)
      Answer — A · O(1)

      No traversal is needed to insert at the head: two pointer writes (newNode->next = head; head = newNode;) and you're done.

      Q2. In a singly linked list, what does the last node's next pointer store?
      A) address of the head nodeB) nullptrC) its own addressD) a garbage value
      Answer — B · nullptr

      NULL marks the end of a NULL-terminated list — it is the sentinel every traversal loop watches for.

      Q3. Which structure allows O(1) deletion of a node given only a pointer to it (no search)?
      A) ArrayB) Singly linked listC) Doubly linked listD) None of these
      Answer — C · Doubly linked list

      The prev pointer gives the predecessor for free, avoiding the search a singly linked list must perform.

      Q4. What is external fragmentation?
      A) wasted space inside an allocated blockB) free memory split into many small, non-adjacent gapsC) a pointer that references freed memoryD) a cycle in a linked list
      Answer — B

      Scattered free gaps: total free space is enough, but no single gap is. (A describes internal fragmentation; C a dangling pointer; D a list bug.)

      Q5. In a circular singly linked list, how do you know traversal has completed one lap?
      A) curr becomes nullptrB) curr equals head againC) a counter reaches zeroD) the list throws an exception
      Answer — B · curr == head

      A circular list has no NULL to stop on — the loop must watch for "back to head" instead.

      Q6. Adding two polynomial lists — what happens when two terms share an exponent?
      A) keep only the first termB) add their coefficients into one result termC) discard both termsD) multiply their coefficients
      Answer — B

      Matching exponents combine into one term: 3x² + 5x² → 8x². Both pointers then advance.

      10.4Practice problems — fully solved

      P1 · Why is inserting at the tail of a singly linked list O(n), unless a tail pointer is maintained?

      With only head, the last node can be found only by walking all n links — hence O(n). If the list also maintains a tail pointer (updated whenever a node is appended or the last node deleted), appending is two writes: tail->next = n; tail = n; — O(1). This is exactly how the queue of § P8 achieves O(1) enqueue.

      P2 · Dangling pointer vs. memory leak — the difference

      Dangling pointer: memory is freed but pointers to it still exist and may be used → undefined behaviour. Memory leak: memory is still allocated but no pointer can reach it → it can never be freed.

      Node* p = new Node{1,nullptr};
delete p;        // p is now DANGLING (freed, still addressable)
Node* q = new Node{2,nullptr};
q = nullptr;     // the node {2} is LEAKED (allocated, unreachable)
      P3 · Why must the circular-list stopping condition differ from a NULL-terminated list?

      In a circular list next is never NULL — the last node points back to head. A while (curr != nullptr) loop therefore never terminates. The correct condition is curr != head inside a do…while (the do-while guarantees the first node is visited before the equality test ends the lap).

      P4 · Reverse a singly linked list — iterative & recursive

      Iterative: O(n) time, O(1) space. Recursive: O(n) time, O(n) call-stack space.

      P5 · Detect a cycle — Floyd's slow/fast pointers

      Why it works: if a cycle exists, both pointers end up inside it; fast gains on slow by exactly one node per iteration, so the gap shrinks to 0 — they must meet. If fast reaches NULL, the list ends: no cycle. O(n) time, O(1) space.

      P6 · Find the middle node in a single pass
      P7 · Merge two sorted linked lists into one sorted list

      Same merge step as polynomial addition (§ 6.3) — compare at each node, advance the smaller side. O(m + n).

      P8 · Implement a stack and a queue using a singly linked list
      P9 · Extend the polynomial multiplier to combine like terms as it inserts

      Use the combining insertTerm from § 6.2 (extension): when the exponent being inserted already exists, add the coefficients in place instead of creating a node — and drop the node if the coefficient becomes zero. multPoly itself needs no change.

      10.6Two-mark rapid-fire definitions

      Node
      A data field bundled with one or more pointers to other nodes.
      Head
      The pointer to the first node; the list's only necessary handle.
      Self-referential structure
      A struct containing a pointer to an object of its own type.
      Walking pointer
      A pointer (curr) that advances node-by-node during traversal.
      Dangling pointer
      A pointer that still references freed memory.
      Memory leak
      Allocated memory that is no longer reachable and never freed.
      Internal fragmentation
      Wasted space inside an allocated block (rounding).
      External fragmentation
      Free memory split into small, non-adjacent, unusable gaps.
      Free list
      The allocator's linked list threading all free heap blocks.
      First-fit
      Allocation strategy: take the first free block big enough.
      Coalescing
      Merging physically adjacent free blocks into one larger block.
      Reference counting
      GC that frees an object when its pointer count hits zero; fails on cycles.
      Mark-and-sweep
      GC that marks everything reachable from roots, then sweeps the rest.
      Circular list
      A list whose last node points back to the first — no NULL, only a loop.
      Round-robin
      Scheduling that cycles through a circular ready queue, one time slice each.
      Josephus problem
      Eliminate every k-th person around a circle until one survives.
      Sparse representation
      Storing only non-zero elements (e.g. polynomial terms) to save memory.
