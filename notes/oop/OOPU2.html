Introduction to Java

Where Java came from, how it runs everywhere, and the language fundamentals you will be tested on: terminology, features, the first program, data types, operators, casting and control flow.

14.1 History & Evolution

Java is a programming language created by James Gosling at Sun Microsystems in 1991 (it was initially called Oak). The founding goal explains almost everything about Java’s design: write a program once, and then run that program on multiple operating systems — without rewriting or recompiling it for each machine.

The first publicly available version, Java 1.0, was released in 1995. Sun began releasing Java under the GNU General Public License (GPL) in 2006 — that open-source project is OpenJDK, which Oracle continues today. In 2010 Oracle Corporation acquired Sun Microsystems, and Oracle has held the stewardship of Java ever since.

  • 1991

    James Gosling creates Java at Sun Microsystems. Target: write once, run on multiple operating systems.

  • 1995

    Java 1.0 — the first public version — is released.

  • 2006

    Sun starts making Java available under the GPL; the OpenJDK project begins.

  • 2010

    Oracle acquires Sun Microsystems and takes the stewardship of Java.

  • Today

    Oracle continues the OpenJDK project; Java remains one of the most used languages on Earth.

Exam note

Memorise the quartet: who (James Gosling), where (Sun Microsystems), when (1991 created / 1995 first public release), who owns it now (Oracle, since the 2010 acquisition).

14.3 Java Terminology: JVM, JRE and JDK

Three acronyms dominate every Java introduction. The key insight is containment: the JDK contains the JRE, and the JRE contains the JVM.

JVM — Java Virtual Machine
A virtual machine that resides in the real machine (your computer). Its “machine language” is bytecode. Because the compiler only has to generate one bytecode format — instead of different machine code for every type of machine — the JVM executes the bytecode and produces the output. The JVM is what makes Java platform independent.
JRE — Java Runtime Environment
The part of the JDK for running Java programs. It includes the JVM, core class libraries, browser plugins and applet support. With only the JRE installed you can run a Java program, but you cannot compile one.
JDK — Java Development Kit
The complete development kit: the JRE plus the compiler (javac) and development tools such as JavaDoc and the Java debugger. To create, compile and run Java programs, you need the JDK installed.

“Java is platform independent, but the JVM is platform dependent.” Each operating system has its own JVM implementation — that is the whole trick: the same .class file runs everywhere because a different, OS-specific JVM translates it for each platform, producing the same output across all operating systems.

14.5 Java as an Object-Oriented Language

Java’s design philosophy is “objects all the way down”. It is deliberately simple and familiar — often described as “C++ Lite” — because it keeps C++’s familiar syntax while removing its sharpest edges:

  • No pointers! — references only; pointer arithmetic does not exist.
  • Garbage Collector — memory is reclaimed automatically; no manual delete.
  • Dynamic binding — method calls resolve at runtime for instance methods.
  • Multiple inheritance with “interfaces” — type inheritance without the diamond problem.

Java is considered a “pure” object-oriented language: it supports encapsulation, inheritance and polymorphism, and all code must be contained in a class — there are no free functions (functions that do not belong to some class) as in C++. (Someone determined to write messy Java still can, of course — the language guides, it does not police.) Compared with C++ (a hybrid OO language) or Smalltalk, Java sits closest to the “everything is an object” ideal while staying practical.

14.8 Platform Dependent vs Platform Independent — WORA

Compare how a C program and a Java program reach the machine. C compiles straight to native machine code for one OS/hardware pair — recompile (or rewrite) for every platform. Java compiles to bytecode, an intermediate form closer to machine representation, which the JVM interprets on whatever platform it happens to be running on. That is the slogan: “Write Once, Run Anywhere.”

C · Platform Dependent
myprog.c — source gcc compiler myprog.exe — machine code One OS / hardware — needs a rebuild per platform
Java · Platform Independent
myprog.java — source javac compiler myprog.class — bytecode JVM (one per OS) Any OS / hardware — same output everywhere

Three statements from the lecture that make excellent short-answer questions:

  • Unlike other languages, Java “executables” are executed on a CPU that does not exist — the virtual machine. The interpreter figures out the equivalent machine-dependent code to run.
  • Each operating system has a different JVM, however the output they produce after executing the bytecode is the same across all operating systems.
  • Porting Java to a new platform means writing an interpreter that supports the JVM — do that once, and every existing Java program runs there. For each platform type there is a separate JVM, but the same compiler for everyone.
Exam note

WORA = architecture neutral & portable. The chain to reproduce: Java compiler converts source code to bytecode → bytecode is an intermediate form closer to machine representation → a virtual machine on any target platform interprets the bytecode.

};
Can you save a Java source file by a name other than the class name?

Yes — provided the file contains no public class. If a class is declared public, the filename must match that class name (MyClass.java for public class MyClass). If none of the classes is public, you may save the file under any name; it compiles fine, and you run it with the class name, not the file name: java Hello even if the file was saved as test.java.

Can you have multiple classes in a Java source file?

Yes. A single .java file may contain any number of classes, but at most one of them may be public, and the file must be named after that public class. On compilation, the compiler generates a separate .class file for every class in the source file.

14.12 Classes & Objects — Data Types You Build Yourself

Java ships with a handful of built-in data types (int, float, …). Just like in C, a programmer typically creates “homemade” data types for a particular application (in C: structs and enums). In Java these are called classes.

  • Class is synonymous with data type. A class contains the implementation details of the data type and the interface for programmers who just want to use it.
  • Object is like a variable — the data type of the object is some class; an object is referred to as an instance of a class.
  • Objects are complex variables: usually multiple pieces of internal data, plus various behaviours carried out via methods.

The three-part lifecycle of every object

  1. Declaration — DataType identifier; e.g. Rectangle r1; (creates the reference only)
  2. Creation — the new operator and the specified constructor: r1 = new Rectangle();
  3. Behaviour — via the dot operator: r2.setSize(10, 20); String s2 = r2.toString();
Rectangle r1;                          // 1) declaration
r1 = new Rectangle();                  // 2) creation (new + constructor)
Rectangle r2 = new Rectangle();        //    declaration + creation together
r2.setSize(10, 20);                    // 3) behaviour via the dot operator
String s2 = r2.toString();

The new operator creates an instance of a class and a constructor executes when the new object is created (Lecture 15 is all about constructors).

14.13 The import Statement

import is a reserved word. Packages and classes can be imported into another class so you can refer to them by their simple names. Two details separate Java’s import from C++’s #include:

  • It does not actually import (copy) the code — unlike the C++ include preprocessor command. It merely instructs the compiler to look in that package for types it cannot find defined locally.
  • It is written outside the class block, at the top of the file.
import java.util.ArrayList;       // one specific class
import java.awt.Rectangle;         // another specific class
import java.util.*;                // the whole package
import java.util.Random;           // or list a given class

public class MyClass {
  // code for MyClass
}
Exam note

The java.lang.* package is automatically imported into every class — that is why System, String, Math and Object need no import. Also: classes that are part of the same project in Eclipse do not need to be imported.

Printing to standard output uses the System.out print stream in three forms:

Constants

  • Literal constants — values specified directly that remain constant for the life of the program: true, false, null, 'c', "C++", 12, -12, 12.12345.

14.16 Expressions, Type Conversion & Casting

Expressions are evaluated based on the precedence of operators. Java automatically converts numeric primitive types in mixed expressions, but the results are sometimes surprising — take special care when mixing integer and floating-point values.

Widening conversion (automatic)

  • In operations on mixed-type operands, the numeric type of the smaller range is converted to the type of the larger range.
  • In an assignment, a smaller-range numeric type can be assigned to a larger-range numeric type.
byte short int long float double

widening direction · also char → int (and upwards)

Casting (explicit)

Casting is the temporary conversion of a variable from its original data type to some other data type — like being “cast” for a part in a play or movie. The direction decides who does the work:

  • Less inclusive → more inclusive (widening): done automatically.
  • More inclusive → less inclusive (narrowing): must be done explicitly by the programmer — otherwise the compiler refuses with a possible-loss-of-precision compile error.
// automatic widening
int x = 5;
double a = 3.5;
double b = a * x + a / x;   // 17.5 + 0.7  -> 18.2
double c = x / 2;           // 5/2 = 2 (int division!) -> 2.0  ** trap **

// explicit narrowing
double a = 3.5, b = 2.7;
int y = (int) a / (int) b;  // 3 / 2 = 1   (casts bind tighter than /)
y = (int) (a / b);          // (int) 1.296 -> 1
y = (int) a / b;            // compile error: double result into int
Classic trap

double c = x / 2; looks harmless — but x / 2 is evaluated in integers first (5 / 2 = 2) and only then widened to 2.0. Write x / 2.0 or (double) x / 2 to get 2.5. This single line is one of the most reused MCQ questions in existence.

14.19 Methods & Call-by-Value

A Java method defines a group of statements as performing a particular operation. Two flavours:

  • static — a static / class method: invoked on the class itself, no object required.
  • no static — an instance method: invoked through an object.

All method arguments are call-by-value

This sentence looks innocent and is heavily examined. The value that gets copied differs by type:

Primitive argument

The value itself is passed — the method may modify its local copy, but the caller’s value is unaffected.

static void twice(int n) {
  n = n * 2;              // changes the copy only
}
Object reference argument

The address of the object is passed. Reassigning the reference inside the method does not affect the caller — but operations on the object are visible to the caller.

static void grow(Rectangle r) {
  r.setSize(10, 20);      // caller sees this!
  r = new Rectangle();    // caller does NOT see this
}
Remember

Java is always call-by-value — for objects, the value being passed is a copy of the reference. That is why you can mutate the object (shared) but never re-point the caller’s variable (private copy).

15.2 Anonymous Objects

Anonymous simply means nameless. An object which has no reference is known as an anonymous object; it can be used at the time of object creation only. If you need an object just once, an anonymous object is a good approach — it is created, used and immediately available for garbage collection.

Named — via reference 
Calculation c = new Calculation();
c.fact(5);

The reference c keeps the object alive for later reuse.

Anonymous — no reference 
new Calculation().fact(5);   // anonymous object

Use once, throw away. Each further use would need a brand-new object.

15.3 Constructors — the Complete Picture

Definition

In Java, a constructor is a block of code similar to a method. It is called when an instance of the class is created — at that moment, memory for the object is allocated. It is a special type of method used to initialize the object, and it “constructs the values at the time of object creation” — hence the name.

Three behaviours anchor every constructor question:

  • Every time an object is created with the new keyword, at least one constructor is called.
  • If the class has no constructor at all, the Java compiler provides a default constructor by default.
  • A constructor can take access modifiers (private, protected, public or default) — this controls object creation (a private constructor is how utility and singleton classes block outside instantiation).

Rules for creating a Java constructor

  1. Constructor name must be the same as its class name.
  2. A constructor must have no explicit return type.
  3. A Java constructor cannot be abstract, static, final or synchronized.
class Bike {
  Bike() {                    // same name as class, no return type
    System.out.println("bike is being constructed");
  }
}
Does a constructor return any value?

Yes — it returns the current class instance (you cannot declare a return type, yet a value is returned). This is why Bike b = new Bike(); leaves b holding the freshly built object.

Can a constructor perform other tasks instead of initialization?

Yes. Object creation, starting a thread, calling a method — you can perform any operation in the constructor that you can perform in a normal method.

15.4 Default Constructor

A constructor is called a default constructor when it doesn’t have any parameter. Its job is to give the object default values — 0, null, etc., depending on the type.

15.6 Constructor Overloading

A constructor is just like a method but without a return type — so it can be overloaded like Java methods. Constructor overloading is the technique of having more than one constructor with different parameter lists. They are arranged so that each constructor performs a different task, and the compiler differentiates them by the number and types of parameters.

class Student5 {
  int id;
  String name;
  int age;

  Student5(int i, String n) {

    name = n;

  Student5(int i, String n, int a) {

15.7 Copying Objects — the “Copy Constructor”

There is no copy constructor in Java (unlike C++). However, we can copy the values from one object to another in three ways:

  1. By constructor — writing a constructor that takes an object of the same class,
  2. By assigning the values of one object into another, field by field,
  3. By the clone() method of the Object class.

The static keyword is used mainly for memory management. A static member belongs to the class rather than to any instance of the class. It can be applied to:

  • a variable (also known as a class variable),
  • a method (also known as a class method),
  • a block,
  • a nested class.

15.9 static Method

Apply static to a method and it becomes a class method: it belongs to the class rather than to an object, and can be invoked without creating any instance of the class. A static method can access static data members and can change their value.

    name = n;

15.11 this Keyword — Six Usages

Inheritance, Aggregation, Overloading & Overriding

Building new classes from existing ones — and the two “same name” mechanisms that power compile-time and runtime polymorphism.

16.1 Inheritance — Concept & Syntax

Definition

Inheritance is a mechanism in which one object acquires all the properties and behaviours of a parent object — an essential part of OOP. The idea: you can create new classes that are built upon existing classes, reusing the parent’s methods and fields, and adding new methods and fields of your own. Inheritance represents the IS-A relationship, also known as a parent–child relationship.

Why use inheritance? Two reasons, both examinable:

  1. For method overriding — so that runtime polymorphism can be achieved.
  2. For code reusability.
class Subclass-name extends Superclass-name {
  // methods and fields
}

The extends keyword indicates that you are making a new class derive from an existing class. The meaning of “extends” is to increase the functionality.

class Employee {
  float salary = 40000;
}

class Programmer extends Employee {
  int bonus = 10000;

  public static void main(String[] args) {
    Programmer p = new Programmer();
    System.out.println("Programmer salary is:" + p.salary);
    System.out.println("Bonus of Programmer is:" + p.bonus);
  }
}
Output
Programmer salary is:40000.0
Bonus of Programmer is:10000
Watch the type

salary is a float, so it prints 40000.0, while the int bonus prints 10000. Reading the field type before answering an output question saves the mark.

On the basis of classes, there are three types of inheritance in Java: single, multilevel and hierarchical. Multiple and hybrid inheritance are supported only through interfaces — never through classes.

  • Animal

One parent, one child. The Dog example: d.bark() works, and the inherited d.eat() works too.

    • Dog

16.3 Why Multiple Inheritance Is Not Supported

To reduce the complexity and simplify the language, multiple inheritance is not supported in Java. The scenario to narrate in the exam — the diamond problem:

Consider classes A, B and C where C inherits both A and B. If A and B have the same method and you call it from the child class object, there is ambiguity: call A’s method or B’s? Since compile-time errors are better than runtime errors, Java renders a compile-time error if you extend two classes — whether the methods clash or not.

16.4 Aggregation — the HAS-A Relationship

Definition

If a class has an entity reference, it is known as aggregation. Aggregation represents the HAS-A relationship — a whole–part association where the part can exist independently. It is used for code reusability.

Example: an Employee object contains many pieces of information — id, name, emailId — and one more object named address, which itself holds city, state, country, zipcode:

class Employee {
  int id;
  String name;
  Address address;      // Address is a class — aggregation
  // ...
}

Because Employee holds an entity reference to Address, the relationship is Employee HAS-A address. Note the difference from inheritance: an Employee is not an Address — it merely has one.

class Operation {
  int square(int n) {
    return n * n;
  }
}

class Circle {
  Operation op;          // aggregation
  double pi = 3.14;

  double area(int radius) {
    op = new Operation();
    int rsquare = op.square(radius);   // code reusability —
    return pi * rsquare;               // delegates the method call
  }

  public static void main(String[] args) {
    Circle c = new Circle();
    double result = c.area(5);
    System.out.println(result);
  }
}

16.5 Method Overloading

Definition

If a class has multiple methods having the same name but different parameters, it is known as method overloading. Having one name for one operation increases the readability of the program — add(2,3) and add(2,3,4) both obviously add, instead of a(int,int) and b(int,int,int).

There are two ways to overload a method:

  1. By changing the number of arguments
  2. By changing the data type of arguments

  int add(int a, int b, int c) { return a + b + c; }

16.6 Type Promotion in Overloading

One type is promoted to another implicitly if no matching datatype is found. The promotion ladder: byte can be promoted to short, int, long, float or double; short to int, long, float or double; char to int, long, float or double — and so on, always upward.

  public static void main(String[] args) {
    OverloadingCalculation1 obj = new OverloadingCalculation1();
    obj.sum(20, 20);        // no (int,int) match -> 2nd int promoted to long
    obj.sum(20, 20, 20);
  }
}

16.7 Method Overriding

Definition

If a subclass has the same method as declared in the parent class, it is known as method overriding. The subclass provides the specific implementation of a method already provided by its superclass. Method overriding is used for runtime polymorphism.

Rules for Java method overriding

  1. The method must have the same name as in the parent class.
  2. The method must have the same parameters as in the parent class.
  3. There must be an IS-A relationship (inheritance).
  4. A static method cannot be overridden. Why? The static method is bound with the class, whereas an instance method is bound with an object — static belongs to the class area, an instance belongs to the heap area. For the same reason we cannot override the Java main method (it is static).
Without overriding 
class Vehicle {
  void run() {
    System.out.println("Vehicle is running");
  }
}

class Bike extends Vehicle {
  public static void main(String[] args) {
    Bike obj = new Bike();
    obj.run();            // inherits the parent version
  }
}

Vehicle is running
With overriding

  void run() {
    System.out.println("Vehicle is running");
  }
}

class Bike2 extends Vehicle {
  void run() {           // same name, same parameters
    System.out.println("Bike is running safely");
  }

  public static void main(String[] args) {
    Bike2 obj = new Bike2();

  }

16.9 super Keyword

Definition

The super keyword in Java is a reference variable used to refer to the immediate parent class object. Whenever you create the instance of a subclass, an instance of the parent class is created implicitly — and it is that implicit parent object which super refers to.

Three usages — mirror the three usages of this:

  1. super can refer to the immediate parent class instance variable.
  2. super can invoke the immediate parent class method.
  3. super() can invoke the immediate parent class constructor.

1 · super for parent instance variables

Used when parent and child have the same field name. Printing color gives the current (Dog) class value by default; super.color reaches the parent property:

class Animal {

  String color = "black";

  void printColor() {
    System.out.println(color);        // Dog class color
    System.out.println(super.color);  // Animal class color
  }
}

    d.printColor();

17.1 The final Keyword — Overview

The final keyword is used to restrict the user. It can be applied in three contexts:

CONTEXT 01

final variable

Value cannot be changed — it becomes a constant.

CONTEXT 02

final method

Cannot be overridden by subclasses.

CONTEXT 03

final class

Cannot be extended at all.

A final variable that has no value is called a blank final variable (an uninitialized final variable). It can be initialized in the constructor only. A blank final variable can also be static — in which case it is initialized in the static block only.

17.2 final Variable · final Method · final Class

final variable 
class Bike9 {
  final int speedlimit = 90;   // final variable

  void run() {
    speedlimit = 400;          // compile-time error
  }

  public static void main(String[] args) {
    Bike9 obj = new Bike9();
    obj.run();
  }
}

Once assigned, a final variable can never be reassigned — the compiler rejects speedlimit = 400.

final method 
class Bike {
  final void run() {
    System.out.println("running");
  }
}

class Honda extends Bike {
  void run() {     // compile-time error —
    System.out.println("running safely with 100kmph");
  }

  public static void main(String[] args) {
    Honda honda = new Honda();
    honda.run();
  }
}

A final method is locked against overriding.

final class Bike { }

class Honda1 extends Bike {    // compile-time error
  void run() { System.out.println("running safely with 100kmph"); }

  public static void main(String[] args) {
    Honda1 honda = new Honda1();
    honda.run();
  }
}

Make the class final and nobody can extend it — the classic examples in the API are String and the wrapper classes.

Is a final method inherited?

Yes — a final method is inherited; you simply cannot override it. The child calls the parent’s implementation as-is:

class Bike {
  final void run() { System.out.println("running..."); }
}

class Honda2 extends Bike {
  public static void main(String[] args) {
    new Honda2().run();     // inherited — works fine
  }
}
Output
running...

17.5 Runtime Polymorphism — Dynamic Method Dispatch

Definition

Runtime polymorphism or Dynamic Method Dispatch is the process in which a call to an overridden method is resolved at runtime rather than compile-time. The overridden method is called through the reference variable of a superclass, and the determination of which method to call is based on the object being referred to — not on the type of the reference.

Upcasting

Definition

If the reference variable of a parent class refers to the object of a child class, it is known as upcasting.

class A { }
class B extends A { }
// ...
A a = new B();     // upcasting
class Bike {
  void run() { System.out.println("running"); }
}

class Splendor extends Bike {
  void run() { System.out.println("running safely with 60km"); }

  public static void main(String[] args) {
    Bike b = new Splendor();   // upcasting
    b.run();                   // runtime decision — Splendor's run
  }
}
Output
running safely with 60km
The heart of the concept

Variable b has type Bike but points to a Splendor object. The compiler checks the method exists on Bike; at runtime the JVM looks at the actual object and runs Splendor’s version. Reference type decides what you may call; object type decides what actually runs.

The Shape family — the classic illustration

17.6 Static Binding vs Dynamic Binding

Definition

Connecting a method call to the method body is known as binding. There are two types: static binding (also known as early binding) and dynamic binding (also known as late binding).

To reason about binding you must first be able to name three different “types” in play — this framing is itself examinable:

  1. Variables have a type — each variable has a type, primitive or non-primitive: int data = 30;
  2. References have a type — Dog d1; is a reference of type Dog.
  3. Objects have a type — Dog d1 = new Dog(); creates an object of type Dog (which is also an Animal if Dog extends Animal).
Static (early) binding

The type of the object is determined at compile time by the compiler. If there is any private, final or static method in a class, static binding applies — these methods cannot be overridden, so the compiler can safely lock the target.

class Dog {
  private void eat() {
    System.out.println("dog is eating...");
  }

  public static void main(String[] args) {
    Dog d1 = new Dog();
    d1.eat();
  }
}
Dynamic (late) binding

The type of the object is determined at run-time. Overridden instance methods bind dynamically — the JVM inspects the actual object behind the reference.

class Animal {
  void eat() { System.out.println("animal is eating..."); }
}

class Dog extends Animal {
  void eat() { System.out.println("dog is eating..."); }

  public static void main(String[] args) {
    Animal a = new Dog();   // reference: Animal
    a.eat();                // object:   Dog
  }
}
Output
dog is eating...
Remember

private, final or static methods (plus constructors) → static binding. Overridden instance methods → dynamic binding. This also explains why static methods cannot be overridden — they are class-bound, never object-bound.

17.7 instanceof Operator

Definition

The instanceof operator tests whether the object is an instance of the specified type (a class, subclass or interface). It is also known as the type comparison operator because it compares the instance against the type — and it returns either true or false.

class Simple1 {
  public static void main(String[] args) {
    Simple1 s = new Simple1();
    System.out.println(s instanceof Simple1);   // true
  }
}

class Animal { }
class Dog1 extends Animal {        // Dog inherits Animal
  public static void main(String[] args) {
    Dog1 d = new Dog1();
    System.out.println(d instanceof Animal);   // true
  }
}

An object of a subclass type is also a type of the parent class: if Dog extends Animal, an object of Dog can be referred to by either a Dog or an Animal reference — hence both tests return true.

class Dog2 {
  public static void main(String[] args) {
    Dog2 d = null;
    System.out.println(d instanceof Dog2);   // false
  }
}
Guaranteed one-liner

If you apply instanceof to any variable holding null, it returns false — null is an instance of nothing.

17.8 Downcasting

Definition

When a subclass type refers to the object of a parent class, it is known as downcasting — the mirror image of upcasting.

  1. Direct downcast: Dog d = new Animal(); → compilation error — the compiler refuses the obvious mismatch.
  2. Forced cast: Dog d = (Dog) new Animal(); → compiles successfully, but throws ClassCastException at runtime — the object really is an Animal, not a Dog.
  3. Safe route: test with instanceof first, and cast only when the test passes — then downcasting works.
Dog d = new Animal();          // compile-time error
Dog d = (Dog) new Animal();    // compiles, but ClassCastException at runtime
Animal a = new Dog();          // upcast first
if (a instanceof Dog) {
  Dog d = (Dog) a;             // safe — the object really is a Dog
  d.bark();
}
Remember

Upcasting is always safe and implicit; downcasting needs an explicit cast and must be guarded by instanceof — otherwise the runtime throws ClassCastException.

18.1 Abstraction & Abstract Classes

Definition

Abstraction is a process of hiding the implementation details and showing only functionality to the user — it shows only the essential things and hides the internal details. Example: sending an SMS — you type the text and send the message; you don’t know the internal processing about the message delivery. Abstraction lets you focus on what the object does instead of how it does it.

There are two ways to achieve abstraction in Java:

WAY 01

Abstract class

Abstraction from 0 to 100% — it may mix abstract and fully implemented methods.

WAY 02

Interface

Abstraction at 100% — traditionally, nothing but abstract methods.

Rules and properties of an abstract class

  • A class declared with the abstract keyword is an abstract class. It can have abstract and non-abstract methods (methods with a body).
  • It needs to be extended, and its abstract methods implemented by a concrete subclass.
  • It cannot be instantiated.
  • It can have constructors and static methods also.
  • It can have data members and even a main() method.
  • It can have final methods, which force the subclass not to change the method body.
abstract class Bike {
  abstract void run();          // no body — subclass must implement
}

class Honda extends Bike {
  void run() { System.out.println("running safely"); }

  public static void main(String[] args) {
    Bike obj = new Honda();     // abstract type, concrete object
    obj.run();
  }
}
Output
running safely

An abstract class can have constructor, data member and methods

  abstract void run();                                   // abstract method
  void changeGear() { System.out.println("gear changed"); } // method body
}

  void run() { System.out.println("running safely.."); }
}

    obj.changeGear();

Exam note

Note the constructor ran even though the class is abstract — you can never write new Bike(), but instantiating the subclass chains the abstract parent’s constructor via the implicit super() (Lecture 16).

Two golden rules

Rule 1 — If there is an abstract method in a class, that class must be abstract (a plain class containing abstract void run(); is a compile-time error). Rule 2 — If you extend an abstract class that has abstract methods, you must either implement them all or declare your class abstract too.

18.2 Interfaces — the Blueprint of a Class

Definition

An interface in Java is a blueprint of a class. It has static constants and abstract methods. It is a mechanism to achieve abstraction and multiple inheritance in Java — it can have abstract methods and variables, but no method body (traditionally). An interface also represents the IS-A relationship and, like an abstract class, cannot be instantiated.

  • The interface provides total abstraction: all methods are declared with an empty body, and all fields are public, static and final by default.
  • A class that implements an interface must implement all the methods declared in it (unless the class is itself abstract).
  • Methods in an interface are public and abstract by default.
  • Since Java 8, interfaces can have default and static methods (with bodies). Since Java 9, they can have private methods.

Three reasons to use an interface: (1) to achieve abstraction, (2) to support the functionality of multiple inheritance, and (3) to achieve loose coupling.

  // declare methods that are abstract (by default)
}

    obj.print();
  }

18.5 Java Packages

Definition

A Java package is a group of similar types of classes, interfaces and sub-packages. Packages come in two forms: built-in packages and user-defined packages. Well-known built-in packages include java.lang, java.awt, javax.swing, java.net, java.io, java.util and java.sql.

Three advantages of packages — memorise verbatim:

  1. Categorization — classes and interfaces are grouped so they can be easily maintained.
  2. Access protection — packages provide an extra level of visibility control.

18.7 Encapsulation

Definition

Encapsulation is the process of wrapping code and data together into a single unit — for example, a capsule, which is a mixture of several medicines. We create a fully encapsulated class by making all data members private, and then expose them through setter and getter methods. The Java Bean class is the example of a fully encapsulated class.

Advantages of encapsulation:

  1. Read-only or write-only control — provide only a getter (read-only) or only a setter (write-only); skip either one.
  2. Control over the data — write logic inside the setter: an id that must be greater than 100, or a refusal to store negative numbers.
  3. Data hiding — other classes cannot reach the private data members directly.
  4. Easy to test — an encapsulated class is ideal for unit testing.
  5. Fast to create — standard IDEs generate getters and setters automatically.

19.1 What Is an Exception & Why Handle It?

Definition

An exception is an event that disrupts the normal flow of the application. Exception handling exists so that the normal flow of the application can be maintained — the core advantage of exception handling.

The lecture’s scenario says it all. Suppose there are 10 statements in your program and an exception occurs at statement 5: the rest of the code — statements 6 to 10 — will not be executed. If we perform exception handling, the rest of the statements execute. That is why we use exception handling in Java.

19.2 Types of Java Exceptions

According to Oracle there are three kinds of throwables — the classification every paper asks for:

TYPE 01

Checked exception

Classes which directly inherit Throwable except RuntimeException and Error. E.g. IOException, SQLException. Checked at compile-time — the compiler forces you to handle them.

TYPE 02

Unchecked exception

Classes which inherit RuntimeException. E.g. ArithmeticException, NullPointerException, ArrayIndexOutOfBoundsException. Not checked at compile-time — checked at runtime.

TYPE 03

Error

Irrecoverable problems. E.g. OutOfMemoryError, VirtualMachineError, AssertionError. You are not expected to handle them.

Exceptions are also split by origin: built-in exceptions (pre-defined classes provided by Java for common errors — each divided into checked and unchecked as above) and user-defined exceptions (when the built-ins cannot describe a certain situation, users create their own exception classes).

19.6 Internal Working of the try–catch Block

  1. The JVM executes the code inside the try block.
  2. If an exception occurs, the remaining try code is skipped and the JVM searches for a matching catch block.
  3. If a match is found, the catch block executes.
  4. Control then moves to the finally block (if present).
  5. If no matching catch is found, the exception is handled by the JVM’s default handler — the program terminates abruptly, and code after that point never executes.
  6. The finally block always executes, whether an exception occurred or not.
Note

When an exception occurs and is not handled, the program terminates abruptly and the code after it will never execute. Handling is precisely what buys the program its remaining statements.

19.7 Multi-catch Blocks

A try block can be followed by one or more catch blocks, each containing a different exception handler — use them when different exceptions demand different responses. Two iron rules:

  • At a time only one exception occurs — and at a time only one catch block executes.
  • All catch blocks must be ordered from most specific to most general: the catch for ArithmeticException must come before the catch for Exception.
public class MultipleCatchBlock1 {
  public static void main(String[] args) {
    try {
      int a[] = new int[5];
      a[5] = 30 / 0;              // ArithmeticException fires first
    } catch (ArithmeticException e) {
      System.out.println("Arithmetic Exception occurs");
    } catch (ArrayIndexOutOfBoundsException e) {
      System.out.println("ArrayIndexOutOfBounds Exception occurs");
    } catch (Exception e) {
      System.out.println("Parent Exception occurs");
    }
    System.out.println("rest of the code");
  }
}

Why Arithmetic, not ArrayIndexOutOfBounds?

In a[5] = 30 / 0; the right-hand side 30 / 0 is evaluated before the value is stored into index 5 — so the arithmetic blow-up happens first and its catch runs. The out-of-bounds store never gets a chance. If you reverse the catch order (Exception first), the specific blocks become unreachable — a compile-time error.

19.8 The finally Block

The finally block is used to execute cleanup code after try and catch — closing files, releasing resources. It normally executes whether an exception occurs or not. The rare cases where finally does not execute:

  • System.exit() is called,
  • the JVM crashes,

How the JVM handles an exception — the call stack hunt

When an exception occurs, the JVM creates an exception object containing the error name, description and program state. Throwing an exception means creating that object and transferring control to the nearest appropriate handler using the throw keyword. The list of methods that had been called to reach the point of failure is the call stack. Then:

  1. The runtime system searches the call stack for an exception handler —
  2. starting from the method where the exception occurred and proceeding backward through the callers —
  3. if a handler is found, the exception is passed to it;
  4. if no handler is found, the default exception handler terminates the program and prints the stack trace.

21.5 Event Handling & the Delegation Event Model

Definition

A change in the state of an object is known as an event — the event describes the change in the state of the source. Events are generated as a result of user interaction with the GUI components: clicking a button, moving the mouse, typing a character, selecting an item from a list, scrolling the page. Event handling is the mechanism that controls the event and decides what should happen if an event occurs — the code that runs when an event occurs is the event handler.

Two types of events

TYPE 01

Foreground events

Require direct interaction of the user — generated by a person interacting with the graphical components: clicking a button, moving the mouse, typing a character, selecting from a list, scrolling the page.

TYPE 02

Background events

Don’t require the interaction of the end user — operating-system interrupts, hardware or software failure, timer expiration, operation completion.

Java uses the Delegation Event Model

The model has two pillars:

Source
The object on which the event occurs. The source is responsible for providing information about the occurred event to its handler. Java provides classes for the source objects, and registration methods (addActionListener(…)) so listeners can subscribe.
Listener
Also known as the event handler. The listener is responsible for generating a response to an event. In Java it is also an object: it waits until it receives an event, then processes the event and returns.
User clicks the button Source — the JButton Event object — ActionEvent created & filled with source info Registered listener receives the event actionPerformed() runs — the response

The benefit of the Delegation Event Model: the user interface logic is completely separated from the logic that generates the event — the UI element can delegate the processing of an event to a separate piece of code. The listener must be registered with the source object to receive notifications, which makes the model efficient: notifications are sent only to the listeners that want them.

Steps involved in event handling

  1. The user clicks the button — the event is generated.
  2. An object of the concerned event class is created automatically, and information about the source and the event is populated within that object.
  3. The event object is forwarded to the callback method of the registered listener class.
  4. The method is executed and returns.

21.6 The ActionListener Interface

The Java ActionListener is notified whenever you click a button or menu item — it is notified against ActionEvent. It lives in the java.awt.event package and has only one method: actionPerformed().

The common approach is to implement the interface. If you implement ActionListener in your class, follow three steps:

  1. Implement the interface: public class ActionListenerExample implements ActionListener
  2. Register the component with the listener: component.addActionListener(instanceOfListenerClass);
  3. Override actionPerformed() and write the response code inside it.
import java.awt.event.ActionEvent;
import java.awt.event.ActionListener;
import javax.swing.*;

public class Simpleframe extends JFrame implements ActionListener {

  JTextField tf1;

  public Simpleframe() {
    this.setSize(400, 400);
    this.setTitle("Simple Frame");
    this.setLayout(null);

    JLabel l1 = new JLabel();
    l1.setText("WELCOME");
    l1.setBounds(120, 20, 180, 40);
    this.add(l1);

    tf1 = new JTextField();
    tf1.setBounds(120, 60, 180, 70);
    this.add(tf1);

    JButton b1 = new JButton();
    b1.setText("Click Me");
    b1.setBounds(120, 140, 180, 60);
    this.add(b1);
    b1.addActionListener(this);      // registration!
    this.setVisible(true);
  }

  public static void main(String[] args) {
    Simpleframe sf1 = new Simpleframe();
  }

  @Override
  public void actionPerformed(ActionEvent arg0) {
    tf1.setText("VIIT");             // the response
  }
}

Run it: the same window as before — but now, clicking the button instantly replaces the text field content with “VIIT”. The flow: click → ActionEvent → actionPerformed → tf1.setText("VIIT").

R.5 Self-Test — 15 Questions

Tap a question to reveal the answer. Score honestly: 13+ means you are exam-ready.

Which component executes bytecode, and which one compiles source code?

The JVM executes bytecode; the compiler javac (part of the JDK) compiles source code into bytecode.

Why is Java called platform independent while the JVM is platform dependent?

Java programs compile to platform-neutral bytecode; each OS ships its own JVM that interprets the same bytecode — identical output everywhere. The JVM is platform dependent because a separate implementation exists per OS.

Why must main be static?

So the JVM can invoke it without creating an object of the class — nothing of the program exists before main runs. It also saves memory.

What does the counter program print without and with a static count?

Without static: 1 1 1 (each object re-creates count). With static: 1 2 3 (one shared copy, memory allocated once at class loading).

What is the output when a constructor assigns rollno = rollno and the field is displayed?

0 null — the parameter is assigned to itself; the instance fields keep their default values (0 for int, null for String).

Name the three class-based inheritance types and state which two are impossible with classes.

Single, multilevel, hierarchical. Multiple and hybrid are impossible with classes — they require interfaces, because two parent classes with the same method would create ambiguity (compile-time errors are preferred over runtime errors).

Why can’t you overload methods by return type alone?

Ambiguity — a call like Adder.add(11,11) matches both candidates identically; the compiler has no way to choose.

What happens with obj.sum(20,20) when the overloads are sum(int,long) and sum(long,int)?

Compile-time error — ambiguity. Each candidate requires promoting exactly one argument, so neither wins.

Bike b = new Splendor(); b.run(); — whose run() executes and why?

Splendor’s run(). Dynamic method dispatch: the reference type (Bike) decides what may be called, but the actual object (Splendor) decides which overridden implementation runs — resolved at runtime.

Can a final method be inherited? Can a final class be extended?

A final method is inherited — it just cannot be overridden. A final class cannot be extended at all.

Where do you initialize a blank final variable and a static blank final variable?

Blank final → only in the constructor. Static blank final → only in the static block.

Multiple inheritance by interface causes no ambiguity — why?

Because the interface supplies no implementation at all — the single implementation is written by the implementing class, so there is only ever one method body to call.

Order these by scope: default, private, public, protected.

private < default < protected < public — class · package · package+subclass · everywhere. And an overriding method may never move leftward.

Classify IOException, ArithmeticException and OutOfMemoryError.

IOException — checked (compile-time, must be handled/declared). ArithmeticException — unchecked (RuntimeException, surfaces at runtime). OutOfMemoryError — Error (irrecoverable).

In the Delegation Event Model, what are the source and the listener?

Source — the object on which the event occurs; it creates the event object and notifies registered handlers. Listener — the object registered with the source that receives the event and responds (the event handler). Registration keeps notifications efficient: only willing listeners are told.
