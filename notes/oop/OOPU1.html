01Foundations of Object-Oriented Programming

Object-Oriented Programming (OOP) organises a program as a collection of objects — self-contained units that bundle data (state) together with the operations (behaviour) that act on that data — instead of a sequence of procedures operating on shared global data.

1.1 Why OOP?

Procedural programming expresses programs as a collection of procedures (subroutines). As programs grow, the data becomes globally visible and any procedure can corrupt it. OOP solves this by:

  • Bundling data and behaviour into one unit (the class).
  • Restricting access to the internal data, exposing only a controlled interface.
  • Reusing existing code through inheritance.
  • Generalising behaviour through polymorphism.

1.2 The Pillars of OOP

Abstraction

Abstraction means exposing only the essential features of an entity while hiding the underlying complexity. A Car class exposes accelerate() and brake(); it does not expose the fuel-injection timing. In C++, abstraction is achieved through classes with public interfaces and private implementations.

Encapsulation

Encapsulation is the packaging of data and the functions that manipulate that data into a single unit, and the protection of that data from outside interference. In C++ this is done with access specifiers: private, protected, public.

Information Hiding

  • The interface to a class is the list of public data members and methods.
  • The interface defines the behaviour of the class to the outside world (other classes and functions).
  • The implementation of the class does not matter outside the class — only the interface does.
  • Consequence: you can change the implementation freely, as long as the interface stays the same. You can use other people's classes without fear.

Inheritance

It is possible to extend existing classes without seeing or modifying them. You add whatever new behaviour you want. Example: you have a class Student; you create a new class GoodStudent. Most behaviour and attributes are the same, but a few are specialised.

Polymorphism

The ability of different objects to respond to the same message in different ways. Sending cout << x to an int, a double, and a user-defined Poly object invokes three different implementations behind one syntax.

1.3 Objects

An object is any entity that has state and behaviour. It can be physical (chair, pen, table, keyboard, bike) or logical. An object is an instance of a class. It occupies memory, has an address, and can communicate with other objects without knowing the details of their data or code — only the type of message accepted and the type of response returned.

Example: a dog is an object because it has states (colour, name, breed) and behaviours (wagging the tail, barking, eating).

1.4 Classes

  • A class is a blueprint or template from which individual objects are created.
  • A class is a group of objects that share common properties.
  • A class does not consume memory (it is a logical entity).
  • Defining a class does not create an object.

In C++, a class is an object type. When you write the definition of a class, you are defining the attributes and behaviour of a new type:

  • Attributes are data members.
  • Behaviour is defined by methods (member functions).

Creating an object (Instantiation)

Student s1;              // stack object
Student s2(101, "Riya"); // parameterised constructor
Student *s3 = new Student(); // heap object

2.6 Expressions

C++ expressions express computation. Expressions include operations and the operands on which the operations are applied. Operands can be variables, literals, or function calls.

Associativity

The associativity of an operator controls the order of evaluation of expressions involving the same operator. Example: 3 / 4 / 5.

  • Right-to-left: the rightmost operator is applied first.

Precedence controls the order of evaluation of different operators. A high precedence means an operator is applied before any lower-precedence operator. Operators with the same precedence are evaluated left-to-right in C++.

3.3 Control Structures

Unless something special happens, a program executes sequentially. When we want something special to happen, we use a control structure. Control structures provide two basic functions: selection and repetition.

3.4 Selection

A selection control structure chooses among alternative courses of action. There must be some condition that determines whether or not an action occurs.

C++ selection structures: if, if/else, switch.

The if statement

if (condition)
    action;

Conditions

The condition used in an if is a Boolean value — either true or false. In C++:

  • the value 0 is false
  • anything else is true
if (1)      cout << "I am true!\n";    // prints
if (1 - 1)  cout << "I am false!\n";   // does not print

Typically a condition is built using relational and equality operators. These operators have the values true (1) and false (0). So x == x has the value true, and 7 <= 3 has the value false.

if (foo)              cout << "foo is not zero\n";
if (grade >= 90)      lettergrade = 'A';
if (lettergrade == 'F') cout << "The system has failed you\n";
Common Mistake It is easy to mix up the assignment operator = with the equality operator ==. 
if (grade = 100)   // ASSIGNMENT — always true (100 is non-zero)!
    cout << "your grade is perfect!\n";
This assigns 100 to grade and then tests 100, which is true.

Compound statements

Inside an if you can put a single statement or a compound statement. A compound statement starts with {, ends with }, and can contain a sequence of statements (or control structures).

if (grade >= 90) {
    cout << "Nice job - you get an A\n";
    acnt = acnt + 1;
}

A word about style

C++ does not care about whitespace (including newlines), so you can arrange your code in many ways. There are a couple of often-used styles. All that is important is that the code is easy to understand and change.

if (foo > 10) { x = y + 100; cout << x; }

    x = y + 100;

}

if(foo>10){x=y+100;cout<<x;}

    statement;

The for loop

for (initialization; condition; update)
    do_something;
  • initialization — a statement executed at the beginning of the loop (and never again).
  • The body is executed as long as the condition is true.

3.6 Complex Conditions

You can build complex conditions involving more than one relational or equality operator using the logical operators:

  • && — AND
  • || — OR
  • ! — NOT (unary)

The && operator

&& is a boolean operator, so the value of an expression is true or false.

(cond1 && cond2)   is true only if BOTH cond1 and cond2 are true.
lettergrade = 'A';
cutoff = 90;
while ((grade < cutoff) && (lettergrade != 'F')) {
    lettergrade++;
    cutoff -= 10;
}

The || operator

|| is a boolean operator. (cond1 || cond2) is true if either cond1 or cond2 is true.

if ((test1 == 0) || (test2 == 0))
    cout << "You missed a test!\n";

if ((hw1 == 0) || (hw2 == 0))
    cout << "You missed a homework!\n";

The ! operator

The ! operator is a unary boolean operator — it has only one operand. It negates its operand. (!condition) is true only when condition is false.

bool done = false;
int i = 1;

while (!done) {
    cout << "i is " << i << endl;
    i++;
    if (i == 100) done = true;
}

04Constructors

4.1 The Problem: Zero Initialisation

Consider a class with private data members and no constructor:

class rectangle {
  private:
    float height;
    float width;
    int   xpos;
    int   ypos;
};

void main() {
    rectangle rc1;
    rectangle rc2;
    rectangle rc3;
    rectangle rc4;
}

Every object is created, but its data members contain garbage. If we add an init() function, the programmer must remember to call it for every object:

class rectangle {
  private:
    float height, width;
    int   xpos, ypos;
  public:
    void init();
};

void rectangle::init() {
    height = 10;  width = 20;
    xpos   = 0;   ypos  = 0;
}

void main() {
    rectangle rc1;
    rc1.init();        // easy to forget!
}
Motivation If a normal member function is defined for zero initialisation, we would need to invoke it for each object separately — very inconvenient and error-prone. The constructor solves this: initialisation happens automatically at the moment of creation.

4.2 The Constructor

class rectangle {
  private:
    float height, width;
    int   xpos, ypos;
  public:
    rectangle();       // constructor
    void draw();       // draw member function
};

rectangle::rectangle() {
    height = 10;  width = 20;
    xpos   = 0;   ypos  = 0;
}

void main() {
    rectangle rc1;     // constructor runs automatically
}

What is a constructor?

  • A special member function that initialises the objects of its class.
  • Invoked whenever an object of its class is created.
  • It is called a constructor because it constructs the values of the data members of the class.

A constructor has:

  1. the same name as the class itself
  2. no return type
Guarantee When the class contains a constructor, an object created by the class will be initialised automatically. rectangle rc; not only creates the object rc but also initialises its data members to the given values. There is no need to write any statement to invoke the constructor.

4.3 Special Characteristics of Constructors

  • They should be declared in the public section.
  • They do not have return types — not even void — and therefore cannot return values.
  • They cannot be inherited, though a derived class can call a base class constructor.
  • They can have default arguments.
  • Constructors cannot be virtual.
  • We cannot refer to their addresses.

4.4 Types of Constructor

4.5 Default Constructor

The default constructor is the constructor that takes no arguments. It has no parameters, but a programmer can write initialisation statements inside it.

A default constructor is very important for initialising object members. Even if we do not define a constructor explicitly, the compiler automatically provides a default constructor implicitly.

Notation The default constructor for class A is written A::A().

4.6 Parameterised Constructors

A default constructor has no parameters, but programmers can add and use parameters within a constructor if required. This helps assign initial values to an object at the time of creation.

class rectangle {
  private:
    float height, width;
    int   xpos, ypos;
  public:
    rectangle(float, float);            // 2-arg constructor
    rectangle(float, float, int, int);  // 4-arg constructor
};

rectangle::rectangle(float h, float w) {
    height = h;  width = w;
    xpos   = 0;  ypos  = 0;
}

rectangle::rectangle(float h, float w, int x, int y) {
    height = h;  width = w;
    xpos   = x;  ypos  = y;
}

void main() {
    rectangle rc1(30.0, 25.0);
    rectangle rc2(5.5, 9.0);
    rectangle rc3(10.0, 20.0, 100, 150);
    rectangle rc4;                       // needs a default constructor
}

Implicit vs explicit call

void main() {
    rectangle rc(3.0, 2.0);              // implicit call
    rectangle rc1 = rectangle(3.0, 2.0); // explicit call
}

4.7 Overloading Constructors

You can have more than one constructor in a class, as long as each has a different list of arguments.

class rectangle {
  private:
    float height, width;
    int   xpos, ypos;
  public:
    rectangle(float, float);  // constructor
    rectangle();              // another constructor
    void draw();
};

rectangle::rectangle() {
    height = 10;  width = 10;
    xpos   = 0;   ypos  = 0;
}

void main() {
    rectangle rc1(3.0, 2.0);
    rectangle rc2();
    rc1.draw();
    rc2.draw();
}
Watch Out rectangle rc2(); is parsed as a function declaration (the "most vexing parse"), not an object creation. Write rectangle rc2; to create an object with the default constructor.

4.8 Composition — Objects as Members of Classes

A class may have objects of other classes as members.

class properties {
  private:
    int color;
    int line;
  public:
    properties(int, int);   // constructor
};

properties::properties(int c, int l) {
    color = c;
    line  = l;
}

class rectangle {
  private:
    float height, width;
    int   xpos, ypos;
    properties pr;          // another object as a member
  public:
    rectangle(float, float, int, int);
    void draw();
};

// Member initialiser list: pr is constructed BEFORE the body runs
rectangle::rectangle(float h, float w, int c, int l) : pr(c, l) {
    height = h;  width = w;
    xpos   = 0;  ypos  = 0;
}

void main() {
    rectangle rc(3.0, 2.0, 1, 3);
}
Order Rule Members are constructed in the order they are declared in the class, not in the order they appear in the member initialiser list. Here pr is constructed before the constructor body runs.

05Destructor, Copy Constructor & Shallow vs Deep Copy

5.1 Dynamic Constructor

When allocation of memory is done dynamically using the dynamic memory allocator new inside a constructor, it is known as a dynamic constructor. Using this, we can dynamically initialise the objects.

#include <iostream>
using namespace std;

class dyncons {
    int *p;
  public:
    dyncons() {                 // default dynamic constructor
        p = new int;
        *p = 10;
    }
    dyncons(int v) {            // parameterised dynamic constructor
        p = new int;
        *p = v;
    }
    int display() { return *p; }
};

int main() {
    dyncons dc1;
    dyncons dc2(199);
    cout << "The value of object dc1's p is:" << dc1.display();
    cout << "\nThe value of object dc2's p is:" << dc2.display();
    return 0;
}

/* OUTPUT
   The value of object dc1's p is: 10
   The value of object dc2's p is: 199  */

5.2 What is a Destructor?

  • A member function that deletes an object.
  • Called automatically when the object goes out of scope:
    1. the function ends
    2. the program ends
    3. a block containing temporary variables ends
    4. a delete operator is called

A destructor has:

  1. the same name as the class but preceded by a tilde (~)
  2. no arguments and returns no value
class string {
  private:
    char *s;
    int   size;
  public:
    string(char *);    // constructor
    ~string();         // destructor
};

string::string(char *c) {
    size = strlen(c);
    s = new char[size + 1];
    strcpy(s, c);
}

string::~string() {
    delete [] s;       // release the heap memory
}

Comments on destructors

  • If you do not specify a destructor, the compiler generates a default destructor for you.
  • When a class contains a pointer to memory you allocate, it is your responsibility to release the memory before the class instance is destroyed.

5.3 Copy Constructor

A member function that initialises an object using another object of the same class.

General prototype:

class_name (const class_name &);
class rectangle {
  private:
    float height, width;
    int   xpos, ypos;
  public:
    rectangle(float, float);          // constructor
    rectangle(const rectangle &);    // copy constructor
    void draw();
};

rectangle::rectangle(const rectangle &old_rc) {
    height = old_rc.height;
    width  = old_rc.width;
    xpos   = old_rc.xpos;
    ypos   = old_rc.ypos;
}

void main() {
    rectangle rc1(3.0, 2.0);   // use constructor
    rectangle rc2(rc1);        // use copy constructor
    rectangle rc3 = rc1;       // alternative syntax for copy constructor
}

5.4 Why Copy Constructors Matter — Shallow vs Deep Copy

Key Rule In the absence of a copy constructor, the C++ compiler builds a default copy constructor for each class, which performs a memberwise (bitwise) copy between objects. Default copy constructors work fine unless the class contains pointer data members.

The problem — a broken class

#include <iostream.h>
#include <string.h>

class string {
  private:
    char *s;
    int   size;
  public:
    void print();
    void copy(char *);
};

void string::print() { cout << s << endl; }
void string::copy(char *c) { strcpy(s, c); }

void main() {
    string str1("George");
    string str2 = str1;   // DEFAULT copy constructor — bitwise copy

    str1.print();         // George
    str2.print();         // George

    str2.copy("Mary");    // writes through the SHARED pointer

    str1.print();         // Mary  <-- NOT what we wanted!
    str2.print();         // Mary
}

Consequences of shallow copy

  • str2 uses the same piece of allocated memory that str1 is using, instead of allocating its own.
  • If a destructor is written, the same memory will be freed twice when str1 and str2 are destroyed — a double free error.
  • Changing one object changes the other — not the desired outcome.

The fix — deep copy constructor

class string {
  private:
    char *s;
    int   size;
  public:
    string(char *);                 // constructor
    ~string();                      // destructor
    string(const string &);        // copy constructor
    void print();
    void copy(char *);
};

string::string(const string &old_str) {
    size = old_str.size;
    s = new char[size + 1];         // allocate a NEW buffer
    strcpy(s, old_str.s);           // copy the CONTENT
}

void main() {
    string str1("George");
    string str2 = str1;

    str1.print();   // George
    str2.print();   // George

    str2.copy("Mary");

    str1.print();   // George   <-- correct!
    str2.print();   // Mary
}
Note The same correct behaviour can be obtained by overloading the assignment operator operator=. This is often called the Rule of Three: if you need a destructor, a copy constructor, or a copy assignment operator, you probably need all three.

5.5 Object Lifecycle Order

When a derived-class object is created:

  1. Space is allocated (on the stack or heap) for the full object — enough for inherited base members plus derived members.
  2. The base class constructor is called to initialise the inherited members.
  3. The derived class constructor is then called to initialise the added members.
  4. The derived-class object is now usable.

When the object is destroyed:

  1. The derived class destructor is called first.
  2. Then the base class destructor is called.
  3. Finally the allocated space for the full object is reclaimed.
Remember Construction flows base → derived.
Destruction flows derived → base.

06The C/C++ Memory Map

6.1 Program Segments

The memory a program uses is divided into several areas, called segments:

SegmentContents
Code segment (text segment)Where the compiled program sits in memory. Typically read-only.
bss segment (uninitialised data)Zero-initialised global and static variables.
Data segment (initialised data)Initialised global and static variables.
Call stackFunction parameters, local variables, and other function-related information.
Heap (free store)Dynamically allocated variables.
BSS bss is used by many compilers and linkers for the portion of an object file or executable containing statically allocated variables that are not explicitly initialised to any value. It is often referred to as the "bss section" or "bss segment".

6.2 The Heap Segment

  • Keeps track of memory used for dynamic memory allocation.
  • In C++, when you use the new operator to allocate memory, that memory is allocated in the application's heap segment.
  • When a dynamically allocated variable is deleted, the memory is returned to the heap and can then be reassigned as future allocation requests are received.
int *p = new int(42);   // p points into the heap
delete p;               // memory returned to the heap

6.3 The Call Stack Segment

  • Holds the memory used for the call stack.
  • When the application starts, main() is pushed onto the call stack by the operating system. The program then begins executing.
  • When a function call is encountered, the function is pushed onto the call stack. When the current function ends, that function is popped off the call stack.
  • By looking at the functions pushed on the call stack, we can see all the functions that were called to get to the current point of execution.
int display(int x) {
    // b
    return x;
}   // display is popped off the call stack here

int main() {
    // a
    display(5);   // display is pushed on the call stack here
    // c
    return 0;
}

6.4 Stack Overflow

  • The stack has a limited size and can only hold a limited amount of information. On Windows the default stack size is about 1 MB; on some Unix machines it can be as large as 8 MB.
  • If the program tries to put too much information on the stack, stack overflow results.
  • Stack overflow happens when all the memory in the stack has been allocated — further allocations begin overflowing into other sections of memory.
  • It is generally the result of allocating too many variables on the stack, and/or making too many nested function calls.
  • On modern operating systems, overflowing the stack generally causes the OS to issue an access violation and terminate the program.

Example 1 — huge local array

#include <iostream>

int main() {
    int stack[10000000];       // ~40 MB array on a ~1 MB stack
    std::cout << "hi";
    return 0;
}

This program tries to allocate a huge array on the stack. Because the stack is not large enough, the array allocation overflows into memory the program is not allowed to use.

Example 2 — infinite recursion

void display() { display(); }

int main() {
    display();
    return 0;
}

A stack frame is pushed every time display() is called. Since display() calls itself infinitely, the stack eventually runs out of memory.

6.5 Memory Allocation for Objects

class book {
    string title;
    int    price;
    void getdata();
    void putdata();
};

int main() {
    book book1, book2, book3;
    int  i;
    return 1;
}

Key rules

  • Before using a member of a class, it is necessary to allocate the required memory space to that member.
  • Data members and member functions are allocated differently, even though both belong to the same class.
  • Memory for data members is allocated only when an object is declared — not when the data members are declared inside the class.
  • Since a single data member can have different values for different objects at the same time, every object has an individual copy of all the data members.
  • Memory for member functions is allocated only once, when the class is defined. There is a single copy of each member function, shared among all objects.

Where does an object live?

  • If Book has members that are allocated only on the stack, then the whole object is on the stack.
  • But Book may have pointer members and Book's constructor may allocate memory for them on the heap.
  • Then some members are on the heap, some on the stack.
class book {
    string  title;
    int     price;
    string *publisher;   // pointer member — may point to heap memory
    void getdata();
    void putdata();
};

int main() {
    book book1, book2, book3;   // book1/2/3 on stack,
                                // publisher targets possibly on heap
    return 1;
}

07Friend Functions and Friend Classes

7.1 Motivation

Normally, private members cannot be accessed from outside the class. That is, a non-member function cannot access the private data of the class. However, there could be a situation where we would like two classes to share a particular function. In such situations C++ allows the common function to be made friendly with both classes, thereby allowing the function to access the private data of these classes. Such a function need not be a member of these classes.

7.2 Syntax

class ABC {
    int p;
  public:
    void display();
    friend void xyz(void);   // declaration
};

class A1 {
    ...
  public:
    ...
    friend void xyz(void);
};

class A2 {
    ...
  public:
    ...
    friend void xyz(void);
};

The function is then defined elsewhere as a normal C++ function:

void xyz() {
    // can now access private members of ABC, A1, A2
}

7.3 Rules for Friend Functions

  • The function declaration should be preceded by the keyword friend.
  • The function is defined elsewhere in the program like a normal C++ function.
  • The function definition does not use either the keyword friend or the scope operator ::.
  • The function can be declared as a friend in any number of classes.

7.4 Characteristics of Friend Functions

  • It is not in the scope of the class to which it has been declared as friend.
  • Since it is not in the scope of the class, it cannot be called using the object of that class.
  • It can be invoked like a normal function without the help of any object.
  • It can be declared in the public or private part without affecting its meaning.
  • Unlike a member function, it cannot access member names directly; it has to use an object name and the dot membership operator with each member name (e.g. A.x).
  • Usually, it has objects as arguments.

7.5 Cautions on Friendship

  1. Friends should be used only for a limited purpose. If too many functions or external classes are declared as friends of a class with protected or private data, it lessens the value of encapsulation of separate classes in object-oriented programming.
  2. Friendship is not mutual. If class A is a friend of B, then B does not automatically become a friend of A.
  3. Friendship is not inherited.
  4. The concept of friends is not there in Java.

7.6 Ways to Declare a Friend

A friend function can be:

  • (a) a global function
  • (b) a method of another class

7.7 Global Friend — Example 1 (mean)

class sample {
    int a, b;
  public:
    void set() { a = 25; b = 55; }
    friend int mean(sample);
};

int mean(sample s) {
    return (s.a + s.b) / 2;    // accesses private members
}

int main() {
    sample s;
    s.set();
    cout << mean(s) << endl;
    return 0;
}

7.8 Global Friend — Example 2 (max of two classes)

class abc;    // forward declaration

class xyz {
    int x;
  public:
    void setx(int px) { x = px; }
    friend int max(xyz, abc);
};

class abc {
    int a;
  public:
    void seta(int pa) { a = pa; }
    friend int max(xyz, abc);
};

int max(xyz x1, abc a1) {
    if (x1.x > a1.a) return x1.x;
    else              return a1.a;
}

void main() {
    xyz xx;
    abc aa;
    xx.setx(100);
    aa.seta(1000);
    cout << max(xx, aa);
}

7.9 Global Friend — Example 3 (swap between two classes)

class abc;

class xyz {
    int x;
  public:
    void set(int p) { x = p; }
    void show()     { cout << x << endl; }
    friend void swap(xyz &, abc &);
};

class abc {
    int a;
  public:
    void set(int p) { a = p; }
    void show()     { cout << a << endl; }
    friend void swap(xyz &, abc &);
};

void swap(xyz &xx, abc &aa) {
    int temp;
    temp = xx.x;
    xx.x = aa.a;
    aa.a = temp;
    cout << xx.x << aa.a << endl;
}

void main() {
    xyz x1;
    abc a1;
    a1.set(100);
    x1.set(500);

    cout << "Before swap" << endl;
    x1.show();   // 500
    a1.show();   // 100

    cout << "After swap" << endl;
    swap(x1, a1);

    cout << "From main" << endl;
    x1.show();   // 100
    a1.show();   // 500
}

7.10 Friend as a Member Function of Another Class

Member functions of one class can be friend functions of another class. In such cases they are defined using the scope resolution operator, as shown:

class X {
  public:
    int fun1();
};

class Y {
  public:
    friend int X::fun1();   // a member of X is a friend of Y
};

Full example

class B;   // forward declaration

class A {
  public:
    void showB(B &);
};

class B {
  private:
    int br;
  public:
    B() { br = 0; }
    friend void A::showB(B & x);
};

void A::showB(B & x) {
    // showB() is a friend of B, so it can access B's private members
    cout << "B::br = " << x.br;
}

int main() {
    A a;
    B x;
    a.showB(x);
    return 0;
}

7.11 Friend Class

We can also declare all the member functions of one class as friend functions of another class. In such cases, the class is called a friend class.

class Z {
  public:
    friend class X;    // all of X's members are friends of Z
};

Full example

class XYZ {
  private:
    char ch  = 'A';
    int  num = 11;
  public:
    friend class ABC;
};

class ABC {
  public:
    void disp(XYZ obj) {
        cout << obj.ch  << endl;
        cout << obj.num << endl;
    }
};

int main() {
    ABC obj;
    XYZ obj2;
    obj.disp(obj2);   // ABC is a friend of XYZ → can access private members
    return 0;
}
Summary Friend function → one function gets access.
Friend class → every member function of another class gets access.
Friendship is a one-way, non-inherited, non-mutual grant of access.

08Function Overloading

8.1 Definition

Two or more functions can share the same name as long as either the type of their arguments differ, or the number of their arguments differs — or both. This reduces the complexity of a program by allowing related operations to be referred to by the same name.

8.2 Overloading by Differing Data Type of Argument

// Declarations
int    add(int a, int b);
int    add(int a, int b, int c);
double add(double x, double y);
double add(int p, double q);
double add(double p, int q);

// Function calls
cout << add(5, 10);        // prototype 1
cout << add(15, 10.0);     // prototype 4
cout << add(12.5, 7.5);    // prototype 3
cout << add(15, 10, 5);    // prototype 2
cout << add(0.75, 5);      // prototype 5

8.3 Overloading by Differing Number of Arguments

void f1(int a)          { }
void f1(int a, int b)   { }

main() {
    f1(10);
    f1(10, 20);
}
Caution Return type alone is not sufficient difference to allow function overloading. 
int    f1(int a);
double f1(int a);   // ILLEGAL — ambiguous
This fragment is incorrect because it is inherently ambiguous. The compiler has no way of knowing which version of f1() to call.

8.4 Resolution of Calls to Overloaded Functions

Calls to overloaded functions and operators are resolved by:

  • Finding all possible matches based on passed arguments
    • may involve type promotion
    • may involve instantiating templates
  • Finding the "best match" among those possible matches.
Signature The signature does not include the return type. Which might not help even if it did, since calls may ignore the result. So overloading cannot be resolved by return type alone. The compiler generates an error if the call cannot be resolved.

8.5 The Matching Algorithm (in order)

  1. The compiler first tries to find an exact match in which the number and types of actual arguments are the same, and uses that function.
  2. If an exact match is not found, the compiler uses integral promotions on the actual arguments — such as char to int, float to double — to find the match.
  3. When either of those fails, the compiler tries to use the built-in conversions on the actual arguments and then uses the function whose match is unique. If the conversion is possible to have multiple matches, the compiler generates an error message.
  4. If all of the above fail, the compiler tries user-defined conversions in combination with integral promotions and built-in conversions to find the match.
  5. Otherwise: error.

Ambiguity example

long   square(long n);
double square(double x);

square(10);   // ERROR: int can convert to BOTH long and double

Another example

class A {
  public:
    int  add(int i, int j);
    long add(long m, long n);
};

int main() {
    int a = 7;
    int b = 8;
    int c = add(a, b);   // exact match: add(int, int)
    return 0;
}
Practice Problems 1. Overload a constructor to implement a Date class.
2. Overload area() and volume() to implement various shapes.

8.6 The this Pointer

Every non-static member function receives a hidden pointer called this, which points to the object on which the member function was invoked. It is how a member function knows which object's data members to use.

class Sample {
    int m;
  public:
    Sample &set(int m) {
        this->m = m;   // disambiguates parameter from member
        return *this;  // enables method chaining
    }
};

09Operator Overloading

9.1 The Need

int   i, j, k;      // integers
float m, n, p;      // floats

k = i + j;          // integer addition and assignment
p = m + n;          // floating addition and assignment

The compiler overloads the + operator for built-in integer and float types by default. But what about user-defined types?

class Complex {
  public:
    int real, img;
    void accept();
    void display();
};

Complex c1, c2, c3;
c3 = c1 + c2;      // does the compiler know how to add two Complex objects?

We want object operations to look like individual variable operations, using operator functions.

9.2 Definition

  • A programmer can use some operator symbols to define special member functions of a class.
  • Provides convenient notation for object behaviours.
  • Uses traditional operators with user-defined objects.
  • A straightforward and natural way to extend C++.
  • Requires great care: when overloading is misused, the program becomes difficult to understand.

9.3 Restrictions on Operator Overloading

Operators that can be overloaded

+   -   *   /   %   ^   &   |   ~   !   =   <   >
+=  -=  *=  /=  %=  ^=  &=  |=  <<  >>  >>= <<=
==  !=  <=  >=  &&  ||  ++  --  ->*  ->  []  ()
new delete new[] delete[]

Rules

  • Arity (number of operands) cannot be changed. Unary operators remain unary, binary operators remain binary.
  • Operators &, *, + and - each have unary and binary versions. Unary and binary versions can be overloaded separately.
  • No new operators can be created — use only existing operators.
  • Built-in types cannot be changed — you cannot change how two integers are added.

9.4 Implementing Operator Overloading

Two ways:

  • Implemented as member functions
  • Implemented as non-member or friend functions — the operator function may need to be declared as a friend if it requires access to protected or private data.

Translation rule

Here operator is a function and @ is one of the C++ operator symbols. Examples: operator+, operator-, operator*, operator/.

9.5 Rules for Operator Functions

  • The leftmost operand must be an object (or reference to an object) of the class.
  • If the left operand is of a different type, the operator function must be a non-member function.
  • A non-member operator function must be a friend if private or protected members of that class are accessed directly.

9.6 Form 1 — Non-static Member Function (one argument)

class distance {
    int km, mt;
  public:
    distance operator+(distance &);
};

distance a, b, c;
c = a + b;            // c = a.operator+(b);

distance distance::operator+(distance &d) {
    distance res;
    res.mt = mt + d.mt;
    res.km = km + d.km;
    return res;
}

Subtraction variant

class distance {
    int km, mt;
  public:
    distance operator-(distance &);
};

distance a, b, c;
c = a - b;            // c = a.operator-(b);

distance distance::operator-(distance &d) {
    distance res;
    res.mt = mt - d.mt;
    res.km = km - d.km;
    return res;
}

9.7 Form 2 — Non-member Friend Function (two arguments)

class distance {
    int km, mt;
  public:
    friend distance operator-(distance &, distance &);
};

distance d3, d4, d5;
d3 = d5 - d4;                    // d3 = operator-(d5, d4);

distance operator-(distance &d2, distance &d1) {
    distance res;
    res.mt = d2.mt - d1.mt;
    res.km = d2.km - d1.km;
    return res;
}

Mixed-type friend operator (int × distance)

class distance {
    int km, mt;
  public:
    friend distance operator*(int, distance &);
};

distance d4, d5;
d5 = 2 * d4;                     // d5 = operator*(2, d4);

distance operator*(int a, distance &d) {
    distance d1;
    d1.km = a * d.km;
    d1.mt = a * d.mt;
    return d1;
}
Why Friend Here? The leftmost operand is int, not a distance object. So the operator cannot be a member function of distance. It must be a non-member — and it needs friend access to reach the private km and mt.

9.8 Overloading Stream Insertion & Stream Extraction

Need

class distance { int km, mt; };

int main() {
    distance d1;
    cin  >> d1;
    cout << d1;
}

C++ is able to input and output built-in data types using the stream extraction operator >> and the stream insertion operator <<. These operators can also be overloaded to perform input and output for user-defined types like an object.

Rules

  • Overloaded << and >> operators must have a left operand of type ostream & and istream & respectively.
  • They must be non-member functions — because the left operand is not an object of the class.
  • They must be friend functions if they access private data members.
class distance {
    int km, mt;
  public:
    friend istream &operator>>(istream &, distance &);
    friend ostream &operator<<(ostream &, distance &);
};

istream &operator>>(istream &din, distance &d) {
    din >> d.km;
    din >> d.mt;
    return din;
}

ostream &operator<<(ostream &dout, distance &d) {
    dout << d.km << "Km";
    dout << "+";
    dout << d.mt << "m" << endl;
    return dout;
}
Why return the stream? Returning istream& / ostream& allows chaining: cin >> a >> b; and cout << x << y;

9.9 Overloading Unary Operators

A unary operator operates on a single operand and returns a new value. Some unary operators are:

  • ++ (increment)
  • -- (decrement)
  • - (unary minus)
  • ! (NOT)

For primitive types like int and string, these are already overloaded. Let us see how to overload a unary operator for a user-defined class.

Prefix vs postfix

The compiler distinguishes them by a dummy int parameter used only for postfix.

class Sample {
    int m;
  public:
    Sample()      { m = 0; }
    Sample(int x1){ m = x1; }

    void   operator++();       // PREFIX  ++ function
    Sample operator++(int);    // POSTFIX ++ function
    void   operator=(Sample);
    void   display();
};
// prefix ++ : increments and returns void here
void Sample::operator++() {
    m = m + 10;
}

// postfix ++ : accepts a dummy int, returns a copy
Sample Sample::operator++(int x) {
    m = m + 50;
    return *this;   // returns current object
}

void Sample::operator=(Sample s) {
    m = s.m;
}

void Sample::display() {
    cout << "m=" << m << endl;
}
int main() {
    cout << "Unary Operator Overloading" << endl;

    Sample s1(10);
    s1.display();     // m=10

    ++s1;             // prefix
    s1.display();     // m=20

    Sample s2(100);
    s2.display();     // m=100

    s2++;             // postfix
    s2.display();     // m=150

    s1 = s2;
    s1.display();     // m=150

    return 0;
}
The Dummy int The int parameter passed to the postfix version is never used. It exists purely so the compiler can tell the prefix and postfix forms apart. Every non-static member function by default has a this pointer; the postfix function returns *this.

9.10 More About 'Friend'

  • Friend declarations introduce extra coupling between classes.
  • Once an object is declared as a friend, it has access to all non-public members as if they were public.
  • Access is unidirectional: if B is a friend of A, B can access A's non-public members; A cannot access B's.
  • A friend function of a class is defined outside that class's scope.
  • The major use of friends is to provide more efficient access to data members, and to accommodate operator functions with easy access to private data members.
  • Friends can access everything, which defeats data hiding — use them carefully.
  • Friends have permission to change the internal state from outside the class. Prefer member functions instead of friends to change state.

10Inheritance

10.1 The Concept

Objects are often defined in terms of hierarchical classes with a base class and one or more levels of classes that inherit from the classes above them in the hierarchy.

  • Each level inherits the members of the above level.
  • Vehicle is the base class. 2-W and 4-W are derived from Vehicle.
  • Bike, Scooter are derived from 2-W; Bus, Car from 4-W.

10.2 Defining a Class Hierarchy

Syntax:

class DerivedClassName : access-level BaseClassName
{
    // members
};
  • access-level specifies the type of derivation — private by default, or public, or protected.
  • Any class can serve as a base class.
  • Thus a derived class can also be a base class (multilevel inheritance).

10.4 Access Control in the Derived Class — An Example

class Person {
  protected:
    int x, y;
  public:
    void set(int a, int b);
  private:
    int z;
};

class daughter : public Person {
  private:
    double a;
  public:
    void foo();
};

void daughter::foo() {
    x = y = 20;              // OK — protected members are accessible
    set(5, 10);              // OK — public method
    cout << "value of a " << a << endl;
    z = 100;                 // ERROR — z is a private member of Person
}

So daughter can access 3 of the 4 inherited members: x, y, and set() — but not z.

10.5 The "Is-A" Relationship

  • Public inheritance models an "Is-A" or "Is-Type-Of" relationship.
    • Rectangle is a shape
    • Orange is a fruit
    • Manager is an employee
    • Rectangle is a Polygon
    • Circle is an Ellipse
  • Use inheritance only when you mean such a relationship in your program.

10.6 What Exactly Is Inherited?

  • In principle, every member of a base class is inherited by a derived class — with different access permission.
  • Technically, in C++ the object of a derived class contains a portion for the base class(es).
  • Exceptions — things that are not inherited:
    • Constructors and destructors
    • The assignment operator =()
    • And so on…
    These are class-specific.

10.7 Types of Inheritance

There are five different inheritances supported in C++:

  1. Simple / Single
  2. Multilevel
  3. Hierarchical
  4. Multiple
  5. Hybrid

A derived class can override methods defined in its parent class. With overriding:

    void set(int a, int b, double c) {
        Point::set(a, b);   // call the base version explicitly
        r = c;
    }
    void print();
};

Circle C;
C.set(10, 10, 100);   // from class Circle
C.foo();              // from base class Point
C.print();            // from class Circle

10.10 The Diamond Problem & Virtual Base Classes

Consider this hierarchy:

class D { public: int i; };
class A : public D { public: int j; };
class B : public D { public: int k; };
class C : public A, public B { public: int v; };

void main() {
    C ob;
    ob.i = 10;    // AMBIGUOUS! Which D::i?
    ob.j = 20;
    ob.k = 30;
}

The solution — virtual base classes

class D { public: int i; };

class A : virtual public D { public: int j; };
class B : virtual public D { public: int k; };
class C : public A, public B { public: int v; };

Now C contains only one copy of D, and ob.i = 10; is unambiguous.

Full example — Person / Faculty / Student / TA

#include <iostream>
using namespace std;

class Person {
  public:
    Person(int x) { cout << "Person::Person(int) called" << endl; }
    Person()      { cout << "Person::Person() called"    << endl; }
};

class Faculty : virtual public Person {
  public:
    Faculty(int x) : Person(x) {
        cout << "Faculty::Faculty(int) called" << endl;
    }
};

class Student : virtual public Person {
  public:
    Student(int x) : Person(x) {
        cout << "Student::Student(int) called" << endl;
    }
};

class TA : public Faculty, public Student {
  public:
    TA(int x) : Student(x), Faculty(x), Person(x) {
        cout << "TA::TA(int) called" << endl;
    }
};

int main() {
    TA ta1(30);
}

Output:

Person::Person(int) called
Faculty::Faculty(int) called
Student::Student(int) called
TA::TA(int) called
Why the order? When a class has a virtual base, the virtual base is constructed first. Then non-virtual bases are constructed in declaration order (Faculty then Student), and finally the most-derived class (TA).

Also, when a virtual base exists, the most-derived class is responsible for calling the virtual base's constructor — which is why TA writes Person(x) in its initialiser list.
Without virtual Without virtual, the constructor and destructor of Person would be called twice for a single TA object, and ta1 would have two copies of all members of Person, causing ambiguities.

11Polymorphism, Virtual Functions & Abstract Classes

11.1 Definition

Polymorphism is the specific implementation of a single message, which is sent from one object to another object, including many different objects, which are related to the base object by an "is-a" relationship.

11.2 Types of Polymorphism

  • Static (compile-time) polymorphism — achieved through function overloading, operator overloading, and templates.
  • Dynamic (run-time) polymorphism — achieved through virtual functions and inheritance.

11.3 Static Polymorphism

class vehicle {
  public:
    void stop() { cout << "Vehicle is stopped\n"; }
};

class wheel_2 : public vehicle {
  public:
    void stop() { cout << "2 wheeler is stopped\n"; }
};

class wheel_4 : public vehicle {
  public:
    void stop() { cout << "4 wheeler is stopped\n"; }
};

void main() {
    wheel_2 v1;
    v1.stop();         // calls wheel_2::stop()

    wheel_4 v2;
    v2.stop();         // calls wheel_4::stop()

    vehicle *p;
    p = &v1;
    p->stop();         // calls vehicle::stop()  <-- static binding!
}

Output:

2 wheeler is stopped
4 wheeler is stopped
Vehicle is stopped

In static polymorphism, the function is invoked by the type of the object (or pointer). So v1 calls wheel_2::stop(), v2 calls wheel_4::stop(), and p calls vehicle::stop() — because at compile time the compiler knows the binding.

11.4 Dynamic Object Creation — Assignment Rules

Rule: Expected <= Provided. A base-class pointer can point to a derived-class object, but not vice versa.

11.5 The Problem with Pointers — Dynamic Polymorphism

class vehicle {
  public:
    void stop() { cout << "Vehicle is stopped\n"; }
};

class wheel_2 : public vehicle {
  public:
    void stop() { cout << "2 wheeler is stopped\n"; }
};

class wheel_4 : public vehicle {
  public:
    void stop() { cout << "4 wheeler is stopped\n"; }
};

void main() {
    vehicle *v[2];
    wheel_2 p1;
    wheel_4 p2;
    Vehicle p3;

    v[0] = &p1;
    v[1] = &p2;
    v[2] = &p3;

    for (int i = 0; i < 2; i++) {
        v[i]->stop();
    }
}

Output:

Vehicle is stopped
Vehicle is stopped
Vehicle is stopped
Why? The function call is determined by the type of the pointer, not the type of the object. The pointer is of type vehicle*, so vehicle::stop() is called every time.

11.6 Virtual Functions

The solution is the virtual keyword.

  1. Prefix the virtual keyword in the function declaration.
  2. No change in the function definition. A virtual function of the base class can be redefined in a child class.
  3. No change in the function call.
class vehicle {
  public:
    virtual void stop() { cout << "Vehicle is stopped\n"; }
};

class wheel_2 : public vehicle {
  public:
    void stop() { cout << "2 wheeler is stopped\n"; }
};

class wheel_4 : public vehicle {
  public:
    void stop() { cout << "4 wheeler is stopped\n"; }
};

void main() {
    vehicle *v = new wheel_2;
    v->stop();    // calls wheel_2::stop()  <-- dynamic dispatch
}
Key Rule A virtual function call is determined by the type of object pointed to by the pointer — not by the type of the pointer.

11.7 Properties of Virtual Functions

  • Used to support polymorphism with pointers and references.
  • Declared virtual in a base class.
  • Can be overridden in a derived class.
  • Overriding only happens when signatures are the same. Otherwise it just overloads the function or operator name.
  • Ensures the derived class function definition is resolved dynamically.
  • E.g. ensures that destructors farther down the hierarchy get called (virtual destructors).

11.8 Pure Virtual Functions

Motivating Question Does a vehicle exist? Show me just a vehicle — no answer. In reality, objects of vehicle's derived classes exist, and not objects of the vehicle class itself. So who will invoke vehicle::stop()? Nobody.

So why write the stop() method in the vehicle class? There is no need. But if we remove it from the base class, it will be removed from all the derived classes. We can't remove it, as we require stop() in all the derived classes. However, each derived class has its own implementation of stop(). So we do not require an implementation of stop() in the base class.

Solution: just declare the stop() method in the base class so it will be available to all derived classes — but do not define it:

class vehicle {
  public:
    virtual void stop() = 0;   // pure virtual function
};

11.9 Abstract Classes

  • A class that contains at least one pure virtual method becomes an abstract class.
  • Abstract classes cannot be instantiated — we cannot create objects from abstract classes.
  • However, we can create pointers to the abstract class, and these pointers can be used to point to objects of concrete classes.
Vehicle  V1;      // ILLEGAL — abstract class
Vehicle *v2;      // LEGAL   — pointer to abstract class
  • Derived classes must implement ALL pure virtual methods.
  • If a derived class does not override a pure virtual method, it will itself become abstract.

11.10 Benefits of Polymorphism

  • By treating objects belonging to the same inheritance hierarchy similarly, the resulting code is elegant and easier to understand.
  • Reduces lines of code and avoids multiple switch/case statements for different types.
  • Allows client programs to be written based only on the abstract interfaces (pure virtual functions) of the objects which will be manipulated.
  • Future extensions in the form of new types of objects are easy — as long as the new objects conform to the original interface.
  • For such additions or deletions of classes in the same hierarchy, application code is not affected in a major way.

11.11 Cost of Polymorphism

  • Virtual functions based on run-time polymorphism slow down performance a little, since they involve automatic type checking at run time for function resolution.
  • So use virtual functions for specific run-time behaviour, not everywhere.

12Templates

12.1 The Need for Function Templates

Suppose you need to swap values of different types. Without templates you write:

void Swap(int &a, int &b)       { int c;    c = a; a = b; b = c; }
void Swap(float &a, float &b)   { float c;  c = a; a = b; b = c; }
void Swap(double &a, double &b) { double c; c = a; a = b; b = c; }

int main() {
    int   x = 10, y = 20;
    float p = 20.5, q = 10.5;
    Swap(x, y);
    Swap(p, q);
    return 0;
}

We have written three versions of Swap(). If we need to swap char, short int, long… we would need even more. And if such a function contained 500 lines of code, writing a separate version for each data type would be unacceptable.

12.2 Function Template Syntax

template <class T>
void Swap(T &a, T &b) {
    T c;
    c = a;  a = b;  b = c;
}

int main() {
    int   x = 10, y = 20;
    float p = 20.5, q = 10.5;
    Swap(x, y);    // T = int
    Swap(p, q);    // T = float
    return 0;
}

12.3 Function Templates with Multiple Parameters

template <class T1, class T2>
returntype functionname(argument of type T1, T2) {
    // body of function with types T1, T2
}
template <class T1, class T2>
void display(T1 x, T2 y) {
    cout << x << " " << y << endl;
}

int main() {
    display(2008, "SEIT");   // T1 = int,    T2 = const char*
    display(60.5, 1234);     // T1 = double, T2 = int
}

12.4 Overloading Template Functions

A template function may be overloaded either by another template function or by an ordinary function of the same name. In such cases, overloading is resolved as follows:

  1. Call an ordinary function that has an exact match.
  2. Call the template function that could be created with an exact match.
  3. Try normal overloading resolution to ordinary functions and call the one that matches.
template <class T>
void display(T x) { cout << "Template display " << x << endl; }

void display(int x) { cout << "Explicit display " << x << endl; }

int main() {
    display("SEIT");   // Template display SEIT
    display(1234);     // Explicit display 1234   (non-template preferred)
    return 0;
}

12.5 The Need for Class Templates

Consider a class that adds two integers:

class sum {
    int a, b;
  public:
    sum(int x, int y) { a = x; b = y; }
    void add() { int c; c = a + b; cout << c; }
};

int main() {
    sum s1(10, 20);
    s1.add();
    return 0;
}
// Output: 30

To add two floats, we must rewrite the entire class:

class sum {
    float a, b;
  public:
    sum(float x, float y) { a = x; b = y; }
    void add() { float c; c = a + b; cout << c; }
};

int main() {
    sum s1(10.5, 20.5);
    s1.add();
    return 0;
}
// Output: 31

Now if I want to add two long values, I have to redefine the entire class — and the same is true for every other type of data.

Idea: define a sum class with the data type as a parameter, and use this class to create a new sum object of any data type instead of defining a new class every time. The template mechanism enables us to achieve this goal.

12.6 Class Template Syntax

A class created from a class template is called a template class. The syntax for defining an object of a template class is:

Classname<type> objectname(argumentlist);

12.7 Class Template Example

template <class T>
class sum {
    T a, b;
  public:
    sum(T x, T y) { a = x; b = y; }
    void add() { T c; c = a + b; cout << c; }
};

int main() {
    sum<int>   A1(10, 10);     A1.add();   // 30
    sum<float> A2(10.5, 10.3); A2.add();   // 20.8
    return 0;
}

12.8 Class Template with Multiple Parameters

We can use more than one generic data type in a class template. They are declared as a comma-separated list within the template specification.

template <class T1, class T2>
class classname {
    // body of the class with types T1, T2 wherever appropriate
};

Example

template <class T1, class T2>
class Test {
    T1 a;
    T2 b;
  public:
    Test(T1 x, T2 y) { a = x; b = y; }
    void show() { cout << a << " and " << b << endl; }
};

int main() {
    Test<float, int>  ts1(1.25, 125);
    Test<int, char>   ts2(100, 'S');

    ts1.show();   // 1.25 and 125
    ts2.show();   // 100 and S
    return 0;
}

12.9 Member Function Templates

Normally, we declare functions inside the class and define them outside the class. Member functions of a template class are themselves parameterised by the type argument, and therefore these functions must be defined by function templates.

Syntax:

template <class T>
returntype classname<T> :: functionname(arglist) {
    // function body
}

Example

    T a, b;
  public:
    sum(T x, T y);
    void add();
};

template <class T>
sum<T>::sum(T x, T y) {
    a = x;  b = y;
}

template <class T>

    T c;
    c = a + b;
    cout << c;
}

13File Handling

13.1 Files and Data Communication

  • A file is a collection of related data stored in a particular area on the disk.
  • Programs can be designed to perform read and write operations on these files.
  • A program involves either or both of the following kinds of data communication:
    • Data transfer between the console unit and the program.
    • Data transfer between the program and a disk file.

13.2 C++ Stream Classes for Files

13.3 Opening and Closing a File

A file can be opened using two ways:

  1. Using the constructor function of the class.
  2. Using the member function open() of the class.

Method 1 — Using the constructor

  • The filename is used to initialise the file stream object.
  • Create a filestream object to manage the stream using the appropriate class: ofstream for output, ifstream for input.
  • Initialise the file object with the desired filename.
ofstream outfile("results");   // output only
ifstream infile("data");       // input only

The first statement creates outfile as an ofstream object that manages the output stream. This opens the file results and attaches it to the output stream outfile. The second declares infile as an ifstream object and attaches it to the file data for reading input.

outfile << "TOTAL";
outfile << sum;

infile >> number;
infile >> string;

We can use the same file for reading and writing data — but we must close it in between:

ofstream outfile("salary");
outfile.close();

ifstream infile("salary");
infile.close();

Method 2 — Using the open() method

The function open() can be used to open multiple files that use the same stream object.

Filestream-class streamobject;
streamobject.open("filename");

// example
ofstream outfile;
outfile.open("data1");
outfile.close();
outfile.open("data2");
outfile.close();

13.4 Detecting End of File

Detection of the end-of-file condition is necessary for preventing any further attempt to read data from the file.

while (fin) {
    // ...
}

An ifstream object such as fin returns a value 0 if any error occurs in the file operation, including the end-of-file condition. Thus the while loop terminates when fin returns 0 on reaching the end-of-file condition.

Another approach:

if (fin1.eof() != 0) {
    exit(1);
}

eof() is a member function of the ios class. It returns a non-zero value if the EOF condition is encountered, and a zero otherwise.

13.6 File Pointers

Each file has two associated pointers known as file pointers:

  1. input (get) pointer
  2. output (put) pointer

These pointers are used to move through the files while reading and writing. The input pointer is used for reading the contents of a given file location and the output pointer is used to write to a given location. Each time an input or output operation takes place, the appropriate pointer is automatically advanced.

Default actions of pointers

  • If the file is opened in read-only mode, the input pointer is automatically set at the beginning so that we can read the file from the start.
  • When the file is opened in write-only mode, the existing contents are deleted and the output pointer is set at the beginning.
  • In case the file is opened in append mode, this moves the output pointer to the end of the file.

Manipulation functions

                    // (bytes start at 0, so this is the 11th byte)

ofstream fileout;

  • ios::end — end of the file

13.7 Sequential Input and Output Operations

put() and get()

  • The function put() writes a single character to the associated stream.
  • The function get() reads a single character from the associated stream.

read() and write()

  • Unlike get() and put(), read() and write() handle the data in binary form.
  • Each function takes two arguments: the first is the address of a variable v, and the second is the length of that variable in bytes.
  • The address of the variable must be cast to type char *.
infile.read((char *)&v, sizeof(v));
outfile.write((char *)&v, sizeof(v));

13.8 Reading and Writing a Class Object

The binary input and output functions read() and write() handle the entire object as a single unit.

class weight {
    int kg, gm;
  public:
    void read() {
        cout << "Enter weight";
        cin  >> kg >> gm;
    }
    void write() {
        cout << "Weight is";
        cout << kg << "+" << gm;
    }
};

void main() {
    weight w1;
    fstream file;

    file.open("data1.dat", ios::in | ios::out);

    w1.read();
    file.write((char *)&w1, sizeof(w1));

    file.seekg(0);
    file.read((char *)&w1, sizeof(w1));

    w1.write();
    file.close();
}
File Handling Cheat Sheet
  • Open for output: ofstream f("x.txt");
  • Open for input: ifstream f("x.txt");
  • Open both: fstream f("x.txt", ios::in | ios::out);
  • Append: ofstream f("x.txt", ios::app);
  • Check EOF: while (f) { ... } or f.eof()
  • Move read pointer: f.seekg(offset, ios::beg/cur/end);
  • Move write pointer: f.seekp(offset, ios::beg/cur/end);
  • Get positions: f.tellg() / f.tellp()
  • Binary I/O: f.read((char*)&obj, sizeof(obj)); and f.write((char*)&obj, sizeof(obj));
  • Close: f.close();
