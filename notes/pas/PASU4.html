Orientation

The Unit at a Glance

One storyline, five moves: estimate a value, test a claim, compare groups, quantify association, predict an outcome.

Everything in Unit IV answers one master question: what can a sample tell us about the population it came from? The unit first builds the vocabulary (population, parameter, statistic), then uses it in two directions — estimation (give me a plausible range for the parameter) and hypothesis testing (is the sample compatible with a claimed value?). It then scales testing up: Z and t handle one or two means, chi-square handles categorical counts, and ANOVA handles three or more means at once. Finally the focus shifts from testing differences to modelling relationships: correlation quantifies how two variables move together, regression turns that association into a prediction equation, and curve fitting generalises the idea beyond straight lines.

Foundations

Statistical Estimation

Using sample evidence to make defensible statements about unknown population values.

1.1Population, sample, parameter, statistic

Measurement is expensive. A population — the complete set of units we care about — is usually too large, too slow or too costly to measure entirely (every API request handled in a day; every device a factory will ever produce). So we measure a sample: a subset selected so that it represents the whole. Statistical estimation is the discipline of turning that sample into knowledge about the population, while being honest about the uncertainty involved.

1.2Point estimation

Definition

A point estimate is a single number calculated from sample data and offered as the best guess for an unknown population parameter. The rule (formula) used to compute it is the estimator; the number it produces for a given sample is the estimate.

  • Estimate μ with the sample mean: x̄ = Σxᵢ / n
  • Estimate p with the sample proportion: p̂ = x / n (x = successes in the sample)
  • Estimate σ² with the sample variance: s² = Σ(xᵢ − x̄)² / (n − 1)
Worked Example 1.1 point estimate of a mean

Five sensor latency readings (ms): 18, 20, 22, 19, 21.

Point estimate of μx̄ = 18 + 20 + 22 + 19 + 215 = 1005 = 20 ms

Interpretation: the best single guess for the population mean latency is 20 ms. It does not mean every request takes 20 ms — only that 20 ms is the sample's centre.

Worked Example 1.2 point estimate, CPU utilization

Random sample of CPU utilization (%): 42, 46, 40, 44, 48.

  1. Sum the observations. 42 + 46 + 40 + 44 + 48 = 220.
  2. Divide by n. x̄ = 220 / 5 = 44%.

The population mean CPU utilization is estimated as 44%. Random sampling matters here: it is what lets us claim the sample is representative.

1.3What makes an estimator good?

Many different rules could estimate μ — the sample mean, the sample median, the first observation. Statistics ranks estimators by four classical properties:

  • Unbiasedness

    On average (over all possible samples) the estimator hits the true value exactly: E(θ̂) = θ. The sample mean is unbiased for μ; the sample variance with n−1 in the denominator is unbiased for σ².

  • Consistency

    As n grows, the estimator converges towards the true parameter. Gather enough data and the error shrinks to zero — the guarantee behind "larger samples are better".

  • Efficiency

    Among unbiased estimators, the one with the smallest variance is most efficient: its guesses cluster most tightly around the truth. The sample mean is more efficient than the median for normal data.

  • Sufficiency

    A sufficient statistic exhausts the sample's information about the parameter — no other statistic computed from the same data can add anything more (x̄ is sufficient for μ in a normal model).

1.4Interval estimation & confidence level

A point estimate is honest about being a guess but says nothing about how wrong it might be. An interval estimate repairs this: it reports a range of plausible values for the parameter together with a confidence level (90%, 95%, 99%). Every confidence interval has the same anatomy:

Anatomy of every confidence intervalestimate ± margin of error  where  margin of error = (critical value) × (standard error)

The correct reading of "95% confident" is subtle and heavily examined: the confidence applies to the method, not to one interval. If we drew sample after sample and built a 95% CI from each, about 95% of those intervals would capture the fixed, unknown parameter. Any single computed interval either contains μ or it does not — there is no probability left once the numbers are fixed.

Key relationships
  • Confidence level = 1 − α for a two-sided interval, so 95% confidence ⇔ α = 0.05.
  • Higher confidence → wider interval (99% beats 95% beats 90% in width): you buy certainty with precision.
  • Larger n → narrower interval: the margin of error shrinks like 1/√n — quadruple the data, halve the width.

Worked Example 1.3 95% Z interval · network delay

A sample of n = 64 network packets has mean delay x̄ = 50 ms. The population SD is known to be σ = 8 ms. Construct a 95% confidence interval for μ.

  1. Identify the ingredients. x̄ = 50, σ = 8, n = 64, zα/2 = 1.96.
  2. Standard error. SE = σ/√n = 8/√64 = 8/8 = 1 ms.
  3. Margin of error. ME = 1.96 × 1 = 1.96 ms.
  4. Interval. 50 ± 1.96 → (48.04, 51.96) ms.
Interpretation

We are 95% confident that the population mean packet delay lies between 48.04 ms and 51.96 ms.

1.6CI for a population mean — σ unknown (t interval)

Far more common in practice: σ is unknown, so we estimate it with the sample SD s. Estimating the spread and the centre adds extra uncertainty, and the t distribution — bell-shaped but with heavier tails than the normal — prices that uncertainty in. Its shape depends on the degrees of freedom, df = n − 1; as df grows, t approaches the standard normal.

t confidence interval for μx̄ ± tα/2, n−1 · s√n
Worked Example 1.4 95% t interval · battery life

A sample of n = 10 devices has mean battery life x̄ = 8.2 h and sample SD s = 1.5 h. Assume approximate normality. Find a 95% CI for μ.

  1. Degrees of freedom. df = n − 1 = 9.
  2. Critical value. t0.025, 9 ≈ 2.262 (from the t-table, two-tailed 0.05).
  3. Standard error. SE = s/√n = 1.5/√10 ≈ 0.474 h.
  4. Margin and interval. ME = 2.262 × 0.474 ≈ 1.07, so 8.2 ± 1.07 = (7.13, 9.27) h.
Interpretation

We are 95% confident the population mean battery life lies between 7.13 and 9.27 hours. With only 10 observations, normality of the underlying population is an assumption we must state.

The Decision Machine

Hypothesis-Testing Framework

A structured courtroom for claims: evidence is sampled, a verdict is returned, and the error rates are known in advance.

2.1What a hypothesis test actually does

A hypothesis is a testable statement about a population parameter (e.g. "the mean response time is 100 ms"). A hypothesis test weighs sample evidence against a baseline claim and returns one of two verdicts: reject the baseline or do not reject it. Crucially, a test never proves a hypothesis true — it only measures how incompatible the data are with the null model. The chain is always:

Claim about the population (μ = 100 ms)
↓
Collect a random sample → compute a statistic (x̄)
↓
How far is x̄ from what H₀ predicts?
measured in standard errors → test statistic
↓
Reject H₀  ·  or Fail to reject H₀

2.2Null vs alternative — and the three tails

  • Null hypothesis H₀ — the baseline: no change, no difference, a specified value. H₀: μ = 100 ms. It is assumed true until the evidence contradicts it.
  • Alternative hypothesis H₁ (or Hₐ) — what we are gathering evidence for: μ ≠ 100, μ > 100 or μ < 100.

The alternative decides the tail of the test, and the tail decides where the rejection region sits. Choose it before seeing the data — switching tails after looking at results is a classic error that inflates the Type I rate.

Memory trick — from the slides

"DIFFERENT" → μ ≠ μ₀ → two tails. "GREATER / INCREASED" → μ > μ₀ → right tail. "LESS / DECREASED / FASTER" → μ < μ₀ → left tail.

2.3The significance level α

The significance level α is the maximum probability of a Type I error we accept in advance — the tolerated false-alarm rate of the procedure. Common choices: 0.10, 0.05, 0.01. It must be fixed before the data are examined, and a smaller α makes rejection harder (critical values move further out). For a two-sided test, α is split equally between the two tails.

  • Type I in practice

    Concluding a software update changed average latency when it actually did not — a false alarm that sends engineers hunting for a bug that isn't there.

  • Type II in practice

    Failing to detect a real increase in sensor failure rate — a missed warning. Increasing n or the effect size, or raising α, reduces β.

2.5Every test statistic is signal ÷ noise

Universal shape of a test statistictest statistic = observed difference (signal)standard error (noise)

Z, t, χ² and F are all of this family: they measure how far the sample result sits from what H₀ predicts, in units of expected sampling variation. A value of z = +2 says "the sample mean is 2 standard errors above the claimed mean". Large |statistic| → data are surprising under H₀ → evidence against H₀.

2.6Two ways to decide — critical value vs p-value

  • Critical-value approach

    Fix α → look up the boundary of the rejection region → reject if the computed statistic crosses it. Best for showing where the rejection region lies; ideal in written exams.

  • p-value approach

    Compute p = probability, under H₀, of a result at least as extreme as observed (in the direction(s) of H₁). Reject if p ≤ α. Best for reporting strength of evidence; software default.

Key idea

At the same α the two approaches always agree. Example: p = 0.032 → reject at α = 0.05, but fail to reject at α = 0.01. And remember what p is not: it is not the probability that H₀ is true, and it is not the size of the effect.

2.7The seven-step procedure (memorise)

  1. State H₀ and H₁ clearly, including the direction of the test.
  2. Choose α (commonly 0.05) before analysing the data.
  3. Select the test statistic and check its assumptions (data type, independence, normality, expected counts...).
  4. Calculate the test statistic from the sample.
  5. Find the critical value or p-value from the relevant reference distribution.
  6. Decide: reject H₀ if p ≤ α (or |statistic| beyond critical); otherwise fail to reject.
  7. Conclude in context — one sentence about the engineering problem, not just "reject".
Watch out — the language that costs marks
  • Never write "accept H₀". Write "fail to reject H₀" — absence of evidence is not evidence of absence.
  • Never write "we proved H₀ true" or "the difference is zero" from a non-significant result.
  • Statistical significance ≠ practical importance. With enough data, a 0.2 ms difference is "significant" and completely useless.
  • Compare p with α, or statistic with critical value — never compare the statistic itself with α.

Tests for One Mean

Z-Test & t-Test

One sample, one claimed mean — the choice between Z and t is decided by a single question: is σ known?

3.1One-sample Z-test (σ known)

Use when: testing a claim about one population mean μ; the population SD σ is known; observations are independent; the population is normal or n is large enough for the CLT.

One-sample Z statisticz = x̄ − μ₀σ / √n  = (observed − claimed) ÷ standard error

Under H₀, z follows the standard normal distribution. The numerator is the signal (how far the sample sits from the claim); the denominator is the noise (expected wobble of a sample mean). Reading z: z = 0 means x̄ matches μ₀ exactly; z = +2 means x̄ is 2 standard errors above the claim; larger |z| → stronger evidence against H₀.

Worked Example 3.1 two-tailed Z-test · packet latency

A network team claims mean packet latency is 50 ms; historical records give σ = 8 ms. A random sample of n = 64 packets yields x̄ = 52 ms. Test at α = 0.05 whether the mean differs from 50 ms.

  1. Hypotheses. H₀: μ = 50; H₁: μ ≠ 50 → two-tailed.
  2. Ingredients. x̄ = 52, μ₀ = 50, σ = 8, n = 64, α = 0.05.
  3. Standard error. SE = 8/√64 = 1 ms.
  4. Statistic. z = (52 − 50)/1 = 2.00.
  5. Critical values. Two-tailed at α = 0.05 → z = ±1.96.
  6. Compare. |2.00| > 1.96 → falls in the rejection region (equivalently p ≈ 0.046 ≤ 0.05).
Decision & conclusion

Reject H₀. At the 5% level there is statistically significant evidence that mean packet latency differs from 50 ms. Whether a 2 ms difference matters operationally is a separate, engineering judgement.

3.2One-sample t-test (σ unknown)

Use when: the same one-mean setup, but σ is unknown and estimated by the sample SD s. Because s is itself a noisy estimate, the reference distribution is Student's t with df = n − 1: symmetric and bell-shaped like the normal, but with heavier tails (wider intervals, larger critical values) to account for the extra uncertainty.

One-sample t statistict = x̄ − μ₀s / √n   df = n − 1
Worked Example 3.2 right-tailed t-test · script run time

A lab claims a script finishes in 10 s on average. Ten runs give x̄ = 11.2 s, s = 1.5 s. Test whether the mean is greater than 10 s at α = 0.05 (assume approximate normality).

  1. Hypotheses. H₀: μ = 10; H₁: μ > 10 → right-tailed t-test (σ unknown).
  2. Ingredients. n = 10, x̄ = 11.2, s = 1.5, df = 9.
  3. Standard error. SE = 1.5/√10 ≈ 0.4743.
  4. Statistic. t = (11.2 − 10)/0.4743 ≈ 2.53.
  5. Critical value. One-tailed t0.05, 9 = 1.833 (p ≈ 0.016).
  6. Compare. 2.53 > 1.833 → reject H₀.
Decision & conclusion

Reject H₀. At the 5% level, the sample provides evidence that mean execution time exceeds 10 seconds. Stated assumptions: independent runs, approximately normal distribution of times.

Worked Example 3.3 two-tailed t-test · manufacturing time

A company claims a task takes 20 min on average. A sample of n = 16 tasks gives x̄ = 21.2 min, s = 2.4 min (σ unknown). Test at α = 0.05 whether the mean differs from 20.

  1. Hypotheses. H₀: μ = 20; H₁: μ ≠ 20 → two-tailed t-test.
  2. Standard error. SE = 2.4/√16 = 0.6 min.
  3. Statistic. t = (21.2 − 20)/0.6 = 2.00.
  4. Degrees of freedom. df = 16 − 1 = 15 → critical t = ±2.131.
  5. Compare. |2.00| < 2.131 → not in the rejection region (p ≈ 0.064).
Decision & conclusion

Fail to reject H₀. The sample does not provide sufficient evidence, at the 5% level, that the mean task time differs from 20 minutes — even though x̄ is 1.2 min higher. Note we have NOT proved μ = 20; we merely failed to disprove it.

Worked Example 3.4 the same data, σ known → different verdict

Identical claim and sample: x̄ = 21.2, n = 36 — but now the process SD is known from long records: σ = 4 min. Test H₀: μ = 20 vs H₁: μ ≠ 20 at α = 0.05.

  1. Test choice. σ known → Z-test.
  2. Standard error. SE = 4/√36 = 0.667 min.
  3. Statistic. z = (21.2 − 20)/0.667 ≈ 1.80.
  4. Compare. −1.96 < 1.80 < +1.96 → fail to reject H₀.
Decision & conclusion

Fail to reject H₀: insufficient evidence of a difference from 20 minutes. Pair this with Example 3.3 — the same observed difference can be significant or not depending on n, σ vs s, and the resulting standard error.

Tests for Categorical Counts

Chi-Square Tests

When the data are counts in categories — not measurements — Z and t step aside for χ².

4.1The core idea: observed vs expected

Z and t work on numerical measurements (latency, temperature, battery life). Chi-square works on frequencies: how many tickets were Login failures, how many devices passed inspection, how many students chose each study mode. The single idea behind both chi-square tests: compare the counts you observed (O) with the counts you would expect (E) if H₀ were true.

Pearson chi-square statisticχ² = Σ (O − E)²E
  • Small χ² → observed ≈ expected → data are compatible with H₀.
  • Large χ² → some observed counts deviate substantially from expectation → evidence against H₀.
Why square the difference — and why divide by E

Raw differences cancel: one category with O − E = −20 and another with +20 sum to zero, hiding both discrepancies. Squaring makes every deviation contribute positively and penalises large ones. Dividing by E makes the contribution relative: being 20 off matters far more when E = 25 than when E = 1000.

4.2The χ² distribution

The chi-square statistic is non-negative (it is built from squares) and its reference distribution is right-skewed, with a shape that depends on the degrees of freedom. Two consequences you must carry into every problem: the rejection region is always in the upper tail, and "more df" shifts the distribution rightwards and makes it more symmetric.

4.3Test 1 — Goodness of fit (one categorical variable)

Question answered: does the observed distribution of a single categorical variable match a specified expected distribution?

  • H₀: population category proportions match the specified ones.
  • H₁: at least one proportion differs.
  • Expected count per category: Ei = n × pi (hypothesised proportion × total observations).
  • Degrees of freedom: df = k − 1 (k = number of categories; minus one because, with n fixed, the last category count is determined by the others).
Worked Example 4.1 goodness of fit · help-desk tickets

A help desk expects four ticket types to be equally common. In 100 tickets: Access 30, Network 25, Software 20, Hardware 25. Test at α = 0.05 whether the distribution is equal.

  1. Hypotheses. H₀: p₁ = p₂ = p₃ = p₄ = 0.25; H₁: proportions not all equal.
  2. Expected counts. E = 100 × 0.25 = 25 per category.
  3. Contributions. (30−25)²/25 = 1; (25−25)²/25 = 0; (20−25)²/25 = 1; (25−25)²/25 = 0.
  4. Statistic. χ² = 1 + 0 + 1 + 0 = 2.00.
  5. df and critical value. df = 4 − 1 = 3 → χ²crit ≈ 7.815 (p ≈ 0.57).
  6. Compare. 2.00 < 7.815 → fail to reject H₀.
Decision & conclusion

Fail to reject H₀. The sample provides insufficient evidence that ticket types depart from an equal distribution. (Not "proof of equality" — only absence of evidence against it.)

Worked Example 4.2 goodness of fit · software defects

A company expects four defect classes to be equally likely (25% each). Of 200 defects observed: Login 70, Network 45, Database 35, UI 50. Test at α = 0.05.

  1. Hypotheses. H₀: observed distribution follows the 25% × 4 expectation; H₁: it does not.
  2. Expected counts. E = 200 × 0.25 = 50 each.
  3. Contributions. Login (70−50)²/50 = 8; Network (45−50)²/50 = 0.5; Database (35−50)²/50 = 4.5; UI (50−50)²/50 = 0.
  4. Statistic. χ² = 8 + 0.5 + 4.5 + 0 = 13.0.
  5. df and critical value. df = 3 → χ²crit = 7.815 (p ≈ 0.0046).
  6. Compare. 13.0 > 7.815 → reject H₀.
Decision & conclusion

Reject H₀. The defect distribution differs significantly from equal at the 5% level — Login defects occur more, Database less, than expected. Practical follow-up: root-cause analysis of the login module, targeted testing.

4.4Test 2 — Independence (two categorical variables)

Question answered: are two categorical variables associated in the population, or independent? Data are arranged in an r × c contingency table of counts.

  • H₀: the two variables are independent (knowing one tells you nothing about the other).
  • H₁: the variables are associated.
  • Expected count of cell (i, j): Eij = (row total × column total) / grand total.
  • Degrees of freedom: df = (r − 1)(c − 1).

Comparing Several Means

One-Way ANOVA

Analysis of Variance — despite the name, it compares means, by asking whether the variation between groups is large relative to the noise within them.

5.1Why not just run many t-tests?

With two groups, a t-test suffices. With three or more groups (algorithms A, B, C…), testing every pair separately explodes the number of comparisons: k groups need k(k−1)/2 pairwise tests — 3 groups → 3 tests, 4 groups → 6, 5 groups → 10. Each test carries its own α = 0.05 chance of a false positive, so the overall chance of at least one spurious "significant difference" inflates quickly: six independent tests at α = 0.05 give a family-wise error of 1 − 0.95⁶ ≈ 26.5% — a 1-in-4 chance of finding a "difference" that isn't there.

ANOVA's solution: one overall F-test of the hypothesis "all population means are equal", holding the experiment-wide Type I error at α. ANOVA compares means by analysing variance — it splits the total variability in the data into a part due to differences between group means and a part due to random variation inside the groups, then takes their ratio.

5.3The central idea: signal vs noise

5.4Hypotheses in one-way ANOVA

Hypotheses for k groupsH₀: μ₁ = μ₂ = … = μk   H₁: at least one population mean is different
Watch out — the most-tested subtlety

H₁ does not say "every mean is different". It says at least one differs. Correspondingly, rejecting H₀ does not tell you which groups differ — that requires post-hoc analysis (§5.11).

5.5Partitioning the variation

Every observation's deviation from the grand mean splits into two pieces: the deviation of its group mean from the grand mean, plus its own deviation from its group mean. Squaring and summing over all data gives the fundamental identity:

The ANOVA identitySST = SSB + SSW

Grand mean: the mean of all N observations pooled — not the average of group means unless all groups are the same size. Degrees of freedom partition the same way:

Degrees of freedom (k groups, N observations)dfbetween = k − 1  ·  dfwithin = N − k  ·  dftotal = N − 1

5.6Mean squares and the F-statistic

Sums of squares grow with the amount of data, so each is scaled by its degrees of freedom to make them comparable — the mean squares:

Mean squares and FMSB = SSBk − 1    MSW = SSWN − k    F = MSBMSW

Under H₀ both mean squares estimate the same background variance, so F hovers near 1. A substantially larger F means group-mean separation exceeds what within-group noise can explain. Reading F:

  • Small F (≈1) — between ≈ within → little evidence of differing means.
  • Large F — between ≫ within → strong evidence at least one mean differs.

The F distribution is non-negative and right-skewed with a pair of degrees of freedom (df₁ = k − 1, df₂ = N − k); the ANOVA test is always upper-tail: reject when Fcalculated > Fcritical.

5.10Assumptions of one-way ANOVA

  • 1 · Independence

    Observations are independent — guaranteed by randomised sampling / run order. One run's latency must not constrain the next (repeated measures need a different design).

  • 2 · Normality

    The response is approximately normal within each group — formally, the residuals. Matters most for small samples; large n gives robustness.

  • 3 · Equal variances

    Homogeneity of variance: σ²₁ ≈ σ²₂ ≈ … ≈ σ²k. If seriously violated, use Welch's ANOVA; for strongly non-normal data, the Kruskal–Wallis test.

5.11What a significant F does — and does not — tell you

  • It tells you

    At least one population mean differs; the factor has evidence of an effect; further analysis (post-hoc) is warranted.

  • It does not tell you

    Which pairs differ · how big the differences are · whether the difference matters practically. A significant F with all means within 0.2 ms of each other is engineering trivia.

Post-hoc analysis (beyond the syllabus but examinable as a concept): after a significant ANOVA, procedures such as Tukey's HSD or Bonferroni-adjusted comparisons test every pair while controlling the family-wise error rate — answering "where are the differences?". Also report effect sizes and confidence intervals, not just the verdict.

Statistical vs practical significance

Algorithm A: 100.0 ms, Algorithm B: 100.2 ms, p < 0.001. Statistically significant — yes, with enough runs any non-zero gap becomes significant. Practically important — almost certainly not. Always read the result through units, costs and engineering impact.

  • AI / IoT

  • Manufacturing

    Product strength across processes; cycle time across machine settings; defect counts across lines.

Correlation

Do two variables move together — how strongly, and in which direction? From pictures to Pearson to Spearman.

6.1Relationships between variables

A variable is any measurable characteristic; a relationship describes how two variables change together. Convention fixes the roles: the independent variable X (predictor, explanatory) is used to explain or predict the dependent variable Y (response, outcome). "Independent" here does not mean experimentally controlled — in observational data X is simply the variable we explain with.

The word "generally" matters: a positive relationship describes the tendency, not a guarantee for every single observation. And always the master caution: association does not imply causation (§6.8).

6.2Scatter plots — read before you calculate

Plot each paired observation (x, y) as one point: X on the horizontal axis, Y on the vertical. The cloud's shape reveals direction, strength, curvature and outliers — check it before computing any coefficient, because a single outlier or a curved pattern can make Pearson's r misleading.

6.3Covariance — direction without a scale

Sample covarianceCov(X, Y) = Σ (Xᵢ − X̄)(Yᵢ − Ȳ)n − 1

Products of paired deviations, averaged: positive when the variables tend to move together (points above-average in X also above-average in Y), negative when they move oppositely, near zero with no linear co-movement. The fatal weakness: covariance depends on the units and scale of measurement (cov in ms·W changes if you switch to seconds), so its magnitude is uninterpretable across datasets. Correlation fixes exactly this.

6.4Pearson's correlation coefficient r

Pearson's r is standardised covariance — divide by the product of the standard deviations and the result becomes unit-free, bounded in −1 ≤ r ≤ +1.

6.7The correlation matrix

With several variables, compute r for every pair and arrange them in a square, symmetric matrix — diagonal 1s, mirrored off-diagonal. It is the standard first look at a multivariate dataset and the workhorse of feature selection.

Feature selection use (CSE angle): two features with r ≈ 0.95 carry nearly the same information — keeping both adds redundancy and can destabilise models. A standard preprocessing pipeline drops one of each highly correlated pair (threshold commonly |r| > 0.8 or 0.9) before training; the lecture cites recent IoT-intrusion-detection research reducing 46 features to 20 and 40 to 31 this way, often followed by Random-Forest importance ranking.

6.8Cautions — where correlation misleads

  • Correlation ≠ causation

    Ice-cream sales and swimming-pool visits correlate — hot weather drives both (a confounder). Never infer the direction of influence, or cause-and-effect, from r alone.

  • Outliers

    A single extreme point can manufacture (or destroy) a strong r. Plot first; investigate before deleting.

  • Nonlinearity

    r ≈ 0 does not mean "no relationship" — only "no straight-line relationship". The U-shaped panel above is a perfect relationship with r ≈ 0.

  • Confounding & time series

    A third variable may drive both X and Y (server load drives users and response time); trends/seasonality in time series can inflate r if ignored.

From Association to Prediction

Regression Analysis

Turning a relationship into an equation — fitting it by least squares, judging it with R², and using it to predict.

7.1From correlation to regression

Given study hours (X) and marks (Y) for five students, three questions escalate in ambition:

  • Are they related? → correlation (r).
  • How much does Y change when X increases by one unit? → the regression slope b₁.
  • What marks would a student studying 6 hours get? → prediction from the fitted equation.

Regression answers all three by postulating a model of the relationship and estimating its coefficients from data.

7.2The simple linear regression model

Population model vs fitted equationY = β₀ + β₁X + ε   → estimated from data →   Ŷ = b₀ + b₁X
  • β₀ (intercept) — the expected value of Y when X = 0. Often has no physical meaning (predicted marks at zero study hours may be a baseline, predicted power at zero irradiance is not physical) — say so when interpreting.
  • β₁ (slope) — the expected change in Y for a one-unit increase in X. The quantity of interest.
  • ε (error) — everything the straight line cannot capture: measurement noise, omitted factors, randomness.
  • Ŷ (y-hat) — the prediction the fitted line produces for a given X.

7.3Residuals and the least-squares principle

Residual of observation ieᵢ = Yᵢ − Ŷᵢ   (actual − predicted)

Real points never sit exactly on the line. The residual is each point's vertical miss (positive above the line, negative below, zero on it). Least squares chooses the intercept and slope that make the sum of squared residuals as small as possible:

Least-squares objectiveSSE = Σ (Yᵢ − Ŷᵢ)²  →  choose b₀, b₁ to minimise SSE

Why square? So positive and negative misses cannot cancel (+2, −3, +4 sum to 3 but square to 4+9+16 = 29), and so large errors are penalised disproportionately. Squaring also makes the minimisation solvable exactly with calculus — which is precisely where the normal equations come from.

7.4The normal equations — and their derivation

Normal equations for the straight line Ŷ = a + bXΣY = n a + b ΣX    ·    ΣXY = a ΣX + b ΣX²

Two equations, two unknowns (a, b) — solve simultaneously. They are not magic: they are exactly the calculus conditions for SSE to be at its minimum.

Derivation a favourite long-answer question
  1. Write the objective. With Ŷᵢ = a + bXᵢ, the residual is eᵢ = Yᵢ − a − bXᵢ, so SSE(a, b) = Σ(Yᵢ − a − bXᵢ)².
  2. Set both partial derivatives to zero (a smooth minimum has zero slope in every direction):
    ∂SSE/∂a = −2 Σ(Yᵢ − a − bXᵢ) = 0   ·   ∂SSE/∂b = −2 Σ Xᵢ(Yᵢ − a − bXᵢ) = 0
  3. First equation → ΣYᵢ − n a − b ΣXᵢ = 0, hence ΣY = n a + b ΣX.
  4. Second equation → ΣXᵢYᵢ − a ΣXᵢ − b ΣXᵢ² = 0, hence ΣXY = a ΣX + b ΣX².

Solving the pair (e.g. eliminate a by multiplying the first by ΣX and subtracting) yields the closed forms:

Direct formulasb = ΣXY − (ΣX ΣY)/nΣX² − (ΣX)²/n    a = Ȳ − b X̄

7.6Is the fit any good? SST, SSE, R², sₑ

Three sums of squares tell the story — the same partitioning logic as ANOVA, one variable later:

Partition of variation in YSST = Σ(Yᵢ − Ȳ)²  ·  SSE = Σ(Yᵢ − Ŷᵢ)²  ·  SSR = SST − SSE  (explained by the model)

R² is the share of the variation in Y that the model explains, relative to a mean-only model. R² = 0.81 → "the model accounts for 81% of the observed variation in Y in this sample". It is not prediction accuracy, not proof of causation, and no guarantee about new data. Because R² never decreases when you add predictors (however useless), the adjusted R² applies a penalty per predictor — it can fall when a useless variable is added, which makes it the honest tool for comparing models of different sizes.

Standard error of estimatesₑ = SSEn − 2  (residual df = n − 2: two parameters, b₀ and b₁, were estimated)

sₑ is the typical vertical spread of the actual Y values around the fitted line, in Y's own units — "the typical prediction miss" in an average sense (it is not a 95% margin).

The regression equivalent of a hypothesis test asks whether the population slope is zero — "does X help explain Y at all?"

7.8Regression of Y on X vs X on Y

Which variable is being predicted decides the line:

Two regression linesY on X: Ŷ = a + bX, slope b = r (sY/sX)   ·   X on Y: X̂ = a′ + b′Y, slope b′ = r (sX/sY)
  • Both lines pass through the point (X̄, Ȳ).
  • They are different lines in general and coincide only when |r| = 1 (perfect correlation).
  • Choose the direction from the prediction goal: predict Y from X → Y on X.

7.9Multiple linear regression (MLR)

One predictor rarely tells the whole story. Marks also depend on attendance and prior knowledge; PV power also on temperature and dust. Multiple linear regression extends the line to a plane (or hyperplane):

MLR modelŶ = b₀ + b₁X₁ + b₂X₂ + … + bkXk

The crucial reading — and a guaranteed exam question — is the ceteris paribus interpretation: each coefficient is the expected change in Ŷ for a one-unit increase in that predictor, holding all other included predictors constant.

Worked Example 7.6 MLR prediction · solar PV

Illustrative model: Ŷ = −20 + 0.20X₁ − 0.50X₂ − 1.20X₃, where X₁ = irradiance (W/m²), X₂ = panel temperature (°C), X₃ = dust coverage (%), Ŷ = power (W). Predict power at X₁ = 800, X₂ = 40, X₃ = 10.

Ŷ = −20 + 0.20(800) − 0.50(40) − 1.20(10) = −20 + 160 − 20 − 12 = 108 W
  • +0.20: each extra W/m² of irradiance adds 0.20 W of predicted power, temperature and dust held constant.
  • −0.50: each extra °C of panel temperature costs 0.50 W, irradiance and dust held constant.
  • −1.20: each extra percentage point of dust costs 1.20 W, the rest held constant.

Also from the lecture: actual 110 W vs predicted 108 W → residual e = 110 − 108 = +2 W (the model under-predicted).

MLR assumptions — the LINE checklist plus two traps
  • Linearity — the relationship is adequately captured by the linear form.
  • Independence of residuals (watch time-ordered data).
  • Normality of residuals (matters for small-sample inference).
  • Equal variance (homoscedasticity) of residuals across fitted values.
  • Multicollinearity — predictors strongly correlated with each other make individual coefficients unstable and their interpretations unreliable (detect via the correlation matrix; drop or combine redundant predictors).
  • Overfitting — too many predictors chase the noise of this particular sample; performance on new data degrades.

7.10Model diagnostics — read the residuals

  • Before trusting any model

    Linearity · residual patterns (above) · constant variance · multicollinearity among predictors · large residuals / unusual points.

  • After trusting it

    Validate on unseen data — a test set or cross-validation. A beautiful R² on the fitting data guarantees nothing about tomorrow's predictions.

Beyond Straight Lines

Curve Fitting

When a line can't follow the data, choose a curve — and choose it without memorising the noise.

8.1What and why

Curve fitting is finding the mathematical equation that best represents the relationship in observed data. Real measurements rarely fall on a clean curve — measurement error, environmental changes, random variation and equipment limits scatter the points — so we fit a model that summarises the pattern according to an error criterion. Least squares is that criterion: whatever the model family, its coefficients are chosen to minimise SSE = Σ(Y − Ŷ)².

Why it matters: prediction and forecasting, engineering system modelling, experimental data analysis, quality control and research. Examples from the lecture — solar power from irradiance, electricity consumption from temperature, manufacturing output from machine operating time, marks from study hours.

8.2The model families

Key idea — least squares generalises

For the quadratic, the normal equations gain terms for ΣX², ΣX³, ΣX⁴ and ΣX²Y; conceptually nothing changes — minimise SSE, solve for the coefficients. In practice numpy.polyfit(X, y, degree) fits degrees 1–3 in one line, and the lecture uses exactly that to compare linear, quadratic and cubic fits for the PV data.

Picking the family is a modelling decision driven by the scatter plot and domain knowledge — PV efficiency, for instance, varies nonlinearly with temperature, so a curved model can fit the observed pattern better than a straight line.

8.3Complexity's trap: underfitting vs overfitting

  • Underfitting

    The model is too simple to capture the real pattern — high bias, large errors on training and test data.

  • Overfitting

    The model memorises this sample's noise — training SSE near zero, test errors large. Guard with validation data, model comparison (adjusted R², RMSE on test) and parsimony: prefer the simplest model that fits well.

9.4Ten traps that cost marks

  1. "Accept H₀" — never; it is fail to reject H₀.
  2. Comparing t with α — compare statistic with critical value, or p with α.
  3. Z-test with σ unknown — the known-σ condition is the whole basis of the Z-test.
  4. df = n instead of n − 1 (t-test) or N − 1 instead of N − k (ANOVA within).
  5. Two-tailed critical value for ANOVA's F — F is a right-tail test, always.
  6. "All means differ" after rejecting H₀ in ANOVA — only "at least one" is licensed.
  7. Using observed counts as expected in χ², or percentages instead of counts.
  8. Confusing SSB with SSW — between = means vs grand mean; within = points vs own mean.
  9. Correlation → causation, in any wording, ever — confounders exist.
  10. Reading R² as accuracy — it is explained variation in the sample, not predictive correctness.

10.1Estimation & confidence intervals

Q1A sample of 25 IoT sensors reports a mean temperature of 31.2 °C. Identify the population, sample, parameter and statistic.
Answer

Population: all temperature readings (or all sensors of this type) that could be observed. Sample: the 25 selected sensors' readings. Parameter: the population mean temperature μ (unknown). Statistic: the sample mean x̄ = 31.2 °C (computed, known, varies from sample to sample).

Q2A sample has values 12, 15, 13, 10, 15. Calculate the point estimate of the population mean.
Answer

x̄ = (12 + 15 + 13 + 10 + 15)/5 = 65/5 = 13.

Q3A sample of 36 observations has x̄ = 72 and known σ = 12. Construct a 95% confidence interval for μ.
Answer

SE = 12/√36 = 2; ME = 1.96 × 2 = 3.92; CI = 72 ± 3.92 = (68.08, 75.92). We are 95% confident the population mean lies in this interval.

Q4Explain unbiasedness and consistency in the context of estimating average network delay.
Answer

Unbiasedness: across many independent samples, the mean of the sample-average delays equals the true population delay — E(x̄) = μ; no systematic over- or under-estimation. Consistency: as the number of monitored requests n grows, the sample average converges to the true average delay — more measurement, less error. The sample mean of delays is both unbiased and consistent.

10.2Hypothesis testing, Z & t

Q5For the claim "average CPU utilization is below 60%", write H₀ and H₁ and identify the tail of the test.
Answer

H₀: μ = 60 (the baseline value); H₁: μ < 60 (evidence sought is a decrease). Left-tailed test — rejection region in the lower tail only.

Q6Explain Type I and Type II errors using a software defect-detection example.
Answer

Type I (α): the test flags a defect (or a change in defect rate) when none exists — a false alarm; engineers chase a phantom bug. Type II (β): the test detects nothing when a real defect exists — a missed warning shipping a faulty release. α is fixed in advance (0.05 typically); 1 − β is the power to catch a real defect.

Q7A sensor manufacturer claims μ = 100 units. Given σ = 12, n = 36 and x̄ = 104, test H₀: μ = 100 against H₁: μ ≠ 100 at α = 0.05.
Answer

SE = 12/6 = 2; z = (104 − 100)/2 = 2.00. Critical values ±1.96. Since 2.00 > 1.96 → reject H₀: at the 5% level there is evidence the mean differs from 100 (p ≈ 0.046).

Q8A sample of 12 program runs has x̄ = 8.4 s and s = 1.2 s. Test whether μ < 9 s at α = 0.05. State the assumptions.
Answer

σ unknown → one-sample t-test, df = 11. SE = 1.2/√12 ≈ 0.346; t = (8.4 − 9)/0.346 ≈ −1.732. Left-tail critical value t0.05, 11 = −1.796. Since −1.732 > −1.796, the statistic is not in the rejection region → fail to reject H₀: insufficient evidence that the mean is below 9 s. Assumptions: independent runs, approximately normal distribution of run times.

Q9State two differences between the p-value and critical-value approaches. What does p = 0.03 mean when α = 0.05?
Answer

(1) The critical-value approach compares the computed statistic with a boundary from the reference distribution; the p-value approach computes the probability of a result at least as extreme and compares it with α. (2) The p-value expresses strength of evidence and can be re-judged against any α; the critical-value approach requires fixing α first and shows where the rejection region lies. With p = 0.03 ≤ 0.05 → reject H₀ (but at α = 0.01, 0.03 > 0.01 → fail to reject). Note p is not the probability that H₀ is true.

10.3Chi-square

Q10A help desk records 120 tickets across four categories. Explain how to test whether the categories are equally common.
Answer

Chi-square goodness-of-fit: H₀: p₁ = p₂ = p₃ = p₄ = 0.25. Expected counts E = 120 × 0.25 = 30 per category. Compute χ² = Σ(O − E)²/E over the four categories, df = 4 − 1 = 3, compare with χ²0.05, 3 = 7.815 (or p with 0.05). Reject H₀ only if χ² exceeds the critical value; check that all E ≥ 5.

Q11A survey records device preference (mobile / desktop) by year of study (first / second). State H₀, the expected-frequency formula and the degrees of freedom.
Answer

Chi-square test of independence. H₀: device preference and year of study are independent. Expected count of each cell: Eij = (row total × column total)/grand total. df = (r − 1)(c − 1) = (2 − 1)(2 − 1) = 1; reject for χ² > 3.841 at α = 0.05. A significant result indicates association, not causation.

10.4ANOVA

Q12Training times (min) under three optimisation methods: A: 14, 13, 15, 14 · B: 11, 12, 10, 11 · C: 16, 15, 17, 16. Complete the ANOVA and test at α = 0.05.
Answer

Means: x̄A = 14, x̄B = 11, x̄C = 16; grand mean = 164/12 = 13.67. H₀: μA = μB = μC; H₁: at least one differs.

SSB = 4[(14−13.67)² + (11−13.67)² + (16−13.67)²] = 4[0.111 + 7.111 + 5.444] = 50.67. SSW: each group deviates by 0, ∓1, ±1, 0 → SS = 2 per group → 6.00. df: 2 and 9. MSB = 25.33, MSW = 0.667. F = 38.0 ≫ F0.05(2,9) = 4.26 → reject H₀ (p < 0.001): strong evidence the mean training times are not all equal; post-hoc tests would locate which methods differ.

ANOVA table: Between 50.67 / 2 / 25.33 / 38.0 · Within 6.00 / 9 / 0.667 · Total 56.67 / 11.

Q13Why is ANOVA preferred over many pairwise t-tests? What does a large F indicate?
Answer

k groups need k(k−1)/2 pairwise tests; each extra test compounds the chance of a false positive (family-wise Type I error), reaching ≈ 26.5% for 6 tests at α = 0.05. ANOVA gives one overall test at the chosen α. A large F means the between-group variation (signal) is large relative to within-group variation (noise) — evidence that not all population means are equal.

10.5Correlation

Q14For X = (1, 2, 3, 4, 5) and Y = (2, 4, 5, 4, 6), calculate Pearson's r and interpret it.
Answer

ΣX = 15, ΣY = 21, ΣX² = 55, ΣY² = 97, ΣXY = 71, n = 5. r = [5(71) − 15(21)]/√{[5(55) − 225][5(97) − 441]} = 140/√(50 × 44) = 140/46.9 ≈ 0.853 — a strong positive linear association: higher X tends to go with higher Y.

Q15Two judges give ranks A = (1, 2, 3, 4, 5) and B = (2, 1, 3, 5, 4). Calculate Spearman's ρ.
Answer

d = (−1, 1, 0, −1, 1) → Σd² = 4. ρ = 1 − 6(4)/[5(25 − 1)] = 1 − 24/120 = 0.8 — strong positive agreement between the judges.

Q16Explain why a high correlation coefficient does not prove that one variable causes the other.
Answer

Correlation is symmetric and observational: it detects co-movement, not mechanism. A confounding third variable may drive both (hot weather raises both ice-cream sales and pool visits; server load raises both user count and response time); the direction of influence is ambiguous; and chance plus outliers can inflate r. Establishing causation needs controlled experiments or domain-specific causal evidence — never r alone.

10.6Regression & prediction

Q17Given n = 5, ΣX = 15, ΣY = 35, ΣX² = 55, ΣXY = 125, find the regression line of Y on X.
Answer

b₁ = [5(125) − 15(35)]/[5(55) − 15²] = (625 − 525)/(275 − 225) = 100/50 = 2. X̄ = 3, Ȳ = 7 → b₀ = 7 − 2(3) = 1. Fitted line: Ŷ = 1 + 2X.

Q18A fitted model is Ŷ = 4 + 3X. Predict Y for X = 8 and interpret the slope. Then: in a marks model using study hours, attendance and assignments, identify Y and the predictors, and explain a temperature coefficient of −0.5 in a solar model.
Answer

Ŷ = 4 + 3(8) = 28. Slope: each one-unit increase in X is associated with a 3-unit increase in predicted Y, on average.

Marks model: Y = marks; predictors X₁ = study hours, X₂ = attendance, X₃ = assignment completion. Temperature coefficient −0.5: each additional °C of panel temperature is associated with 0.5 W less predicted power, holding irradiance and dust constant.
